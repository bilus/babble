* Plan                                                                :plan:

The first chapter in the file, and a temporary one: it exists only
while work is in flight. One entry per stage; the LOGBOOK lines that
state changes leave behind are the in-flight ledger. When a stage
completes, its entry is deleted, ledger and all, and its Changes
draft moves, timestamped, to [[#changes][Changes]]. The plan is scaffolding;
the journal is the record.

Vocabulary, since this chapter sits before everything that
defines it. Tangling extracts a book's code blocks into source
files. The oracle is batch Emacs running the lit driver,
lit/tangle.el; babble must match it byte for byte, and the closing
whole-book comparison is the parity sweep. A hole is a typed stub
whose body only panics, tracked by name; the census is the grep
that lists every hole and every plan mark by its sigil, a marker
string steady-state prose never contains. A badge is the
fifteen-star marker headline the plan convention plants at a
change site. Fixture books are each test's miniature input book,
and goldens are their expected outputs, minted from Emacs. The
fence is the pass that rejects everything outside the subset.
Stage headings wear the todo keywords the #+todo line declares,
and the skeleton gate is where work stops for human review.

This plan builds the whole program, so the ladder is long: eleven
stages, of which the first is the skeleton gate and the last is the
parity sweep. Two other kinds of entry hang off that ladder without
being rungs on it. A repair fixes something the ladder already
built, and takes the next free number rather than a place in the
diagram. An editorial stage changes only prose. Both are numbered
above eleven, so a number above eleven never means late; it means
appended. Every stage after the skeleton lands with its tests in
the same commits and leaves the suite green. The oracle harness
arrives in stage 6, early enough that every later stage's fixtures
are cross-checked against Emacs from the day they are written; the
fixture books start from the worked examples in
[[#writing-a-book][Writing a book for babble]].

After the harness the ladder opens into a diamond: comments,
noweb (block inclusion by named reference), and dynamic blocks
(the book's generated views) are independent of one another, and
they close back together at the fence.

** PLANNED Stage 26: chapter files                                 :stage26:
:PROPERTIES:
:CUSTOM_ID: stage-26
:SPEC:     The subset contract, "Recognition"
:DEPS:     stage 6, whose cross-check this stage's acceptance runs
:ACCEPTANCE: a fixture whose book is split across three chapter files tangles identically under both engines; go test ./...; ORACLE=1 go test ./...
:SIZE:     ~200 lines
:END:

Claim: after this stage babble tangles a book split across chapter
files into the tree Emacs writes from the same book, and accepts
two ~#+include~ spellings, refusing the rest.

This is a gap rather than a deviation. lit/BOOK.org makes a
multi-file book a feature of the toolchain: a master includes its
chapters in reading order, both halves expand the includes before
anything else, and a split book and a whole one produce the same
bytes. The driver implements that with
~org-export-expand-include-keyword~, called between the
dynamic-block refresh and the tangle. babble implements nothing,
so the two engines write different trees from one book. The
difference is loud when the chapter owns a file of its own, and
quiet when a chapter and the master both feed one target, since
both engines write that file and only one writes all of it.

Decided: (1) babble expands rather than refusing. A refusal would
forbid the multi-file book. The toolchain documents it and the
driver supports it, and forbidding it is the mistake the gate
caught once already in [[#stage-12][stage 12]].

(2) Expansion sits where the driver puts it, after the
dynamic-block refresh and after the write-back. The refresh
therefore sees the master alone, the master alone is written back,
and a src-block-diff naming a block that lives in a chapter
resolves under neither engine.

(3) Heading levels shift, because org shifts them. Org takes the
shallowest heading level in the included file and moves every
heading in it by the difference to one level below the include's
enclosing heading, or to level 1 at top level. A chapter starting
at level 2 and included at top level is promoted; a chapter
included under a level-1 heading is demoted; nesting compounds.
The shift decides subtree membership and so decides what tangles.
Put a chapter under a COMMENT heading and nothing in it tangles,
where a flat splice of the same text would write the file.

(4) Footnote labels are left alone. Org rewrites them in an
included file with a per-file prefix and does not touch block
bodies, so the renaming reaches no tangled byte and babble has no
use for it.

(5) The keyword is read case-insensitively, and every spelling
outside the two is refused. This is the deviation the stage adds.
The driver's own check reads only uppercase ~#+INCLUDE:~, so a
lowercase form carrying extra arguments passes it and reaches
org's expander, which honors the arguments; the weave's reader is
case-insensitive and refuses that form. babble reads the keyword
the way org and the weave read it, and refuses the rest by name.
The check also differs in reach: the driver searches raw text and
would refuse a malformed include quoted inside an example block,
where org's expander, and babble's tree, pass over it.

(6) Positions keep naming a file. Merged text has line numbers
that belong to no file, so the expansion carries a map from merged
line back to chapter and line, and an error still prints a chapter
file with a line number inside it.

(7) A missing chapter and an inclusion cycle are errors, as they
are for the driver; only the message differs.

One defect turned up in the measurement and belongs to lit rather
than to this stage. The weave half splices a chapter with no level
shift and the tangle half shifts, so the two halves disagree about
any include below top level, against lit/BOOK.org's own
requirement that a split book and a whole one produce the same
bytes. No book in the corpus does this today, and the fix is a
stage in lit/BOOK.org.

* Introduction

babble tangles lit books without Emacs. Three words in that
sentence need explaining, and this chapter explains them: literate
programming, lit, and the oracle that decides when babble is right.

Literate programming is an idea Donald Knuth published in 1984. A
program should be written for humans first and computers second.
You write an essay, actual prose with a narrative flow, and embed
the code inside it wherever the explanation calls for it. One tool
extracts the code and stitches it together into something a
compiler can run, which is tangling. Another produces a typeset
document for reading, which is weaving.

The radical part is the ordering. Traditional code follows the
structure the machine needs: imports at the top, functions in
dependency order. Literate programming follows the structure your
thinking needs. You present ideas in whatever sequence makes the
argument clearest.

One mechanism does that reordering here, and only one. It is called
noweb, and it lets a block pull named blocks into itself by
reference, so a long function can be written as a shell of named
regions and the regions explained one at a time wherever they fit
the argument. Everything else concatenates: a target file is its
blocks in the order you wrote them.

lit is the convention and toolchain that applies the idea, carried
under lit/. A lit book is one org file that is the whole program.
Org is Emacs's plain-text outline format. Prose says why, code
blocks tangle into the sources, and two generated views, a plan
index and a diff, keep the in-book planning in step with the code.

Books also plan inside themselves. Work in flight lives in a
temporary Plan chapter as stage entries. Badges, marker headlines
of fifteen or more stars, stand at every site the work touches. A
planned twin, a rewrite kept beside the block it replaces, waits
for acceptance. A generated index, plan-toc, lists every such site.
This book opens with exactly such a plan.

Batch Emacs does the tangling today: org-babel, org's code-block
machinery, plus lit/tangle.el, the driver from here on. It works.
It also costs about a second of wall clock and 116 MB of resident
memory per tangle, out of a 411 MB install, on every CI run and
every fresh machine. babble tangles the same book in under ten
milliseconds and 9 MB, out of a 3 MB binary. Those numbers were
measured on this book with doc comments switched off, since that
part of babble is not built yet; the rest is a like-for-like run.

One constraint shapes everything here: the oracle.
~babble tangle BOOK.org~ must produce byte-identical results to
~emacs -Q --batch -l lit/tangle.el --eval '(lit-tangle "BOOK.org")'~,
the same tangled files, the same refreshed book. Why bytes?
Because a machine can check bytes. The suite carries an oracle
run that puts every fixture through both engines and diffs the
trees, and a reminting run that rewrites goldens from the
Emacs side only. So committed goldens are Emacs output by
construction.

This is a port of a narrow, documented subset, not of org-mode.
Where the books never rely on a behavior, babble prefers a loud
error to a faithful imitation; the [[#deviations][Deviations]] chapter is the
complete list. When the oracle and any description of it disagree,
this book included, the oracle wins.

babble is itself a lit book. This file is the program: the blocks
below tangle into the Go sources, tests included, and until babble
reaches parity, batch Emacs tangles it. Self-hosting is the finish
line: v1 is done when babble tangles its own book byte-identically.

* Writing a book for babble

:PROPERTIES:
:CUSTOM_ID: writing-a-book
:END:
This chapter is the tour: the org babble reads, one construct at a
time, each construct with an example. And the examples are load
bearing: every one of them is meant to reappear in the test suite
as a fixture book whose goldens batch Emacs mints, so what
this chapter promises, the oracle enforces. The precise
rules behind the tour live in [[#subset-contract][The subset contract]].

Org quoted inside the examples is comma-escaped (a comma before a
star or a ~#+~), which is org's own convention for quoting itself;
escaping is explained below.

** A minimal book

A book is prose and code under headlines. Every src block that
names a target file tangles into it; everything else is yours. The
smallest useful one is a single block:

#+begin_example
,#+title: a tiny book

,* Greeting

greet is the whole library.

,#+begin_src go :tangle greet.go
package greet
,#+end_src
#+end_example

Call that book greet.org and run ~babble tangle greet.org~. It
writes greet.go:

#+begin_example
// Code generated from BOOK.org by make tangle. DO NOT EDIT.

package greet
#+end_example

The banner says BOOK.org even though the book is greet.org. That is
not a bug being reproduced: the driver hardcodes the string, babble
hardcodes the same string, and matching the oracle means keeping
it. Every book gets the same banner whatever it is called.

Every tangled file opens with that banner in the comment syntax of the
language that wrote it: ~//~ for go and js, ~;;~ for emacs-lisp,
~--~ for lua, and ~#~ for a language the comment table does not
name, with ~.lit/comments.json~ beside the book adding languages
or overriding these, then one blank line, then the
code. Tangling
again without changing the book rewrites nothing: the target's
bytes already match, so its timestamp survives and nothing
downstream rebuilds.

** Choosing targets

~:tangle~ decides where a block lands. A path lands relative to the
book's directory, and parent directories appear on demand:

#+begin_example
,#+begin_src go :tangle internal/req/req.go
package req
,#+end_src
#+end_example

~:tangle no~ keeps a block in the book only, which is what you want
for illustrations and scratch work; a block with no ~:tangle~ at
all means the same thing. ~:tangle yes~ derives the target from
the book's name and the language, so in BOOK.org a go block lands
in BOOK.go. Tangling into the book itself is refused.

A block with no language is an error. Emacs would skip it without
a word, which is how a renamed language quietly empties a file;
babble names the line instead.

** How files assemble

Blocks reach a file in document order, whatever their targets do in
between, and consecutive blocks in the same file are separated by
exactly one blank line:

#+begin_example
,#+begin_src go :tangle greet.go
package greet
,#+end_src

,#+begin_src go :tangle other.go
package other
,#+end_src

,#+begin_src go :tangle greet.go
func greet(name string) string {
	return "Hello, " + name + "!"
}
,#+end_src
#+end_example

greet.go collects the first and third blocks with one blank line
between them; other.go gets the middle one. Trailing blank lines
inside a block body are dropped, so you cannot accidentally pad a
file's end.

** Keeping drafts out

A heading whose title starts with ~COMMENT~ takes its whole
subtree out of the tangle, children included. The ~:ARCHIVE:~ tag
does the same:

#+begin_example
,* COMMENT Scratchpad

,#+begin_src go :tangle greet.go
package wrong
,#+end_src

,* Old ideas                                                    :ARCHIVE:
#+end_example

Neither block above reaches a file. This is how a rejected draft
stays in the book without tangling: mark the heading, keep the
text.

** Doc comments

~:comments org~ turns prose above a block into its comment in the
tangled file. The rule is not quite "the paragraph above", and the
difference shows up the first time you comment two blocks in a row.

What the driver takes is the last paragraph of an extent, and the
extent begins at whichever comes last: the heading above the block,
the end of the previous block, or the start of the file. So the
first commented block under a heading gets the prose between the
heading and itself. A second commented block right after it gets
the prose between the end of the first block and itself, and if
there is none, it gets no comment at all. Put a paragraph between
them or expect silence.

#+begin_example
,* Greeting

Callers pick the name; greet only decorates it.

greet returns its salute with the name spliced in.

,#+name: greet
,#+begin_src go :tangle greet.go :comments org
func greet(name string) string {
	return "Hello, " + name + "!"
}
,#+end_src
#+end_example

greet.go reads:

#+begin_example
// Code generated from BOOK.org by make tangle. DO NOT EDIT.

// greet returns its salute with the name spliced in.
func greet(name string) string {
	return "Hello, " + name + "!"
}
#+end_example

The first paragraph stayed in the book; the ~#+name:~ line never
leaks into the comment. When a docstring needs several paragraphs,
put an invisible ~# doc~ marker line where it starts:

#+begin_example
Greeting strings concatenate; there is no template engine here.

# doc
greet returns its salute with the name spliced in.

The exclamation point is part of the contract: tests pin it.

,#+begin_src go :tangle greet.go :comments org
func greet(name string) string {
	return "Hello, " + name + "!"
}
,#+end_src
#+end_example

Everything after the marker becomes the comment, blank lines
preserved as bare ~//~ lines.

A paragraph opening with ~Note:~ or ~Apropos:~ is an aside: the
weave styles it, and the tangle drops the aside marker and keeps the
text, so the aside lands in the source as an ordinary comment.

Doc comments come out in the language's own line-comment syntax,
read from the same table the banner reads, so a language the table
does not name gets a hash and a project adds its own through
~.lit/comments.json~.

** Splitting code with noweb

With ~:noweb yes~, a block can pull named blocks into itself with
~<<name>>~ references, which is how a long function becomes a
shell of named regions:

#+begin_example
,#+begin_src go :tangle greet.go :comments org :noweb yes
func main() {
	<<print-greetings>>
}
,#+end_src

,#+name: print-greetings
,#+begin_src go
fmt.Println(greet("you"))
fmt.Println(greet("me"))
,#+end_src
#+end_example

The tangled main carries both lines, and the tab before
~<<print-greetings>>~ is replicated in front of every expanded
line, so indentation survives:

#+begin_example
func main() {
	fmt.Println(greet("you"))
	fmt.Println(greet("me"))
}
#+end_example

When no single block carries the name, the reference collects
every block whose ~:noweb-ref~ equals it, in document order, each
followed by its own ~:noweb-sep~ (a newline unless you say
otherwise), and the last block's separator is dropped. A referenced
block may itself reference further blocks, but only if it carries
~:noweb yes~ of its own. Without it, a reference inside that block
reaches the file as the text you wrote. A reference nothing defines
is an error, and so is a cycle; Emacs expands the first to nothing
and writes the file, and gives up on the second when its own
recursion runs out.

** Header arguments at large

Org defines some thirty header arguments; a tangler needs eight of
them. babble sorts every header key on every block into three
bins. Implemented: ~:tangle~, ~:mkdirp~, ~:comments~,
~:padline~ (the blank line between blocks in a target), ~:noweb~,
~:noweb-ref~, ~:noweb-sep~, and the ~-i~ switch that preserves
indentation. Inert: the evaluation-only
arguments such as ~:results~ and ~:exports~, accepted and ignored
because they cannot change a tangled byte. Everything else is an
error that names the key, which among other things catches typos:

#+begin_example
,#+begin_src go :tangel greet.go
package greet
,#+end_src
#+end_example

Emacs reads ~:tangel~ as an unknown key and ignores it, and the
block silently stops tangling. babble refuses the book until the
key is spelled right.

Headers can be set once and inherited. A property drawer under a
heading applies to every block in its subtree, and a nearer drawer
replaces a farther one wholesale rather than merging with it. That
word matters: a key the nearer drawer leaves out is not inherited
from further up, it is simply unset. Nesting a drawer to change one
header silently drops every other header the outer drawer set.

#+begin_example
,* Engine
:PROPERTIES:
:header-args: :comments org
:END:
#+end_example

** The plan convention

lit books plan changes inside themselves, and babble has to
recognize what that leaves in the text. A change in flight lives
in a temporary Plan chapter at the front of the book, one entry per
stage. A stage is one unit of planned work: it lands in two commits
with a human review between them, and its entry is deleted when the
work is accepted, which is why the Plan chapter shrinks to nothing
as the program finishes.

Text that describes the finished program is steady-state, and it is
what the book is made of. Prose written for a change in flight is
not, and the difference is the whole point of the convention: a
reader should be able to read a book mid-change and see the program
it is becoming, with the scaffolding marked as scaffolding.

The scaffolding marks the book three ways. A twin is a planned
replacement for a live block: a sibling block, named after the
original plus a planned marker, that sits dormant until accepted. A
badge is a marker headline of fifteen or more stars before a change
site, pointing a reviewer at it. CriticMarkup brackets an edit to
prose in place, so a reviewer sees the old words and the new ones
together. And each kind carries a sigil (a spelling ordinary text
never contains), so one grep, the census, indexes the whole
in-flight layer. babble's own part is small: badge lines parse as
plain headlines, and the two dynamic blocks below render the plan's
jump list and a twin's diff.

** Dynamic blocks

Two generated views live in books, and tangling refreshes both
before any code moves, so committed generated content cannot
disagree with the blocks under it. Hand edits inside them are
lost: the next refresh rewrites the interior wholesale. Dynamic
blocks start in column zero, and only these two names exist; an
unknown name is an error.

plan-toc renders a jump list of every plan-markup site in the
book, one line-number link per site:

#+begin_example
,#+begin: plan-toc
,#+end:
#+end_example

src-block-diff renders a unified diff of two named blocks' bodies,
which is how a twin shows its delta next to the original:

#+begin_example
,#+begin: src-block-diff :old greet :new greet-quiet
,#+end:
#+end_example

Both names must exist as ~#+name:~'d blocks.

** Quoting org inside a block

Org has one rule for putting org inside org: escape a line that
starts with a star or ~#+~ by putting a comma in front, and the
tangle strips one comma back off. Headlines are the reason the
rule exists at all: a bare star line ends every block it appears
in, no matter how deeply quoted it looks.

#+begin_example
,#+begin_src org :tangle no
,,* A quoted heading, safely inert
,,#+begin_src go
,,#+end_src
,#+end_src
#+end_example

One comma per nesting level, and the comma is what makes the shape
legal. An escaped delimiter is text to both engines and causes no
trouble. An unescaped one inside an example, src, export, or
comment body is refused outright: the Emacs driver's raw text
searches would anchor doc-comment extents on it, and a parser
working from the tree cannot reproduce that. So the rule is not
"no delimiters in bodies", it is "escape the ones you show".

** When babble says no

Everything outside src and dynamic blocks is yours: keywords,
drawers, tables, footnotes, links, timestamps pass through
untouched, because babble rewrites the book only by splicing fresh
dynamic-block interiors into the bytes it read. The refusals all
sit on the tangling path; the complete list, with what Emacs would
have done instead, is [[#deviations][Deviations]]. A book that
tangles at all tangles to the same bytes Emacs produces; a book
that would not is refused before any file changes.

* The subset contract

:PROPERTIES:
:CUSTOM_ID: subset-contract
:END:
What ~babble tangle~ does: refresh the book's dynamic blocks, write
the book back when that changed it, then tangle every eligible src
block into its target file. The refresh comes first because it moves
line numbers the tangle depends on.

The subsections here state the contract each stage implements; the
chapters that own the code carry the mechanics. Where a subsection
describes something a stage has not built yet, it says so and names
the stage.

** Recognition

*************** PLANNED stage 12 drops a doubled word below ([[#stage-12][plan]]) :stage12:
One word, in the paragraph this stage was already reading. The
list item runs "and and blocks inside example", across a line
break, which is why it survived a proofread.
*************** END

A tangle candidate is a src block that has a language. Recognition
follows org's element grammar: delimiter keywords are
case-insensitive, only whitespace may follow ~#+end_src~ on its
line, affiliated ~#+name:~ and ~#+header:~ lines belong to the run
above the block below them, {--and--}
and blocks inside example, export, comment and verse blocks are
text rather than blocks. A quote block is not in that list: org
parses it as a greater element, so a src block quoted inside one
is a real src block and tangles. The oracle does this too, and the
fixtures pin it. A src block without a language is an error
(org's scanner cannot even see one, which is worse). A src block
that never closes is an error (org reads it as a paragraph).

*************** PLANNED stage 12 corrects the paragraph below ([[#stage-12][plan]]) :stage12:
The paragraph this stage first added said neither engine reads an
included file. Measurement says otherwise. lit/tangle.el expands a
chapter include before it tangles, so the blocks in that file
reach their targets under Emacs and reach nothing here. What
replaces it separates the two spellings and names the stage that
closes the gap.
*************** END

Keyword lines are not blocks. ~#+include~ is the exception worth
stating, because expansion happens before recognition. The oracle
expands a chapter include as its own step, so a block in the
included file reaches its target as if the master had held it. The
second spelling, ~#+include: "path" example~, shows a file's text
in the weave without making it part of the book, and no tangler
reads that line; this book uses it for its fixtures. Expansion is
[[#stage-26][stage 26]]'s work. Until it lands, babble walks past
both spellings, so a book split across chapter files tangles under
Emacs and comes up short here.

** Collection

Walk src-block nodes in document order. A block under a COMMENT
heading or an ARCHIVE-tagged heading is skipped, with keyword and
tag inheritance down the subtree, and a badge line is a headline
like any other, because batch Emacs never loads org-inlinetask,
which would read it as an inline task instead. A block whose
~:tangle~ resolves to ~no~ is skipped. Blocks gather by resolved target file into units, one unit
per file. Units are ordered by first appearance, and the blocks
inside a unit stay in document order.

** Targets

~:tangle~ takes ~no~, ~yes~, or a path. A path resolves relative to
the book's directory; ~yes~ derives the target from the book's name
plus the language's extension. ~:mkdirp~ (default yes, set by the
driver) creates parent directories. Tangling into the book itself
is an error. A target whose final bytes, banner included, already
sit on disk is not rewritten, so its mtime survives.

** Header arguments

Effective headers merge in org's order, later entries winning:
babel defaults (with the driver's mkdirp), language defaults,
file-level ~#+property:~ lines, inherited ~header-args~ and
~header-args:LANG~ properties, the block's own header line, then
the ~#+header:~ lines above it. Language defaults are org's
~org-babel-default-header-args:LANG~ variables, and they are empty
here for the same reason body expansion is the identity: batch
Emacs with no init file loads no language packs, so nothing defines
them. Inheritance is wholesale and not per key: the nearest
ancestor's drawer replaces a farther one entire, so a key the
nearer drawer omits is not inherited from further up, and the
accumulating ~+~ forms are rejected. The header line splits on space-then-colon
outside balanced parentheses, brackets, and double quotes. A value
is a string; a quoted value is read with elisp string escapes; a
value org would evaluate as lisp is rejected.

The header surface is closed. Every key on every src block,
tangling or not, must sit in a fixed table with three bins:
implemented (~:tangle~, ~:mkdirp~, ~:comments~, ~:padline~,
~:noweb~, ~:noweb-ref~, ~:noweb-sep~, the ~-i~ switch), rejected
(the [[#deviations][Deviations]] list), and inert, the evaluation-only keys
(~:results~, ~:exports~, ~:session~, ~:cache~, ~:eval~ and kin)
that org parses but its tangle path never reads. A key outside the
table is an error. The bins claim to be exhaustive against the oracle, and the
argument is this: the union of parameter lookups on org's tangle
code path (collection, block assembly, noweb expansion, the write
loop) is the implemented set plus the rejected set, and a key that
path never reads cannot change a byte. The argument was made by
reading that path, not by testing every key, so it is only as good
as the reading. An inert key that turns out to be read is a parity
bug, and the oracle is what would catch it.
The table applies to non-tangling blocks too: a misspelled
~:tangle~ leaves the block looking like a deliberate illustration,
and only the unknown-key error can tell the difference. A
non-tangling block carrying ~:results output~ passes, because
inert keys are accepted everywhere.

** The body pipeline

The body is the raw text between the delimiter lines, minus exactly
one trailing newline. Comma-escaped lines (a comma before ~*~ or
~#+~, possibly indented) drop one comma. Common indentation,
measured in columns with tab width eight, is removed unless the
block carries the ~-i~ switch. Noweb expansion runs when enabled. What follows depends on
that same switch, and this is the one place the pipeline forks.

Without ~-i~, indentation is removed once more and the body is
trimmed at both ends of every space, tab and newline, so the first
line starts at column zero whatever it looked like in the book.

With ~-i~, neither dedent runs and the trim keeps the lead: whole
blank lines come off the front, but the first surviving line keeps
its indentation. Both branches trim the same way at the end, so
trailing blanks never reach a target either way.

** Assembly

Each target file is its blocks in document order, with one blank
line between consecutive blocks and a single final newline at end
of file. The blank line is org's padline and it is switchable: a
block carrying ~:padline no~ is joined to the one above it with no
separator, and the value read is the later block's. The count is
one blank line between bodies, not one blank line in the file, so
an empty block still contributes its own newline and two adjacent
empties show up as a run. The first line is the generated-file
banner, ~Code generated from BOOK.org by make tangle. DO NOT
EDIT.~, in the comment syntax of
the language that wrote the file: ~//~ for go and js, ~;;~ for
emacs-lisp and elisp, ~--~ for lua, ~#~ for a language the comment
table does not name, with ~.lit/comments.json~ beside the book
adding languages or overriding these,
followed by one blank line. A target fed by blocks of two
languages is an error naming the file and both languages, raised
before anything is written, since one file takes one comment
syntax.

The banner names BOOK.org whatever the book is actually called.
Both engines hardcode the same string, so a book named b.org still
gets a banner pointing at BOOK.org. Matching the oracle means
keeping it.

** Org comments

Under ~:comments org~, the text between a block and the structure
above it becomes its doc comment. The extent runs from whichever is
nearest above: just past the stars and single space of the closest
headline, or just past the literal end_src of the previous block,
or offset zero, down to the start of the block's begin line, so an
affiliated name line sits inside the extent. A block that tangles
nowhere still counts as a previous block, since the anchor is the
text and not the target.

The driver's docstring rule then applies. Each of its steps has an
edge that is easy to read the wrong way, so they are worth stating
one at a time.

The marker is the line ~# doc~ exactly. A trailing space disqualifies
it, and where there are several, the last one wins. With a marker,
the docstring is everything after it and no paragraph is chosen.
Without a marker, the docstring is the last paragraph, where
paragraphs are separated by two or more newlines and a line of
spaces separates nothing. Keyword lines drop before either of those
steps runs, and only at column zero, so an indented ~#+name:~ reaches
the comment as ordinary text, while a keyword sitting between two
prose lines joins them into one. A leading ~Note:~ or ~Apropos:~
drops, and only when the space after the colon is there.

The result wraps in the block language's line-comment syntax, and a
docstring that is all whitespace inserts nothing. Wrapping preserves
indentation rather than putting a marker at column zero on every
line. The marker sits at the indentation of the shallowest line, and
each line keeps whatever indentation it had beyond that. The marker
takes one space unless the prefix already ends in whitespace, which
is where it parts company with the banner: the banner adds its space
whatever the prefix, so a prefix ending in a space yields two spaces
in a banner and one in a comment.

A line that reads as the comment marker followed by one space comes
out as the bare marker. The driver does this in a hook that runs
over the whole tangled file once it is written, so the rule reaches
a block body as readily as a doc comment, and babble applies it to
the assembled file for the same reason.

The anchors need an example. Two commented blocks under one
heading:

#+begin_example
,* Loading

Load reads the set.

,#+begin_src go :tangle a.go :comments org
func Load() {}
,#+end_src

,#+begin_src go :tangle a.go :comments org
func Save() {}
,#+end_src
#+end_example

Load's extent starts after the heading's stars and runs to its
begin line, so it holds the title and the paragraph; the
last-paragraph rule picks ~Load reads the set.~ and the title
stays behind. Save's extent starts after the previous block's
literal end_src and holds only blank lines, so Save tangles with
no comment at all. Delete the paragraph, though, and the title
itself becomes Load's comment: the extent still ends somewhere,
and the docstring rule takes the last paragraph it finds there.

** Noweb

Under ~:noweb yes~, a reference ~<<name>>~ on its own or with text
before it resolves to the named block's body, or, when no block
carries the name, to the document-order concatenation of every
block whose ~:noweb-ref~ equals it, each followed by its own
~:noweb-sep~ (default newline) except the last. The reference is
single-line and its name neither starts nor ends with whitespace.
Text before the reference on its line is replicated in front of
every expansion line, and it is the text since the previous
reference on that line rather than the whole line. Expansion
recurses only into a block that carries ~:noweb yes~ itself. A block
that tangles nowhere is still a source. Blocks under COMMENT
headings do not participate, and a commented block holding a name
makes that name resolve to nothing for the whole document, since org
takes the first block carrying it and then asks whether it is
commented. An unresolvable reference and a reference cycle are
errors; org expands the first to nothing and gives up on the second
when its recursion runs out.

** Dynamic blocks

~#+begin: NAME args~ dispatches on NAME; a refresh deletes the
interior wholesale and rewrites it, so hand edits do not survive
and a second refresh is byte-identical to the first. Dynamic
blocks are recognized at column zero, and the writer set is closed
by dispatch: two names exist, and an unknown name is an error.
src-block-diff takes ~:old~ and ~:new~ block names, runs the
system ~diff -u~ over their bodies, drops the two temp-file header
lines, and wraps the rest in a src diff block, or writes the words
~no differences~. plan-toc writes one line per plan-markup site (a
site is any line carrying plan markup: a stage heading, a badge
line of fifteen or more stars, a hole string, a CriticMarkup edit,
a twin name, or a generated diff), labels spelled without the
sigils, as line-number links, with sites below the block shifted
by the number of lines the writer is about to insert. babble never
renders org; the book file is rewritten by splicing fresh
interiors into the retained bytes, so every construct outside a
dynamic-block interior, understood or not, survives byte-for-byte
by construction.

An interior is what the writer inserts, plus one newline. Org
empties a dynamic block by deleting the interior and then opening a
line for the writer to insert at, and the opened line's newline
stays behind whatever arrives. plan-toc writes lines that each end
in a newline, so a refreshed plan-toc ends with a blank line before
its ~#+end:~. src-block-diff stops at ~#+end_src~ with no newline of
its own, so its ~#+end_src~ and ~#+end:~ end up on consecutive
lines. The difference is org's, not the writers'.

A writer reads the book part-refreshed. Org takes the dynamic blocks
in document order, so a writer runs against a buffer where every
block above it already holds its new interior, its own interior is
one empty line, and every block below it still holds the old one.
plan-toc counts lines in that buffer, which is why a book with two
generated diffs above a plan-toc and one below it produces different
numbers than the same book would if all four were refreshed at once.

plan-toc corrects for its own insertion and for nothing else. A site
above the block keeps the number the staged buffer gave it; a site
below the block gains the number of lines the writer is about to
insert. Every other block below plan-toc is still at its old size in
that buffer, so if one of them grows on the same run, every site
under it gets a number that is short by the growth. The index is
right one run later, when the writer finds those interiors already
at their final size.

That is worth stating plainly, because it means a single refresh is
not a fixed point and the goal is not that it should be. The
property babble holds to is that its first run matches the driver's
first run and its second matches the driver's second, wrong numbers
included. Producing a better index than the driver produces would be
a difference, and a difference is the one thing the tangler is not
allowed to be.

The bodies a src-block-diff compares are the bodies org-babel hands
over, which is the shape a tangle would write minus the noweb
expansion: comma escapes off, one trailing newline off, and dedented
unless the block keeps its indentation. A reference inside a
compared body is compared as the reference, not as what it stands
for.

Where the two engines look for dynamic blocks differs, and the
difference is the reason for a refusal rather than a rule. Org
searches the raw buffer line by line for a begin line and does not
care what element that line sits in, so a delimiter quoted inside an
example block, or a line of code that happens to start that way, is
a dynamic block to org. babble reads the tree, where the same line
is text belonging to something else. Reproducing the raw search
would mean giving up the tree, so the book is refused instead, and
the refusal lives in the parser so that no document reaches a
refresh without it.

Where a dynamic block ends is org's rule too, and not the keyword
reader's. Org closes on the first line reading ~#+end~ followed by a
colon, whitespace, or the end of the line, with anything after the
colon ignored and any indentation allowed. The keyword reader is
stricter on both counts, and the gap is not a difference of opinion
about the tree: it decides which bytes a refresh overwrites. A book
holding ~#+end: x~ inside a dynamic block would give the reader an
interior running past it, and splicing over that interior would
delete lines org kept.

Every pattern taken from the driver folds case, because Emacs folds
case when it searches and the driver never asks it not to. So
~#+BEGIN:~ opens a dynamic block, a lowercase todo word in a heading
is a plan site, and a twin suffix in any casing names a twin. A
literal port into a case-sensitive language would lose index entries
and refuse books that are fine.

* Deviations

:PROPERTIES:
:CUSTOM_ID: deviations
:END:
Places where babble departs from what org would do: refusals,
each a loud error instead of an imitation, plus one byte-neutral
difference in when files are written. The refusals are the fence.
No refusal may fire on a real book, and [[#stage-10][stage 10]] adds the test that
enforces it; today the corpus is only parsed, not judged. The error
message always names the construct and the supported alternative.

- A block whose target is the book itself is refused, and the
  refusal fires during collection so nothing is written at all; org
  would happily overwrite the book with its own code.
- Lisp-valued header arguments (a value starting with a parenthesis,
  quote, backquote, or bracket) are rejected; org evaluates them.
- A src block without a language is an error; org's tangle scanner
  silently ignores the block.
- A block that never closes is an error, for every kind babble
  parses and not just src; org parses the opener as a paragraph and
  reads on.
- An unresolvable noweb reference is an error; org expands it to
  the empty string and writes the file, which it does because the
  variable that would make it complain is off and the driver leaves
  it off. A noweb cycle is an error; org exhausts its own recursion
  limit and writes nothing, so both engines refuse and only the
  message differs. A noweb call reference, ~<<name(args)>>~, is
  evaluation and is rejected; org treats any parentheses in the
  name as a call, wherever they sit.
- A reference naming a heading's ~CUSTOM_ID~ is an error. Org
  searches those before it searches block names and answers with the
  whole subtree as raw text, delimiter lines included.
- A name that is both a block's name and some block's ~:noweb-ref~
  value is an error. Which one org picks depends on what it expanded
  earlier in the same run, because the group scan replaces the cache
  the name lookup consults.
- ~:noweb~ is read as a list of words, which is how org reads it:
  it splits the value on whitespace and looks for a word from its own
  list.
  The subset takes ~yes~, ~no~, and ~inline~ beside ~yes~. The last
  is not org's word. It asks the weave to show a block's references
  expanded in the listing rather than as links, and org carries it
  past without noticing, so a book marked that way tangles the same
  under either engine and under an org that has never heard of it.
  Alone it is refused, since org would read the value as ~no~ and
  leave the references in the tangled file with nothing to say why.
  A word neither engine knows is refused too, where org would
  quietly ignore it.
- Noweb and named-block resolution is case-sensitive. Org folds case
  when it searches for a block's name, though not when it looks up a
  ~:noweb-ref~ group, so a reference that only resolves by ignoring
  case tangles there and is an error here, naming the near miss.
- A duplicate ~#+name:~ across src blocks is an error, as is a name
  that some block also uses as a ~:noweb-ref~ value; org would
  resolve both by whichever its scan finds first.
- The header table is closed: a key babble does not know is an
  error, so org's option space cannot leak in unclassified. Within
  the table, the rejected keys error by name: ~:comments~ values
  other than ~no~ and ~org~, ~:var~, ~:shebang~, ~:tangle-mode~,
  ~:no-expand~, ~:noweb~ values other than ~yes~ and ~no~,
  ~:noweb-prefix~, ~:prologue~, ~:epilogue~, ~:dir~ (org's
  working-directory key, rejected in every form and not only the
  attachment one), the ~-r~ and ~-l~
  coderef switches (org's code-reference labels), accumulating
  ~header-args+~ properties, inline src blocks (code blocks inside
  a prose line).
  The inert keys (evaluation-only arguments such as ~:results~ and
  ~:exports~, and the ~-n~ and ~-k~ switches) pass through because
  the oracle's tangle path never reads them. The
  tangle-inert fixture carries one block with every one of them and
  one block with none, and requires the two targets to come out
  identical.
- A language whose comment prefix holds no marker, only whitespace
  or nothing, cannot carry a doc comment. babble refuses the block
  and names the language. The driver does not refuse it: it dies
  partway through with the file unwritten, and matching a crash is
  worth less than naming what is wrong.
- A block delimiter written at column zero inside an example, export
  or comment body is refused. Org finds the block above by searching
  the raw text backwards, so it reads that line as a real delimiter
  and anchors a comment extent on it; babble reads a tree, where the
  line is text inside one verbatim block. Both engines would write a
  file and the files would differ. Indenting the line, or escaping
  it with a comma, keeps the meaning and removes the ambiguity.
- ~.lit/comments.json~ is looked for beside the book. The driver
  resolves the book's path a second time inside a buffer already
  visiting it, so a relative path naming a subdirectory looks one
  level too deep and finds nothing; babble looks where the file is.
  The make rules always name the book from its own directory, so the
  two agree on every path the toolchain itself uses.
- Block delimiters quoted verbatim inside example, src, export, or
  comment block bodies are a lint error: org's raw backward searches
  would anchor comment extents on them, and no structural parser can
  agree with that. Dynamic-block delimiters are a separate rule, two
  bullets down, because indentation does not put one out of reach.
  {>>stage 10: src bodies come out of this bullet. Measured, the two
  engines agree on them: the backward search looks for an end
  delimiter and a src body cannot carry one without ending itself,
  and an opener quoted in one tangles the same way in both<<}
- A dynamic block with an unknown name is an error; org empties
  its interior and logs a message it then ignores. An indented
  dynamic block is an error; org re-indents its interior, padding
  blank lines with trailing spaces. Dynamic-block arguments beyond keyword and name tokens
  are rejected; org hands them to the lisp reader.

- A ~#+begin:~ line that babble's tree does not report as a dynamic
  block is refused, and so is a dynamic block that lives in the tree
  and outside a raw search. Org looks for dynamic blocks by searching
  the buffer line by line, ignoring block structure and allowing
  indentation, so a delimiter quoted inside an example block or a
  code body is one to org and not to babble. Its own rule is
  narrower in the other direction: it wants whitespace after the
  colon, where babble's keyword reader does not. Escaping the line
  with a comma settles the first case; writing the space settles the
  second. Indenting settles neither, which is the one piece of
  advice the older refusal above gets wrong for this construct.
- A src-block-diff naming a block the book does not contain is an
  error. Org's refresh has already emptied the interior when the
  lookup fails, logs the failure, and moves on, so the block ends up
  empty with nothing on the page to say why.
- An indented dynamic block is an error for a second reason the
  entry above does not give: org has two answers for it. The step
  that indents a refreshed interior begins by selecting a window,
  and selecting a window also changes the current buffer to the one
  that window shows. The driver opens the book without showing it,
  so the step goes looking for a dynamic block in whatever buffer
  happens to be on screen, fails to find one, and the failure is
  swallowed with every other refresh failure. Under a driver that
  shows the book, the same refresh indents the interior and pads its
  blank lines with trailing spaces. Nothing about this depends on
  batch mode; batch Emacs has a window like any other.
- A dynamic block whose closing line babble's keyword reader and
  org's search disagree about is not a refusal but a rule: org's
  search wins. It closes on the first line reading ~#+end~ followed
  by a colon, whitespace, or nothing, ignoring the rest of the line
  and allowing indentation, where the reader wants a colon and an
  empty value. The disagreement decides which bytes a refresh
  overwrites, so following the reader here would delete text org
  keeps.
- A book with CRLF line endings is refused. Org decodes the file on
  the way in and encodes it on the way out, so a line it generates
  comes back with the same ending as the rest of the file; babble
  splices bytes and would leave the file half one way and half the
  other. The refusal is a limit of the subset, not of org.
- A book whose last line has no newline gains one, because saving a
  buffer adds it. This is the one place a refresh changes a byte
  nobody asked it to change, and both engines change it the same
  way.
- Unchanged targets are not rewritten, so their mtimes survive a
  tangle; the oracle rewrites every target every run because its
  identity check compares a bannerless buffer to the bannered file
  on disk. The book file likewise is written only when its bytes
  changed; the oracle saves it after every dynamic-block refresh.
  Bytes are identical in all four cases; only mtimes differ.

* How the oracle parses

:PROPERTIES:
:CUSTOM_ID: how-the-oracle-parses
:END:
The specification for babble's frontend is not the org manual, it
is org-element.el. This chapter states the algorithm that file
implements, because babble replicates it: same shape, same
decisions, same order, in Go types. Line numbers below are org
9.7.11, the version the oracle runs, and the syntax those parsers
implement is written up separately at
https://orgmode.org/worg/dev/org-syntax.html. Everything here is
this book's own account of what that code does; none of its text
is reproduced, since org is GPL and babble is not.

The first thing to know is that org has no tokenizer. There is no
token stream between the buffer and the parser. The parser looks
at raw text at the moment it needs to decide something, which is
why a construct's meaning can depend on where it sits.

** The loop

:PROPERTIES:
:CUSTOM_ID: the-loop
:END:
~org-element--parse-elements~ (org-element.el:5192) walks a byte
range and does three things per element: ask what starts here,
jump to where that element says it ends, and, when the element can
contain other elements, recurse into its interior. The range is
the parser's bound, and it is the reason a block cannot swallow
the heading below it: a section's elements are parsed between the
section's own start and end.

#+begin_src mermaid
flowchart TD
  start([parse range beg..end]) --> ask["current-element:<br/>what starts at point?"]
  ask --> el["element with begin, end,<br/>contents-begin, contents-end"]
  el --> jump["point = element end"]
  jump --> greater{"greater<br/>element?"}
  greater -->|yes| rec["recurse into<br/>contents range"]
  greater -->|no| more{"point < end?"}
  rec --> more
  more -->|yes| ask
  more -->|no| done([return elements])
#+end_src

** The dispatch

:PROPERTIES:
:CUSTOM_ID: the-dispatch
:END:
~org-element--current-element~ (org-element.el:4637) decides an
element's type from the start of one line, in a fixed order.
Context comes first: when the caller passed a mode saying "we are
inside a list item" or "inside a property drawer", that mode wins
before any text is examined. Then a star run means a headline.
Then one bulk regexp (~org-element--current-element-re~, 4616)
matches drawers, fixed-width lines, dynamic-block openers,
~#+begin_X~, ~#+CALL:~, plain keywords, footnote definitions,
horizontal rules and diary sexps in a single pass, and the code
dispatches on which numbered group matched. What is left over is a
table or a paragraph.

The single regexp is an optimization, and the source explains it:
the parsers follow house rules about never disturbing Emacs's
global match data, grouping regexps so one call replaces several,
and precomputing patterns instead of building them per line, all
because repeated matching dominated the profile on large buffers.
babble inherits the decision but not the technique. Its dispatcher
tests line prefixes rather than matching regexps, so there is no
match state to protect and nothing to gain by fusing the tests;
the branches stay separate, which is what lets the dispatch table
read as a table.

For ~#+begin_X~ the block name picks the parser: CENTER, COMMENT,
EXAMPLE, EXPORT, QUOTE, SRC and VERSE have their own, and any
other name is a special block. That list is the whole reason
babble splits verbatim blocks from greater blocks.

The order is the specification, because the first branch that
matches wins and several of them can match the same line. Here it
is as the elisp reads it, with the branches babble's subset never
reaches marked. babble's ~currentElement~ answers these questions
in this order, which is what makes the two comparable at all.

| # | branch | condition | subset |
|---|---|---|---|
| 1 | item | mode is item | no |
| 2 | table row | mode is table-row | no |
| 3 | node property | mode is node-property | yes |
| 4 | headline | stars, then a space | yes |
| 5 | section | mode is a section mode | implicit |
| 6 | comment | an org comment line | as prose |
| 7 | planning | mode is planning | no |
| 8 | property drawer | mode admits one | yes |
| 9 | paragraph | point past a line start | no |
| 10 | clock | a clock line | no |
| 11 | inlinetask | deep stars, feature loaded | no |
| 12 | affiliated | a name line, then retry | yes |
| 13 | bulk regexp | nine shapes in one match | four |
| 14 | table | a leading pipe | no |
| 15 | paragraph | everything left | yes |

Branch 13 is the one that carries most of org's syntax. Its nine
shapes are drawers, fixed-width lines, dynamic-block openers,
~#+begin_X~, ~#+CALL:~, keywords, footnote definitions,
horizontal rules and diary sexps, and babble reaches four of them:
the dynamic-block opener, ~#+begin_X~, keywords, and the drawer
shape that branch 8 consumes.

Two other entries are worth reading twice. Branch 11 is why a
fifteen-star badge is an ordinary headline here: batch Emacs never
loads org-inlinetask, so the condition is false and control falls
to branch 4, which is what babble does unconditionally. Branch 7 is
a difference babble carries: org admits a planning line between a
headline and its property drawer, and babble does not, so a drawer
below a planning line is prose here and its properties are lost.

** Elements find their own end

Every element parser receives the bound and searches for its own
terminator inside it. ~org-element-src-block-parser~
(org-element.el:2990) looks for a line matching ~#+END_SRC~ with
nothing after it, and when the search fails it does not raise an
error: it calls the paragraph parser instead, and the opening line
becomes ordinary text. babble refuses that case instead, which is
one of the [[#deviations][Deviations]].

Paragraphs are the subtle ones (org-element.el:2854). A paragraph
ends at the next line that cannot be inside it, but each candidate
is verified before it counts: a drawer line only ends the
paragraph if a matching ~:END:~ exists ahead, and a ~#+BEGIN_X~
only ends it if a matching ~#+END_X~ exists, with X captured from
the opener and quoted into a fresh search. Deciding where prose
stops therefore requires proving that a pair matches, somewhere
below.

** Greater, lesser, and mode

Two properties of an element type steer the loop. Whether it is a
greater element decides whether the parser recurses into it:
headlines, sections, quote blocks, centre blocks, special blocks,
items, tables and footnote definitions hold elements, while src,
example, export, comment and verse blocks hold text. And the mode
an element hands to its successor decides how the next line is
read: after a headline the mode admits a planning line and then a
property drawer, inside a list the mode makes each line an item,
inside a property drawer each line is a node property.

Mode is why the same three characters parse differently in two
places. ~:END:~ closes a drawer in one position and is prose in
another, and no amount of looking at the line itself will tell you
which.

One rule about greater elements is worth stating because babble's
block parsers depend on it: apart from headlines and list items, a
greater element cannot contain another of its own type. That is
why searching forward for the first matching terminator is correct
rather than merely convenient, and why a quote block inside a
quote block closes the outer one.

** Affiliated keywords

~org-element--collect-affiliated-keywords~ (org-element.el:4843)
runs before the element parser and attaches ~#+name:~,
~#+caption:~ and their kin to the element below them. The element
then carries two positions: ~:begin~, at the first affiliated
keyword, and ~:post-affiliated~, at the element's own first line.
The tangler uses the second, which is why babble records the
begin-line offset separately from the block's full span.

** What babble takes, and what it leaves

babble replicates the element layer: the loop, the dispatch, the
per-element terminator search, greater against lesser, mode, and
affiliated keywords. It leaves three things behind. The object
layer, ~org-element--object-lex~ (org-element.el:5261), which
tokenizes inline markup inside paragraphs, is unnecessary because
nothing in a tangle looks inside prose. The element cache exists
for interactive editing. And granularity, which lets a caller stop
the recursion early, has one setting here: parse everything.

The naming follows the oracle deliberately. Org calls its parsers
~org-element-TYPE-parser~, so babble calls its own TYPEParser, and
the two correspond function for function, which is what makes a
divergence findable rather than merely suspected. Org also
records what adding an element type costs: write its parser, teach
the dispatcher to recognize it, and list the type. babble's price
is the same three, an element parser, a branch in the table, and a
node type, which is the shape the remaining stages pay each time
they widen the subset.

* Architecture
:PROPERTIES:
:CUSTOM_ID: architecture
:END:

babble parses first. The whole book becomes a logical tree, and
the tangler decides everything against that tree rather than by
re-scanning text. The dynamic-block writers are the exception, and
the next paragraph says why.

The oracle works the same way, which is what makes the design a
port and not a guess. org-babel's scan loop (~org-babel-map-src-blocks~,
ob-core.el:1273) does use a regexp to find candidates, but every
hit must then be confirmed: ~org-babel-active-location-p~
(ob-core.el:1237) asks ~org-element-context~ whether point is
really on a src block, and a hit that is not is skipped.
Everything babel then reads comes from the element.
~org-babel-get-src-block-info~ takes the language, body, name,
switches and position through ~org-element-property~, and never
reads the regexp's captures. The tangler's own collector
(~org-babel-tangle-collect-blocks~, ob-tangle.el:482) is built on
that loop. So the element grammar is the authority for recognition
and attributes, and the tree is babble's spelling of the same
authority.

That is why the book is kept as bytes as well as a tree. Every node
carries its line number, which plan-toc links point at, and its
byte span, which extents and dynamic-block splicing slice.

The dynamic-block writers are the exception because the lit
convention defines plan markup on raw lines and not on structure. A
badge is a headline of fifteen stars, a twin is a block whose name
ends a certain way, and CriticMarkup is a bracket pair that can
open and close mid-sentence. None of those are element types, so no
tree can hold them. plan-toc therefore runs the patterns ported
from tangle.el over the retained source lines, and takes only its
splice points from the tree.

Org spellings stop at ~internal/org~. The frontend knows org
syntax, scanning, spans, the balanced header splitter, the value
reader, and nothing past it does. ~internal/book~ is the tree the
backend consumes, free of org spellings, which is the seam a future
markdown frontend would plug into. ~internal/tangle~ owns
collection, targets, the body pipeline, comments, noweb, banners,
and assembly; ~internal/dblock~ owns refresh and the two writers.
The dependency arrows all point one way, and everything passes
through the tree:

#+begin_src mermaid
graph LR
  book[BOOK.org] --> org["internal/org<br/>recognition, spans, headers"]
  org -->|"org spellings stop here"| tree["internal/book<br/>the logical tree"]
  tree --> tangle["internal/tangle<br/>collect, noweb, comments, assemble"]
  tree --> dblock["internal/dblock<br/>refresh, plan-toc, src-block-diff"]
  tangle --> files[tangled sources]
  dblock --> book2[BOOK.org rewritten]
  cmd["internal/cmd<br/>the order a command runs them in"] -.-> org
  cmd -.-> tangle
  cmd -.-> dblock
#+end_src

The confirm step makes the scan regexp almost invisible: whatever
it captures is thrown away. Three effects survive it, found by
reading the regexp against what the element parser produces for the
same text, and each has a home here. First, it demands a language
token, so a languageless block never tangles: babble makes that an
error.
Second, the ~:comments org~ extent is anchored on raw match
positions, so the tree records them: per headline, the offset just
past the stars and following space; per block, the offset where the
begin line starts and the offset just past the literal end_src.
Third, org's backward anchor search does not element-confirm, so a
delimiter quoted inside a verbatim body would anchor extents in
Emacs but never in a tree; the quoted-delimiter lint forbids the
shape, so the divergence never reaches an accepted book.

Two facts keep the port small. The first is that batch Emacs loads
no language packs, so org's language-specific expansion hooks never
exist and body expansion falls to the generic path. That path is
the identity as long as nothing injects variables into a body, and
nothing can: ~:var~ is a rejected key, so a book that asks for
injection is refused rather than expanded. babble expands nothing
and matches. The second is that the driver pins the whole comment
story to five language modes, so comment wrapping is a table rather
than a port of Emacs's comment machinery.

* The command line

babble is four subcommands over one book: ~tangle~ writes the
sources, ~parse~ reads the book and reports whether it parses,
printing the tree only when asked with ~--dump~. main is only the wiring, streams
in and exit code out, so the tests can drive run the way a shell
drives main. Exit codes follow convention: 2 for usage errors, 1
for failures.

babble tangles lit books without Emacs. This file is tangled from
BOOK.org.

#+name: cli-run
#+begin_src go :tangle main.go :comments org
func run(args []string, stdout, stderr io.Writer) int {
	if len(args) < 1 {
		fmt.Fprint(stderr, usage)
		return 2
	}
	switch args[0] {
	case "parse":
		fs := flag.NewFlagSet("parse", flag.ContinueOnError)
		fs.SetOutput(stderr)
		dump := fs.Bool("dump", false, "print the tree as JSON")
		if err := fs.Parse(args[1:]); err != nil {
			return 2
		}
		if fs.NArg() != 1 {
			fmt.Fprint(stderr, usage)
			return 2
		}
		d, err := org.Parse(fs.Arg(0))
		if err == nil {
			err = org.ResolveAll(d)
		}
		if err != nil {
			fmt.Fprintln(stderr, "babble:", err)
			return 1
		}
		if *dump {
			out, err := book.Dump(d)
			if err != nil {
				fmt.Fprintln(stderr, "babble:", err)
				return 1
			}
			if _, err := stdout.Write(out); err != nil {
				return 1
			}
		}
		return 0
	case "tangle":
		if len(args) != 2 {
			fmt.Fprint(stderr, usage)
			return 2
		}
		return tangleCmd(args[1], stderr)
	case "init":
		fs := flag.NewFlagSet("init", flag.ContinueOnError)
		fs.SetOutput(stderr)
		module := fs.String("module", "", "go module path (default: the directory name)")
		dir := fs.String("dir", ".", "directory to set up")
		if err := fs.Parse(args[1:]); err != nil {
			return 2
		}
		if fs.NArg() != 0 {
			fmt.Fprint(stderr, usage)
			return 2
		}
		return initCmd(*dir, *module, stdout, stderr)
	case "vendor":
		fs := flag.NewFlagSet("vendor", flag.ContinueOnError)
		fs.SetOutput(stderr)
		dir := fs.String("dir", ".", "directory to write lit/ into")
		if err := fs.Parse(args[1:]); err != nil {
			return 2
		}
		if fs.NArg() != 0 {
			fmt.Fprint(stderr, usage)
			return 2
		}
		return vendorCmd(*dir, stdout, stderr)
	}
	fmt.Fprint(stderr, usage)
	return 2
}
#+end_src

The walk writes only what differs, so the report names the files that
were behind and says nothing when the copy is already current. A
directory that is not there is refused rather than created: init
makes a project and this refreshes one, so a mistyped path should
say so instead of leaving a directory holding nothing but a
toolchain. The toolchain's own checkout is refused too, since there
the embedded copy is whatever was compiled in and the source beside
it may be newer.

#+begin_src go :tangle main.go :comments org
func vendorLit(dir string, out io.Writer) error {
	info, err := os.Stat(dir)
	if err != nil {
		return err
	}
	if !info.IsDir() {
		return fmt.Errorf("%s is not a directory", dir)
	}
	if _, err := os.Stat(filepath.Join(dir, "lit", "BOOK.org")); err == nil {
		return fmt.Errorf("%s holds lit/BOOK.org and is the toolchain's own checkout; run make tangle in lit/ instead", dir)
	}
	wrote := 0
	err = fs.WalkDir(litFS, "lit", func(path string, d fs.DirEntry, err error) error {
		if err != nil || d.IsDir() {
			return err
		}
		want, err := litFS.ReadFile(path)
		if err != nil {
			return err
		}
		target := filepath.Join(dir, filepath.FromSlash(path))
		if old, err := os.ReadFile(target); err == nil && bytes.Equal(old, want) {
			return nil
		}
		if err := replaceFile(target, want); err != nil {
			return err
		}
		wrote++
		fmt.Fprintln(out, path)
		return nil
	})
	if err == nil && wrote == 0 {
		fmt.Fprintln(out, "lit/ is already current")
	}
	return err
}
#+end_src

A file is written beside its target and renamed over it. The rename
is what makes the file whole-old or whole-new, so a run that fails
partway leaves no mixture of two toolchains, and it is also what
replaces a symbolic link instead of writing through it to whatever
it points at.

#+begin_src go :tangle main.go :comments org
func replaceFile(target string, body []byte) error {
	if err := os.MkdirAll(filepath.Dir(target), 0o755); err != nil {
		return err
	}
	tmp, err := os.CreateTemp(filepath.Dir(target), ".babble-*")
	if err != nil {
		return err
	}
	defer os.Remove(tmp.Name())
	if _, err := tmp.Write(body); err != nil {
		tmp.Close()
		return err
	}
	if err := tmp.Close(); err != nil {
		return err
	}

** Starting a book

~babble init~ turns an empty directory into a lit repository. It
exists so that starting one takes a single command with no checkout
and no copying by hand:

#+begin_example
  go run github.com/bilus/babble@latest init
#+end_example

The toolchain has to travel with the binary for that to work, since
~go run~ compiles from the module cache and leaves the program no
way back to its own source tree. So lit's files are compiled in.
The book's own copy under lit/ is the only copy: this embed reads
the same bytes the rest of the repository uses, so a new project
gets whatever lit was current when the binary was built, and there
is nothing to keep in step.

vendor writes the embedded toolchain into a directory that already
holds a project. Everything under lit/ belongs to the toolchain, so
vendor replaces the whole embedded set, and a project that wants
instructions of its own keeps them somewhere else. A file is
rewritten only when its bytes differ, which is the rule a tangled
target already follows and which matters more here: lit.mk makes the
PDF depend on the filters, so touching every file would cost every
following weave a full rebuild.

Each file is replaced whole or not at all, written beside its target
and renamed over it, so a run that fails partway leaves no mixture of
two toolchains and a symlink under lit/ is replaced rather than
written through. Nothing is removed, because several paths sit
outside the embedded set on purpose and the repository holding them
is the toolchain's own; sweeping lit/ clean would delete the source
the rest is tangled from. Nothing outside lit/ is touched at all,
which is what lets a build call it without knowing what is already
there.

* The document tree
:PROPERTIES:
:CUSTOM_ID: the-document-tree
:END:

Package book is the tree the backend consumes, and it parses
nothing. That is the package's whole job: it is the seam a markdown
frontend would plug into, and a frontend plugs in by building these
types, never by handing over text.

The names still borrow org's vocabulary, and deliberately. SrcBlock,
Padline, NowebRef and AfterStars all say what org calls the thing,
because inventing a second vocabulary for concepts a markdown
frontend would have to reproduce anyway buys nothing. What is
absent is the syntax: no code here knows what a star or a ~#+~ line
looks like, and none of it can read a byte of a book.

Document is one parsed book: the node tree plus the retained
source bytes that every Span indexes.

		if !fn(n) {

		case *Headline:

The wrapper marshals itself because Go cannot flatten a field into
its enclosing object: an embedded type parameter is illegal and an
embedded interface marshals under its own key, so a typed wrapper
that keeps the flat shape has to splice the node's object itself.

func (d dumped) MarshalJSON() ([]byte, error) {
	body, err := json.Marshal(d.node)
	if err != nil {
		return nil, err
	}
	if len(body) < 2 || body[0] != '{' || body[len(body)-1] != '}' {
		return nil, fmt.Errorf("dump: %s node marshaled as %s, want an object", d.kind, body)
	}
	var b bytes.Buffer
	fmt.Fprintf(&b, `{"type":%q`, d.kind)
	if inner := body[1 : len(body)-1]; len(inner) > 0 {
		b.WriteByte(',')
		b.Write(inner)
	}
	if len(d.children) > 0 {
		kids, err := dumpNodes(d.children)
		if err != nil {
			return nil, err
		}
		raw, err := json.Marshal(kids)
		if err != nil {
			return nil, err
		}
		b.WriteString(`,"children":`)
		b.Write(raw)
	}
	b.WriteByte('}')
	return b.Bytes(), nil
}

#+begin_src go :tangle internal/book/book.go
func dumpNodes(nodes []Node) ([]json.Marshaler, error) {
	out := make([]json.Marshaler, 0, len(nodes))
	for _, n := range nodes {
		m, err := dumpNode(n)
		if err != nil {
			return nil, err
		}
		out = append(out, m)
	}
	return out, nil
}

func dumpNode(n Node) (json.Marshaler, error) {
	switch n := n.(type) {
	case *Headline:
		return dumped{"headline", n, n.Children}, nil
	case *Prose:
		return dumped{"prose", n, nil}, nil
	case *Keyword:
		return dumped{"keyword", n, nil}, nil
	case *SrcBlock:
		return dumped{"src", n, nil}, nil
	case *DynamicBlock:
		return dumped{"dynamic", n, n.Children}, nil
	case *QuoteBlock:
		return dumped{"quote", n, n.Children}, nil
	case *VerbatimBlock:
		return dumped{"verbatim", n, nil}, nil
	}
	return nil, fmt.Errorf("dump: unknown node type %T", n)
}

* Reading org
:PROPERTIES:
:CUSTOM_ID: reading-org
:END:

Package org is the frontend: everything that knows the input syntax
lives here, and it hands the backend a finished tree. This chapter
is the port of the algorithm the previous one described, in the
order that chapter described it.

Six sections, and the order is the pipeline. First the entry points
and the line index every offset is measured against. Then the loop
and the dispatcher, which are org's two halves and the reason the
port is comparable at all. Then the element parsers, one per shape
the dispatcher can reach. Then the line shapes those parsers ask
about, which are small predicates over one line each. Then the two
things read from the whole document rather than one line. And last,
header resolution, which turns what was parsed into what the
backend acts on, and which owns the closed table that is half the
fence.

refresh reparse can feed bytes directly.

#+begin_src go :tangle internal/org/org.go
func ParseBytes(src []byte, path string) (*book.Document, error) {
	if bytes.Contains(src, []byte("\r\n")) {
		return nil, fmt.Errorf("%s: CRLF line endings; org rewrites generated lines in the file's own ending and babble splices bytes, so the two cannot agree on a mixed file", path)
	}
	d := &book.Document{Path: path, Source: src,
		Keywords: map[string][]string{}, Todo: todoWords(src)}
	p := &parser{src: src, path: path, d: d,
		todo: map[string]bool{}, lines: lineStarts(src)}
	for _, w := range d.Todo {
		p.todo[w] = true
	}
	nodes, err := p.parseElements(0, len(src), modeFirstSection)
	if err != nil {
		return nil, err
	}
	d.Nodes = nodes

Org does not find dynamic blocks the way babble does, and the gap is
not something a tree can be taught. Org reads the buffer line by
line and takes the first line that looks like an opener, wherever it
sits: inside an example block, inside a code body, indented by any
amount. babble reads the tree, where such a line belongs to whatever
element contains it. Reproducing org's search would mean giving up
the tree for the one case that abuses it.

So babble asks both and compares. Run org's opener pattern over the
raw source, collect every line number in the tree, and look at
the difference. A line only org finds is a delimiter that wants a
comma in front of it. A line only the tree finds is one written
without the whitespace org's pattern requires after the colon.
Either way the answer is an error naming the line, and neither
engine has to imitate the other.

The pattern folds case, and so does every other pattern this stage
ports. Emacs searches case-insensitively unless told otherwise and
the driver never tells it otherwise, so ~#+BEGIN:~ is an opener to
org. A case-sensitive port would call that line tree-only and refuse
a book org is perfectly happy with.

The scan runs a line at a time rather than over the whole source,
which is why the pattern anchors without a multiline flag. Comparing
by line number is also what makes the two answers comparable at all:
one side has offsets and elements, the other has lines and nothing
else, and a line number is the one thing common to both.

** The loop and the dispatcher

Mode is the context a parent hands its children. Org threads seven
of them; the three below are the ones this subset can reach, and
the dispatcher branches on the third. Org's planning mode has no
counterpart here, and not because the line is unrecognized: it is,
and the drawer below it is read. The difference is where. Org
threads a mode to make the next line's parse depend on the last
one; babble handles the planning line inside the headline parser,
which steps over it and then asks for the drawer. Same result,
one fewer mode.

parseElements is the loop from [[#the-loop][The loop]]: identify what starts
here, recurse when it holds elements, jump to its end, repeat. The
bound matters twice over. Elements are parsed within it, and a
non-headline element gets the tighter bound of the next headline,
which is org's section, and the reason a block cannot reach past
a heading to find its terminator.

#+begin_src go :tangle internal/org/org.go :comments org
func (p *parser) parseElements(beg, end int, m mode) ([]book.Node, error) {
	var out []book.Node
	for off := beg; off < end; {
		p.off = off
		text, _ := p.line(off)
		limit := end
		if starRun(text) == 0 {
			limit = p.nextHeadline(off, end, anyLevel)
		}
		el, next, err := p.currentElement(limit, m)
		if err != nil {
			return nil, err
		}
		if el.node != nil {
			if el.adopt != nil && el.contents.End > el.contents.Start {
				kids, err := p.parseElements(el.contents.Start, el.contents.End, el.childMode)
				if err != nil {
					return nil, err
				}
				el.adopt(kids)
			}
			out = append(out, el.node)
		}
		off = next
		m = modeSection
	}
	return out, nil
}

currentElement is the dispatcher. It asks, in this order: is this a
star run, are we inside a property drawer, does a run of affiliated
lines start here, is this a block delimiter, is this a keyword, and
otherwise a paragraph. The first branch that matches wins, which is
why the order is the contract and not a detail.

The order differs from org's table in [[#the-dispatch][The dispatch]], which tests
node-property before headline. Org can afford that because it has
modes babble does not: item, table-row and node-property each
narrow what a line is allowed to be. babble carries one such mode,
for the property drawer, and a star run is unambiguous against it
because a drawer cannot contain a headline. So the two orders agree
on every input either can be given, and the difference is in what
org must still rule out at that point and babble already has.

#+begin_src go :tangle internal/org/org.go :comments org
func (p *parser) currentElement(limit int, m mode) (parsed, int, error) {
	start := p.off
	text, next := p.line(start)
	if starRun(text) > 0 {
		return p.headlineParser(text, next, limit)
	}
	if m == modePropertyDrawer {
		if props, after, ok := p.propertyDrawerParser(start, limit); ok {
			return parsed{props: props}, after, nil
		}
	}
	aff := affiliated{begin: start}
	if blockAt, name, header, ok := p.affiliatedRun(start, limit); ok {
		aff.name, aff.header = name, header
		p.off = blockAt
		text, next = p.line(blockAt)
	}
	if name, rest, _, ok := blockDelim(text, "begin"); ok {
		switch name {
		case "src":
			return p.srcBlockParser(rest, next, limit, aff)
		case "example", "export", "comment", "verse":
			return p.verbatimBlockParser(name, next, limit, aff)
		default:
			return p.greaterBlockParser(name, next, limit, aff)
		}
	}
	if key, value, ok := keywordLine(text); ok {
		if key == kwBegin {
			return p.dynamicBlockParser(value, next, limit, aff)
		}
		return p.keywordParser(key, value, text, next)
	}
	return p.paragraphParser(limit)
}

		return true
	}

		return true

		}
		off = next
	}

			return off, text, true
		}
		off = next
	}
	return 0, "", false

func (p *parser) headlineParser(text string, next, limit int) (parsed, int, error) {
	off := p.off
	stars := starRun(text)
	h := &book.Headline{Level: stars, Line: p.lineNum(off),
		AfterStars: off + stars + 1,
		Head:       book.Span{Start: off, End: off + len(text)}}
	rest := strings.TrimLeft(text[stars+1:], " \t")
	if w, r, ok := firstWord(rest); ok && p.todo[w] {
		h.Todo = w
		rest = r
	}
	if len(rest) >= 4 && strings.HasPrefix(rest, "[#") && rest[3] == ']' {
		rest = strings.TrimLeft(rest[4:], " \t")
	}
	if rest == "COMMENT" || strings.HasPrefix(rest, "COMMENT ") {
		h.Commented = true
		rest = strings.TrimLeft(strings.TrimPrefix(rest, "COMMENT"), " \t")
	}
	rest, h.Tags = splitTags(rest)
	h.Title = strings.TrimSpace(rest)
	for _, tag := range h.Tags {
		if tag == "ARCHIVE" {
			h.Archived = true
		}
	}
	end := p.nextHeadline(next, limit, stars)
	contents := next
	if after, ok := p.planningLine(next, end); ok {
		contents = after
	}
	p.off = contents
	if el, after, err := p.currentElement(end, modePropertyDrawer); err == nil && el.props != nil {
		h.Properties = el.props
		contents = after
	}
	return parsed{node: h, contents: book.Span{Start: contents, End: end},
		adopt:     func(kids []book.Node) { h.Children = kids },
		childMode: modeSection}, end, nil
}

Tags are the trailing colon-fenced run; each tag is alphanumerics
plus the four org extras. Anything that fails the shape stays in
the title, so the first line below has two tags and the second has
none.

#+begin_src go :tangle internal/org/org.go :comments org
func splitTags(s string) (string, []string) {
	t := strings.TrimRight(s, " \t")
	if !strings.HasSuffix(t, ":") {
		return s, nil
	}
	i := strings.LastIndexAny(t, " \t")
	cand := t[i+1:]
	if len(cand) < 2 || cand[0] != ':' {
		return s, nil
	}
	parts := strings.Split(cand[1:len(cand)-1], ":")
	for _, p := range parts {
		if p == "" || !tagWord(p) {
			return s, nil
		}
	}
	return t[:i+1], parts
}

func tagWord(s string) bool {
	for _, c := range s {
		switch {
		case c >= 'a' && c <= 'z', c >= 'A' && c <= 'Z',
			c >= '0' && c <= '9', c == '_', c == '@', c == '#', c == '%':
		default:
			return false
		}
	}
	return true
}

func (p *parser) propertyDrawerParser(from, limit int) (map[string]string, int, bool) {
	text, next := p.line(from)
	key, value, ok := colonLine(text)
	if !ok || !strings.EqualFold(key, "PROPERTIES") || value != "" {
		return nil, from, false
	}

			return props, next, true
		}
		props[strings.ToLower(key)] = value
		off = next
	}
	return nil, from, false
}

** Line shapes

The shape tests below are the only place a line's spelling is
examined, and every one of them is a pure function of the line
plus a position. They are read at the point of decision, never
ahead of time, which is what stops a lexical phase from deciding
grammar. Each answers one question about one line, in the order
below: how many stars open it, whether it is a block delimiter,
whether it is a keyword line, and whether it is a colon line.

#+begin_src go :tangle internal/org/org.go :comments org
func starRun(text string) int {
	i := 0
	for i < len(text) && text[i] == '*' {
		i++
	}
	if i > 0 && i < len(text) && text[i] == ' ' {
		return i
	}
	return 0
}

func blockDelim(text, word string) (name, rest string, after int, ok bool) {
	i := 0
	for i < len(text) && (text[i] == ' ' || text[i] == '\t') {
		i++
	}
	prefix := "#+" + word + "_"
	if len(text) < i+len(prefix) || !strings.EqualFold(text[i:i+len(prefix)], prefix) {
		return "", "", 0, false
	}
	j := i + len(prefix)
	k := j
	for k < len(text) && text[k] != ' ' && text[k] != '\t' {
		k++
	}
	if k == j {
		return "", "", 0, false
	}
	return strings.ToLower(text[j:k]), strings.TrimSpace(text[k:]), k, true
}

func keywordLine(text string) (key, value string, ok bool) {
	t := strings.TrimLeft(text, " \t")
	if !strings.HasPrefix(t, "#+") {
		return "", "", false
	}
	rest := t[2:]
	i := strings.IndexByte(rest, ':')
	if i <= 0 {
		return "", "", false
	}
	for _, c := range rest[:i] {
		switch {
		case c >= 'a' && c <= 'z', c >= 'A' && c <= 'Z',
			c >= '0' && c <= '9', c == '_', c == '-':
		default:
			return "", "", false
		}
	}
	return strings.ToLower(rest[:i]), strings.TrimSpace(rest[i+1:]), true
}

func colonLine(text string) (key, value string, ok bool) {
	t := strings.TrimSpace(text)
	if len(t) < 3 || t[0] != ':' {
		return "", "", false
	}
	j := strings.IndexByte(t[1:], ':')
	if j <= 0 || strings.ContainsAny(t[1:1+j], " \t") {
		return "", "", false
	}
	return t[1 : 1+j], strings.TrimSpace(t[2+j:]), true
}

	generic string            // header-args
	lang    map[string]string // header-args:LANG

func (s scope) with(props map[string]string) (scope, error) {
	out := scope{generic: s.generic, lang: s.lang}
	for k, v := range props {
		if strings.HasSuffix(k, "+") {
			return out, fmt.Errorf("accumulating property %s is not in the subset; set the whole value", k)

			out.generic = v
			continue

			next := map[string]string{}

				next[key] = val
			}
			next[l] = v
			out.lang = next
		}
	}
	return out, nil
}

func balancedSplit(s string) []string {
	var out []string
	start, depth, quoted := 0, 0, false
	for i := 0; i < len(s); i++ {
		switch c := s[i]; {
		case quoted:
			if c == '\\' {
				i++
			} else if c == '"' {
				quoted = false
			}
		case c == '"':
			quoted = true
		case c == '(' || c == '[':
			depth++
		case c == ')' || c == ']':
			if depth > 0 {
				depth--
			}
		case c == ':' && depth == 0 && i > 0 && (s[i-1] == ' ' || s[i-1] == '\t'):
			out = append(out, strings.TrimSpace(s[start:i]))
			start = i
		}
	}
	if last := strings.TrimSpace(s[start:]); last != "" {
		out = append(out, last)
	}
	if len(out) > 0 && out[0] == "" {
		out = out[1:]
	}
	return out
}

	case '(', '\'', '`', '[':

#+begin_src go :tangle internal/org/org.go
func unquote(v string) (string, error) {
	if len(v) < 2 || v[len(v)-1] != '"' {
		return "", fmt.Errorf("unterminated string in header argument %s", v)
	}
	var b strings.Builder
	for i := 1; i < len(v)-1; i++ {
		if v[i] != '\\' {
			b.WriteByte(v[i])
			continue
		}
		i++
		if i >= len(v)-1 {
			return "", fmt.Errorf("trailing escape in header argument %s", v)
		}
		switch v[i] {
		case 'n':
			b.WriteByte('\n')
		case 't':
			b.WriteByte('\t')
		default:
			b.WriteByte(v[i])
		}
	}
	return b.String(), nil
}

A dynamic block that diffs two blocks needs their bodies in the
shape the driver's writer gets, which is the tangling shape minus
one step. References stay as
written because the driver asks org-babel for the body and org-babel
expands nothing at that point, so a twin of a block full of
references shows a diff of the references, which is also the diff a
reader wants to see.

The lookup underneath it is the whole-document one, not the lookup
noweb uses. Those two differ on purpose. Noweb refuses a name whose
first definition sits under a COMMENT heading, because org's noweb
expansion refuses it. Org's named-block search is a plain scan of
the buffer with no notion of COMMENT, so a buried block does
answer a diff even though nothing would tangle it. Reusing the noweb
lookup here would be the same kind of mistake in the other
direction.

It lives in package tangle rather than beside the writer that calls
it because the rules it applies are the tangler's. A second copy of
them would be free to drift away from the file the diff claims to
describe.

func collect(d *book.Document) ([]unit, error) {
	var units []unit
	var firstErr error
	at := map[string]int{}
	fail := func(format string, args ...any) {
		if firstErr == nil {
			firstErr = fmt.Errorf(format, args...)
		}
	}
	d.Walk(func(n book.Node) bool {
		switch n := n.(type) {
		case *book.Headline:
			return !n.Commented && !n.Archived
		case *book.SrcBlock:
			if n.Lang == "" {
				fail("%s:%d: src block without a language", d.Path, n.Line)
				return true
			}
			if n.Params.Tangle == "no" || n.Params.Tangle == "" {
				return true
			}
			target, err := targetFor(d, n)
			if err != nil {
				fail("%s", err)
				return true
			}
			if sameFile(d.Path, target) {
				fail("%s:%d: refusing to tangle into the book itself: %s", d.Path, n.Line, target)
				return true
			}
			i, seen := at[target]
			if !seen {
				i = len(units)
				at[target] = i
				units = append(units, unit{target: target, lang: n.Lang})
			}
			if units[i].lang != n.Lang {

The trim is org's own, and org's takes a flag. Without it both ends

blank lines and nothing else, so the first line of a block that
preserves its indentation stays indented. The set is space, tab and
newline; a carriage return is not whitespace to org and survives.

func orgTrim(s string, keepLead bool) string {
	s = strings.TrimRight(s, orgSpace)
	if !keepLead {
		return strings.TrimLeft(s, orgSpace)
	}
	for {
		nl := strings.IndexByte(s, '\n')
		if nl < 0 || strings.Trim(s[:nl], " \t") != "" {
			return s
		}
		s = s[nl+1:]
	}
}

func unescapeCommas(body string) string {
	lines := strings.Split(body, "\n")
	for i, line := range lines {
		j := 0
		for j < len(line) && (line[j] == ' ' || line[j] == '\t') {
			j++
		}
		k := j
		for k < len(line) && line[k] == ',' {
			k++
		}
		if k == j {
			continue
		}
		if rest := line[k:]; strings.HasPrefix(rest, "*") || strings.HasPrefix(rest, "#+") {
			lines[i] = line[:k-1] + rest
		}
	}
	return strings.Join(lines, "\n")
}

Indentation is measured in columns, with a tab worth eight, and
the common measure comes off every line. A blank line has no
indentation to speak of and does not hold the measure down; a line
flush with the margin does, and then nothing moves.

Cutting by column rather than by character means a tab can straddle
the cut. A tab advances to the next multiple of eight, so a measure
of four lands halfway through one, and there is no half tab to
delete. Such a line keeps its indentation whole and is not dedented
at all.

That is org's behaviour, and it is worth knowing why, because the
obvious guess is wrong. Org cuts with ~move-to-column n t~, and the
forcing flag does not split a tab: it pads with spaces in front of
the tab until point sits at column n. The delete that follows takes
exactly the padding it just added, so the line comes out as it went
in. A tab is only removed when the measure lands on its far edge.

#+begin_src go :tangle internal/tangle/tangle.go :comments org
func dedent(body string) string {
	lines := strings.Split(body, "\n")
	measure := -1
	for _, line := range lines {
		if strings.TrimSpace(line) == "" {
			continue
		}
		if c := indentColumns(line); measure < 0 || c < measure {
			measure = c
		}
	}
	if measure <= 0 {
		return body
	}
	for i, line := range lines {
		lines[i] = cutColumns(line, measure)
	}
	return strings.Join(lines, "\n")
}

func indentColumns(line string) int {
	col := 0
	for i := 0; i < len(line); i++ {
		switch line[i] {
		case ' ':
			col++
		case '\t':
			col += 8 - col%8
		default:
			return col
		}
	}
	return col
}

func cutColumns(line string, n int) string {
	col, i := 0, 0
	for i < len(line) && col < n {
		switch line[i] {
		case ' ':
			col++
		case '\t':
			col += 8 - col%8
		default:
			return line[i:]
		}
		i++
	}
	if col > n {
		return line
	}
	return line[i:]
}

// Wrapping follows comment-region, which is more particular than a
// prefix on every line. It ignores whitespace at either end of the
// text, indents every marker to the shallowest line it is about to
// comment, and keeps whatever indentation the line had beyond that.
// A blank line inside becomes the marker and a space, which the
// file-wide trim later reduces to the bare marker.
//
// The marker takes one space unless the prefix already ends in
// whitespace. The banner's rule differs: it always adds a space, so
// a project whose prefix ends in one gets two there and one here.
//
// A prefix with nothing but whitespace in it has no marker to write.
// The driver does not refuse that, it dies partway with the file
// unwritten, and matching a crash is worth less than naming it.
func wrapComment(lang, text string, comments commentTable) (string, error) {
	prefix := comments.prefix(lang)
	if strings.TrimSpace(prefix) == "" {
		return "", fmt.Errorf("%s has no comment marker, so a :comments org block cannot be written; give it one in .lit/comments.json", lang)
	}
	marker := prefix
	if !strings.HasSuffix(marker, " ") && !strings.HasSuffix(marker, "\t") {
		marker += " "
	}
	lines := strings.Split(text, "\n")
	lead := shallowest(lines)
	var out strings.Builder
	for _, line := range lines {
		rest := line
		if len(rest) >= len(lead) {
			rest = rest[len(lead):]
		} else {
			rest = strings.TrimLeft(rest, " \t")
		}
		out.WriteString(lead)
		out.WriteString(marker)
		out.WriteString(rest)
		out.WriteString("\n")
	}
	return out.String(), nil
}

// The indentation of the shallowest line that has anything on it.
// A blank line does not lower it.
func shallowest(lines []string) string {
	lead := ""
	found := false
	for _, line := range lines {
		if strings.TrimSpace(line) == "" {
			continue
		}
		indent := line[:len(line)-len(strings.TrimLeft(line, " \t"))]
		if !found || len(indent) < len(lead) {
			lead, found = indent, true
		}
	}
	return lead
}

// The docstring is everything after the last "# doc" marker line, or
// the last paragraph when there is none. Keyword lines drop first,
// which is why a keyword between two prose lines joins them: the rule
// takes the line and its newline together, and the split that finds
// the last paragraph runs afterwards.
func docstring(text string) string {
	if i := lastDocMarker(text); i >= 0 {
		return sigil(strings.Trim(dropKeywordLines(text[i:]), " \t\n\r"))
	}
	clean := dropKeywordLines(text)
	var last string
	for _, para := range regexp.MustCompile(`\n\n+`).Split(clean, -1) {
		if para != "" {
			last = para
		}
	}
	return sigil(strings.Trim(last, " \t\n\r"))
}

// The marker is the line "# doc" and nothing else, so a trailing
// space disqualifies it, and the last one in the text wins.
func lastDocMarker(text string) int {
	at := -1
	for i := 0; ; {
		j := strings.Index(text[i:], "# doc\n")
		if j < 0 {
			break
		}
		start := i + j
		if start == 0 || text[start-1] == '\n' {
			at = start + len("# doc\n")
		}
		i = start + 1
	}
	return at
}

// Only a keyword at column zero counts, so an indented one reaches
// the comment as ordinary text.
func dropKeywordLines(text string) string {
	return regexp.MustCompile(`(?m)^#\+[^\n]*\n?`).ReplaceAllString(text, "")
}

// The sigil marks an aside for the reader and is not part of the
// comment. It needs the trailing space, and it runs after the trim,
// which is the one way a docstring can start with a newline.
func sigil(text string) string {
	for _, word := range []string{"Note: ", "Apropos: "} {
		if strings.HasPrefix(text, word) {
			return text[len(word):]
		}
	}
	return text
}

#+begin_src go :tangle internal/tangle/tangle.go :comments org
// The reference pattern is org's, ported character for character.
// Hand-rolling a line scanner instead would miss two things it does:
// a name may hold spaces inside it but not at either end, and a
// one-character name whose closer is followed by another reference on
// the same line swallows both into one unresolvable name.
var nowebRe = regexp.MustCompile(`(.*?)(<<([^ \t\n](?:.*?[^ \t\n])?)>>)`)

func expandNoweb(d *book.Document, b *book.SrcBlock, body string) (string, error) {
	return expandInto(d, body, nil)
}

// The text before a reference is repeated in front of every line the
// reference expands to, except the first, which already sits after
// that text. The prefix is what lies between the previous reference
// and this one on the same line, so a second reference on a line is
// prefixed by the text between the two and not by the whole line. It
// cannot reach back past a line ending, which is why the pattern's
// dot does not match one.
func expandInto(d *book.Document, body string, open []string) (string, error) {
	var out strings.Builder
	rest := body
	for {
		m := nowebRe.FindStringSubmatchIndex(rest)
		if m == nil {
			out.WriteString(rest)
			return out.String(), nil
		}
		prefix := rest[m[2]:m[3]]
		name := rest[m[6]:m[7]]
		out.WriteString(rest[:m[0]])
		out.WriteString(prefix)
		text, err := resolve(d, name, open)
		if err != nil {
			return "", err
		}
		out.WriteString(strings.ReplaceAll(text, "\n", "\n"+prefix))
		rest = rest[m[1]:]
	}
}

// A name resolves to the block that carries it, or to the blocks that
// share it as a :noweb-ref, joined by each one's own separator with
// the last one's dropped. A referenced body is expanded further only
// when that block asks for it: org gates recursion on the block's own
// :noweb, so a plain block's references reach the file as text.
func resolve(d *book.Document, name string, open []string) (string, error) {
	for _, seen := range open {
		if seen == name {
			return "", fmt.Errorf("%s: noweb reference cycle: %s", d.Path, strings.Join(append(open, name), " -> "))
		}
	}
	if strings.ContainsAny(name, "()") {
		return "", fmt.Errorf("%s: <<%s>> is a call reference, which is evaluation and not in the subset", d.Path, name)
	}
	if err := refusedName(d, name); err != nil {
		return "", err
	}
	if named := namedBlock(d, name); named != nil {
		return bodyOf(d, named, append(open, name))
	}
	group := groupBlocks(d, name)
	if len(group) == 0 {
		return "", fmt.Errorf("%s: <<%s>> resolves to nothing%s", d.Path, name, nearMiss(d, name))
	}
	var parts []string
	for i, g := range group {
		text, err := bodyOf(d, g, append(open, name))
		if err != nil {
			return "", err
		}
		parts = append(parts, text)
		if i < len(group)-1 {
			parts = append(parts, g.Params.NowebSep)
		}
	}
	return strings.Join(parts, ""), nil
}

A block under a COMMENT heading is not a noweb source, and the way
org reaches that answer matters. It takes the first block carrying
the name in document order and then asks whether it is commented,
rather than passing over it and looking further, so a commented
block holding a name makes that name resolve to nothing for the
whole document. babble does the same, since the alternative is to
find a different block than the driver finds.

That makes the lookup two questions, not one, and the reason to
split them is that neither answers the other. The first block
carrying the name is the one org settles on, commented or not. Whether
org would still tangle that block is a separate fact about where it
sits. A block is a source only when both questions return it; when
they return different blocks, the first one is buried and shadows
whatever follows.

The shape below exists because the obvious single walk gets this
wrong, and the way it gets it wrong is quiet. Carrying one flag
that turns true at a COMMENT heading and never turns off makes
every block after that heading look commented, wherever in the
document it actually sits, so one dead draft near the top
unresolves references far below it and the error names the
reference rather than the draft. The flag has no way back down,
because a walk that reports entering a node never reports leaving
it. Asking twice removes the need for the flag: each walk is a
plain search under a fixed rule about COMMENT, each is right on its
own, and the answer is whether they agree.

// firstNamed is the search both questions need: the first block in
// document order carrying name, over the whole document or over
// only the part org would still tangle.
func firstNamed(d *book.Document, name string, skipCommented bool) *book.SrcBlock {
	var found *book.SrcBlock
	d.Walk(func(n book.Node) bool {
		switch n := n.(type) {
		case *book.Headline:
			return !(skipCommented && n.Commented)
		case *book.SrcBlock:
			if found == nil && n.Name == name {
				found = n
			}
		}
		return true
	})
	return found
}

func groupBlocks(d *book.Document, name string) []*book.SrcBlock {
	var group []*book.SrcBlock
	d.Walk(func(n book.Node) bool {
		switch n := n.(type) {
		case *book.Headline:
			return !n.Commented
		case *book.SrcBlock:
			if n.Params.NowebRef == name {
				group = append(group, n)
			}
		}
		return true
	})
	return group
}

// A referenced body arrives the way the block would have tangled it,
// minus the target: comma escapes gone, one trailing newline gone,
// and dedented unless the block preserves its indentation.
func bodyOf(d *book.Document, b *book.SrcBlock, open []string) (string, error) {
	body := unescapeCommas(string(d.Source[b.Body.Start:b.Body.End]))
	body = strings.TrimSuffix(body, "\n")
	if !b.Params.PreserveIndent {
		body = dedent(body)
	}
	if !b.Params.Noweb {
		return body, nil
	}
	return expandInto(d, body, open)
}

// The near miss is worth naming. Org folds case when it looks a name
// up and babble does not, so a reference that differs only in case
// tangles there and stops here, and the reader needs to see why.
func nearMiss(d *book.Document, name string) string {
	miss := ""
	d.Walk(func(n book.Node) bool {
		if b, ok := n.(*book.SrcBlock); ok && miss == "" {
			if strings.EqualFold(b.Name, name) && b.Name != name {
				miss = b.Name
			}
			if strings.EqualFold(b.Params.NowebRef, name) && b.Params.NowebRef != name {
				miss = b.Params.NowebRef
			}
		}
		return true
	})
	if miss == "" {
		return ""
	}
	return fmt.Sprintf("; %s differs only in case, and names here are case-sensitive", miss)
}

One table gives every language its line-comment prefix. The
built-in rows name the languages the toolchain's own books tangle,
~.lit/comments.json~ beside the book adds languages or overrides
these, its entries winning, and a language in neither takes the
hash.

Four rules govern the file itself. They exist because the driver
reads it with Emacs's JSON parser and babble reads it with Go's, and
those two parsers disagree in ways that change the bytes a tangle
writes.

A missing file is not an error, and neither is a file that cannot be
read. The driver skips both without a word. A babble that refused
would refuse every book in this repository, since none of them has
the file.

A value that is not a string is an error in both engines. That
includes JSON null. Go would otherwise store null as the empty
string and give every banner a leading space, where the driver
refuses to tangle at all.

Content after the closing brace is accepted, because Emacs reads one
value and ignores whatever follows it. Go's usual reader rejects the
whole document instead, so babble decodes one value and stops.

A prefix that is present but empty is used as it stands. The elisp
lookup treats the empty string as an answer; the Go habit of testing
whether a value is empty would fall through to the hash.

// The rows the toolchain's own books need. A language absent from
// the table takes the hash, which comments shells, Python, Ruby and
// make; the languages that would read a hash as code name themselves
// here or in the project's own file.
var builtinComments = commentTable{
	"go": "//", "js": "//",
	"emacs-lisp": ";;", "elisp": ";;",
	"lua": "--",
}

func loadCommentTable(bookPath string) (commentTable, error) {
	t := commentTable{}
	for lang, prefix := range builtinComments {
		t[lang] = prefix
	}
	path := filepath.Join(filepath.Dir(bookPath), ".lit", "comments.json")
	f, err := os.Open(path)
	if err != nil {
		return t, nil
	}
	defer f.Close()
	var raw map[string]any
	if err := json.NewDecoder(f).Decode(&raw); err != nil {
		return nil, fmt.Errorf("%s: %w", path, err)
	}
	for lang, v := range raw {
		prefix, ok := v.(string)
		if !ok {
			return nil, fmt.Errorf("%s: comment prefix for %s is not a string", path, lang)
		}
		t[lang] = prefix
	}
	return t, nil
}

// A prefix that is present wins even when it is empty, which is why
// this reads the second return value rather than testing for "".
func (t commentTable) prefix(lang string) string {
	if prefix, ok := t[lang]; ok {
		return prefix
	}
	return "#"
}

* The tangle flow

Package cmd holds what a command does once its arguments are
parsed. Today that is one thing, Tangle, and it is here because two
callers need it: the command line and the oracle harness. When each
kept its own copy they drifted, and the drift was the worst kind.
The harness never ran the lint the command ran, so the cross-check
that exists to prove babble matches Emacs was quietly measuring
something babble does not do.

The order is short and every step in it has a reason to be where it
is. Read the book. Refresh its dynamic blocks. Write the book back
if the refresh changed it. Read it again. Tangle.

The reread is the step to explain. Refreshing inserts and deletes
lines, so every byte offset in the tree is stale the moment it
happens, and the tangle leans on offsets throughout: a block's body
is a byte range, a doc comment's extent is found by walking back
from one, and a generated diff holds a real src block that
collection has to see. Patching the tree to match would mean keeping
a second implementation of the parser. Reading again costs one pass
over a file that is already warm.

It reads again only when the refresh changed something, because when
nothing changed the tree in hand still describes the file on disk.

The package sits above the other three and nothing else imports it,
which is what keeps the arrows pointing one way. Putting this
function in package tangle instead would have made the backend
import the frontend, and putting it in main would have put it out of
the harness's reach, since Go will not let a package import main.

* Dynamic-block refresh

Package dblock owns the book side. Refresh splices a fresh interior
into every dynamic block and returns the book's new bytes together
with whether they differ from the old ones, so the caller writes the
file only when there is something to write.

The package never renders org. It keeps the bytes the book already
has and replaces the interiors, so a construct nothing here
recognizes comes through a refresh unchanged. There is no round trip
from text to a tree and back, which is the trip a book loses
formatting on.

Refresh takes a function rather than reaching for the bodies itself.
A src-block-diff needs the body of a named block shaped the way
org-babel shapes it, and those rules belong to the tangler. Passing
them in keeps dblock resting on the document alone and keeps one
copy of the shaping.

func Refresh(d *book.Document, body NamedBody) ([]byte, bool, error) {
	var blocks []*book.DynamicBlock
	d.Walk(func(n book.Node) bool {
		if db, ok := n.(*book.DynamicBlock); ok {
			blocks = append(blocks, db)
		}
		return true
	})
	if len(blocks) == 0 {
		return d.Source, false, nil
	}
	src := d.Source
	file := filepath.Base(d.Path)
	out := make([]byte, 0, len(src))
	cursor := 0
	for _, db := range blocks {
		out = append(out, src[cursor:db.Interior.Start]...)
		staged := make([]byte, 0, len(out)+1+len(src)-db.Interior.End)
		staged = append(staged, out...)
		staged = append(staged, '\n')
		staged = append(staged, src[db.Interior.End:]...)
		text, err := write(db, staged, bytes.Count(out, newline)+1, file, body)
		if err != nil {
			return nil, false, fmt.Errorf("%s:%d: %v", d.Path, db.Line, err)
		}
		out = append(out, text...)
		out = append(out, '\n')
		cursor = db.Interior.End
	}
	out = append(out, src[cursor:]...)
	if out[len(out)-1] != '\n' {
		out = append(out, '\n')
	}
	return out, !bytes.Equal(out, src), nil
}

var newline = []byte("\n")

Splicing is a loop over the dynamic blocks in document order,
copying the bytes between them and calling a writer for each
interior. Two details in that loop are not obvious, and both come
from watching what the driver does rather than from what a refresh
sounds like it should do.

The first is the newline. Org empties an interior by deleting it and
then opening a line, so the writer inserts at the start of an empty
line that already ends in a newline. Whatever the writer produces
keeps that newline behind it. babble appends it, which is why a
writer here returns text that does not end in one and why the two
writers can end differently without either being wrong.

The second is which buffer a writer reads. Org refreshes from the
top down, so a writer sees a book where the blocks above it are
already rewritten, its own interior is a single empty line, and the
blocks below it still hold their old contents. plan-toc counts lines
in that buffer. Handing it the original book, or the finished one,
gives different numbers for the same input. So the loop stages that
exact byte sequence for each writer: the output built so far, one
newline, and the rest of the original from the closing line onward.

The walk that finds the blocks does not skip a COMMENT subtree,
because org's search does not. A dynamic block under a commented
heading refreshes like any other. Nothing tangles out of it, and it
is still part of the book's text.

Saving a buffer appends a final newline when the file lacks one, so
the splice does too. It is the only byte a refresh changes that
nobody asked it to change, and the condition is exact: the driver
saves only a buffer it modified, and emptying an interior modifies
the buffer even when the text that replaces it is identical. A book
with no dynamic block in it is never saved and never gains the
newline, so a book with no dynamic block comes out of a refresh
byte for byte as it went in.

counted and will exist in the file the links have to address.

its old size, so those links come out short and stay short until the
next refresh. babble reproduces that rather than fixing it, because
matching the driver is the point and being right where the driver is
wrong is a difference like any other.

unless something turns that off, and nothing in the driver does, so
a lowercase todo word in a heading is a plan site and a twin suffix
in any casing names a twin. Ported literally into a language that
does not fold, the index would quietly come out shorter than the
driver's.

carried them would be a plan site itself, and the index would start
indexing itself on the next refresh.

#+begin_src go :tangle internal/dblock/dblock.go :comments org
func planToc(staged []byte, self int, file string) string {
	type site struct {
		line  int
		label string
	}
	var hits []site
	for i, text := range strings.Split(string(staged), "\n") {
		if label := planSite(text); label != "" {
			hits = append(hits, site{i + 1, label})
		}
	}
	var b strings.Builder
	shift := len(hits)
	for _, h := range hits {
		n := h.line
		if n > self {
			n += shift
		}
		fmt.Fprintf(&b, "- [[file:%s::%d][%d]] %s\n", file, n, n, h.label)
	}
	return b.String()
}

// The census patterns, ported from the driver. Every one folds case
// because Emacs folds case, and the folding is not cosmetic: it
// turns [A-Z] in the entry pattern into any letter, which is what
// makes a lowercase heading an entry.
//
// The CriticMarkup openers are written as character classes rather
// than escaped literals. The weave rewrites CriticMarkup by running
// over the book's whole text, code bodies included, so a pattern
// that spelled its own sigil would be read as an edit to the
// sentence around it and would swallow the rest of the page.
var (
	planSiteRe   = regexp.MustCompile(`(?i)^\*+ (?:PLANNED|FILLING|HOLE|LIVE|DROPPED) |^\*{15,} |HOLE\(|\{[+][+]|\{[-][-]|\{[~][~]|\{[>][>]|^#\+begin: src-block-diff|--planned`)
	planTodoRe   = regexp.MustCompile(`(?i)^#\+todo:`)
	planBadgeEnd = regexp.MustCompile(`(?i)^\*{15,} END`)
	planBadgeRe  = regexp.MustCompile(`(?i)^\*{15,} (.*)`)
	planEntryRe  = regexp.MustCompile(`(?i)^\*+ ([A-Z]+ .*)`)
	planDiffRe   = regexp.MustCompile(`(?i)^#\+begin: src-block-diff`)
	planHoleRe   = regexp.MustCompile(`(?i)HOLE\(([0-9]+)\): ([^"]*)`)
	planInsRe    = regexp.MustCompile(`\{[+][+](.*)`)
	planDelRe    = regexp.MustCompile(`\{[-][-](.*)`)
	planRepRe    = regexp.MustCompile(`\{[~][~](.*)`)
	planNoteRe   = regexp.MustCompile(`\{[>][>](.*)`)
	planTwinRe   = regexp.MustCompile(`(?i)#\+name: (.*)--planned`)
)

// planSite answers what a line is called in the index, or nothing
// when the line is not a site. A line has to match the census
// pattern first: the naming rules below are wider than it is, and
// the driver applies them only to lines the census already found.
func planSite(text string) string {
	if !planSiteRe.MatchString(text) {
		return ""
	}
	if planTodoRe.MatchString(text) || planBadgeEnd.MatchString(text) {
		return ""
	}
	if m := planBadgeRe.FindStringSubmatch(text); m != nil {
		return "badge: " + planStrip(m[1])
	}
	if m := planEntryRe.FindStringSubmatch(text); m != nil {
		return "entry: " + planStrip(m[1])
	}
	if planDiffRe.MatchString(text) {
		return "generated diff"
	}
	if m := planHoleRe.FindStringSubmatch(text); m != nil {
		return fmt.Sprintf("hole %s: %s", m[1], planStrip(m[2]))
	}
	for _, kind := range []struct {
		re    *regexp.Regexp
		label string
	}{
		{planInsRe, "insertion: "},
		{planDelRe, "deletion: "},
		{planRepRe, "replacement: "},
		{planNoteRe, "note: "},
	} {
		if m := kind.re.FindStringSubmatch(text); m != nil {
			return kind.label + planStrip(m[1])
		}
	}
	if m := planTwinRe.FindStringSubmatch(text); m != nil {
		return "twin of " + m[1]
	}
	return ""
}

var (
	planLinkRe = regexp.MustCompile(`\[\[[^]]*\]\[([^]]*)\]\]`)
	planTagRe  = regexp.MustCompile(`\s+:[a-zA-Z0-9_@:]+:$`)
)

// planStrip is the driver's label cleanup: trim, replace org links
// with their descriptions, drop a trailing tag block, and cut to
// sixty characters with an ellipsis. The count is characters and
// not bytes, which is what the driver counts.
func planStrip(s string) string {
	s = strings.TrimSpace(s)
	s = planLinkRe.ReplaceAllString(s, "$1")
	s = planTagRe.ReplaceAllString(s, "")
	if r := []rune(s); len(r) > 60 {
		return string(r[:57]) + "..."
	}
	return s
}

Only the first mark on a line is indexed. The driver searches, takes
the line it landed on, names it, and then steps to the next line, so
a sentence carrying an insertion and a deletion is one site and the
deletion is not in the index. Splitting on newlines and asking each
line once reproduces that without reproducing the search.

srcBlockDiff writes a unified diff of two named blocks' bodies, or
the words ~no differences~. The engine is the system ~diff~, called
with ~-u~ on two temporary files, because that is what the driver
calls and the hunks then agree without anyone reasoning about
context lines.

Each body is written with a newline appended, so a body that does
not end in one still makes a whole last line. The first two lines of
the output name the temporary files and are dropped. What is left is
wrapped in a src block tagged diff, so the woven book highlights it
and a tangler passes over it. ~diff~ exits nonzero when the files
differ, which is the ordinary case here, so the exit status only
means trouble above one.

A compared body can carry a line that breaks the block it is about
to sit in. Diff prefixes context lines with a space, so a body line
reading ~#+end_src~ arrives indented by one column, and an indented
closer still closes a block: the generated block would end early and
the rest of the diff would become prose. A body line reading
~#+begin:~ is worse. It arrives as an opener org's raw search will
find, inside a src block where the tree will not, which is exactly
the disagreement that makes the parse refuse a book. babble would write the refreshed
book and then refuse to read it again, leaving a file on disk that
the tool that wrote it cannot parse.

Both are refused here, before anything is written. A refusal that
comes after the write does not refuse anything. It sets a trap.

Arguments are read strictly. Org hands the argument text to the lisp
reader, whose grammar is the whole of lisp; babble takes keyword
and name tokens and refuses the rest, so the subset does not inherit
a reader it has no use for.

func srcBlockDiff(args string, body NamedBody) (string, error) {

	if err != nil {
		return "", err
	}
	old, err := body(p["old"])
	if err != nil {
		return "", fmt.Errorf("src-block-diff :old %s: %v", p["old"], err)
	}
	new, err := body(p["new"])
	if err != nil {
		return "", fmt.Errorf("src-block-diff :new %s: %v", p["new"], err)
	}
	dir, err := os.MkdirTemp("", "src-block-diff")
	if err != nil {
		return "", err
	}
	defer os.RemoveAll(dir)
	oldPath := filepath.Join(dir, "old")
	newPath := filepath.Join(dir, "new")
	if err := os.WriteFile(oldPath, []byte(old+"\n"), 0o644); err != nil {
		return "", err
	}
	if err := os.WriteFile(newPath, []byte(new+"\n"), 0o644); err != nil {
		return "", err
	}
	out, err := exec.Command("diff", "-u", oldPath, newPath).CombinedOutput()
	if ee, ok := err.(*exec.ExitError); ok && ee.ExitCode() == 1 {
		err = nil
	}
	if err != nil {
		return "", fmt.Errorf("diff -u: %v", err)
	}
	if len(out) == 0 {
		return "no differences", nil
	}
	lines := strings.Split(string(out), "\n")
	if len(lines) < 3 {
		return "", fmt.Errorf("diff -u printed %d lines, too few to hold its own header", len(lines))
	}
	hunks := lines[2:]
	for i, text := range hunks {
		if dangerousLine.MatchString(text) {
			return "", fmt.Errorf("the diff of %s and %s carries %q, which would end the generated block or open a dynamic block inside it; the two bodies cannot be shown this way", p["old"], p["new"], strings.TrimSpace(hunks[i]))
		}
	}
	return "#+begin_src diff\n" + strings.Join(hunks, "\n") + "#+end_src", nil
}

func dblockArgs(args string) (map[string]string, error) {
	out := map[string]string{}
	fields := strings.Fields(args)
	for i := 0; i < len(fields); i += 2 {
		key := fields[i]
		if len(key) < 2 || key[0] != ':' {
			return nil, fmt.Errorf("dynamic-block argument %s is not a keyword or a name", key)
		}
		if i+1 == len(fields) {

		}
		out[key[1:]] = value
	}
	return out, nil
}

tangle-comments pins the three parts of the rule that could each be
read another way. Its anchors book asks that a block directly under
a heading with no paragraph takes the heading's own title, that a
block with only blank lines above it takes no comment at all, and
that a block before any headline reaches back to the start of the
file. Its marker book asks that the last ~# doc~ wins, that a sigil
drops only with its space, and that one without the space stays. Its
shapes book asks that an indented keyword survives, that a blank
line inside becomes a bare marker, and that indentation beyond the
shallowest line is kept.

watching both suites report it, the goldens and the cross-check
against Emacs.

tangle-comment-table pins four requirements. A go block writing a
~.templ~ file opens with ~//~, since the marker follows the language
and not the extension. A language the built-in table does not name
opens with ~#~, unless ~.lit/comments.json~ names it. A prefix that
is present but empty is used as it stands, where the Go habit of
testing whether a value is empty would give a hash instead. A file
fed by blocks of two languages is refused with nothing written.

with different parsers and could write different bytes without
either of them failing. Each requirement was checked by breaking the
code that satisfies it and watching the fixture report the break.

** Rebuilding a golden

A golden is what Emacs produces, and the way to rebuild one is to
ask Emacs. By hand, that is four steps, and doing it once is worth
more than reading about it:

#+begin_example
  mkdir -p /tmp/fix && cd /tmp/fix
  cp -R "$BABBLE/lit" lit          # $BABBLE is your checkout
  # write the fixture's book here as b.org
  emacs -Q --batch -l lit/tangle.el --eval '(lit-tangle "b.org")'
#+end_example

What lands beside b.org is the golden, byte for byte, and it is
the same command lit.mk runs for a real book. Copy it into the
fixture yourself. A golden must never be taken from what babble
produced: it would agree with babble by construction and prove
nothing. Doing this by hand is what the stage that mints goldens
from the oracle will replace.

** Adding a fixture

Start from the behavior, not from the file. A fixture earns its
place by pinning something that could plausibly break, and the
book's own guide is a good quarry: the worked examples in
[[#writing-a-book][Writing a book for babble]] are written to be lifted.

Then, in order:

1. Write the fixture book. Keep it to the smallest thing that
   shows the behavior, and give the blocks targets that say what
   they are for, greet.go rather than a.go.
2. Mint the goldens with Emacs, by hand as above. Read what comes
   out. A golden accepted without reading is a test that pins
   whatever the code did on the day it was written.
   Each golden goes in the txtar under ~want/~, at the path it
   pins: the golden for ~sub/late.go~ is ~want/sub/late.go~.
   Reminting depends on that, since it has to write each file back
   without guessing which golden belongs to which target.
3. Write the script. Name the command, then compare each expected
   file, then assert what should not exist. A fixture that only
   checks what was produced will not notice a file that should not
   have been.
4. Add the comment at the top saying what the fixture pins, in one
   or two sentences. It is the first thing a reader sees when the
   fixture fails.
5. If the fixture pins a deviation, say so in an oracle skip line
   with the reason. Emacs does not refuse what babble refuses, so
   a cross-check would fail on a difference that is the point.
6. Add it to the table above, with a few words on what it pins.
   A test compares that table against the directory, so a fixture
   added and not listed fails the suite.
7. Run the suite twice: once plain, once with the oracle. The
   first proves the goldens match what babble does, the second
   proves they match what Emacs does. Only the pair is evidence.

* Testing
:PROPERTIES:
:CUSTOM_ID: testing
:END:

Two layers hold babble to the oracle. The golden suite checks
every fixture against its committed goldens and needs no
Emacs, so it is what an ordinary run does; the oracle run replays
each fixture through batch Emacs as well and diffs the bytes the
two engines produce. Both layers run the fixtures the previous chapter described, through
testscript, the script-driven test runner from go-internal.

One word from that chapter carries the weight here, and it is
golden. The name is a promise about where the bytes came from:
goldens are minted from Emacs and never typed by hand. That is what
makes a passing suite evidence rather than agreement with myself,
and it is the reason reminting reads the Emacs tree and refuses to
read babble's.

The oracle harness ties every fixture to Emacs's own output. Under
ORACLE=1 each fixture's files are written into two directories,
batch Emacs with lit/tangle.el runs in one and babble in the other,
and the harness compares everything the two runs left behind. A
file one engine wrote and the other did not is a failure, and so is
the same path with different bytes.

The books it runs are the ones the fixture's own script tangles.
Half the fixtures tangle more than one and one tangles none, so
reading them from the script is the only way to know which. A
refusal is written with ~! exec~ rather than ~exec~ and is left out
by the same rule, since a book babble is meant to refuse produces
nothing to compare against.

Two failures would otherwise pass. A run that tangled no blocks
leaves two empty directories, and two empty directories agree, so
the harness reads the count the driver prints and fails when the
total is zero. With ORACLE=1 set on a machine without Emacs, it
fails rather than skipping, because a skip here removes the
comparison without reporting that it is gone.

A book that cannot be compared is named in a skip line, followed by
the reason. A skip that names no book excuses the whole fixture.
Reminting goldens from the oracle is not part of this stage. A
golden is minted by hand, with the recipe below, until the stage
that mints them lands.

from the Emacs tree, never from babble's:

TestParseCorpora parses the books this repository carries and
checks each tree against the file it came from: one src block per

#+name: TestParseCorpora

func TestParseCorpora(t *testing.T) {
	for _, path := range []string{
		"../../BOOK.org",
		"../../lit/BOOK.org",
		"../../lit/example/BOOK.org",
	} {
		t.Run(path, func(t *testing.T) {
			d, err := org.Parse(path)
			if err != nil {
				t.Fatal(err)
			}
			want := countSrcBlocks(string(d.Source))
			got := 0
			d.Walk(func(n book.Node) bool {
				b, ok := n.(*book.SrcBlock)
				if !ok {
					return true
				}
				got++
				if b.Body.Start < b.Full.Start || b.Body.End > b.Full.End {
					t.Errorf("line %d: body %v outside the block %v", b.Line, b.Body, b.Full)
				}
				if b.BeginAt < b.Full.Start || b.AfterEnd > b.Full.End {
					t.Errorf("line %d: anchors outside the block %v", b.Line, b.Full)
				}
				return true
			})
			if got != want {
				t.Errorf("parsed %d src blocks, file opens %d", got, want)
			}
		})
	}
}

func TestResolveHeaders(t *testing.T) {
	const src = `
,#+property: header-args :comments org

,#+begin_src go
the file property reaches here
,#+end_src

,* Outer
:PROPERTIES:
:header-args: :tangle outer.go :noweb yes
:END:

,#+begin_src go
the drawer replaces the file property
,#+end_src

,** Inner
:PROPERTIES:
:header-args: :tangle inner.go
:END:

,#+begin_src go :padline no
its own line wins
,#+end_src
`
	blocks := srcBlocks(t, src)
	if len(blocks) != 3 {
		t.Fatalf("parsed %d blocks, want 3", len(blocks))
	}
	if got := blocks[0].Params; got.Comments != "org" || got.Tangle != "no" {
		t.Errorf("file property: %+v", got)
	}
	// A nearer drawer replaces a farther setting whole, so the file's
	// :comments does not survive into Outer.

	if got := blocks[2].Params; got.Tangle != "inner.go" || got.Noweb || got.Padline {
		t.Errorf("inner block: %+v", got)
	}
}

func srcBlocks(t *testing.T, src string) []*book.SrcBlock {
	t.Helper()
	d, err := org.ParseBytes([]byte(src), "b.org")
	if err != nil {
		t.Fatal(err)
	}
	if err := org.ResolveAll(d); err != nil {
		t.Fatal(err)
	}
	var out []*book.SrcBlock
	d.Walk(func(n book.Node) bool {
		if b, ok := n.(*book.SrcBlock); ok {
			out = append(out, b)
		}
		return true
	})
	return out
}

#+begin_src go :tangle internal/org/org_test.go
func countSrcBlocks(src string) int {
	n, inside := 0, ""
	for _, l := range strings.Split(src, "\n") {
		t := strings.ToLower(strings.TrimLeft(l, " \t"))
		if inside != "" {
			if strings.HasPrefix(t, "#+end_"+inside) {
				inside = ""
			}
			continue
		}
		if !strings.HasPrefix(t, "#+begin_") {
			continue
		}
		kind := strings.TrimPrefix(t, "#+begin_")
		if i := strings.IndexAny(kind, " \t"); i >= 0 {
			kind = kind[:i]
		}
		switch kind {
		case "src":
			n++
			inside = kind
		case "example", "export", "comment", "verse":
			inside = kind
		}
	}
	return n
}

TestSkipsIdenticalWrites pins the one place babble parts company
with the oracle on purpose. A target whose bytes already match is
not rewritten, so its timestamp survives and nothing downstream
rebuilds; a target whose bytes changed is written. The test sets
the timestamp back rather than sleeping, so it measures the write
and not the clock.

#+name: TestSkipsIdenticalWrites
#+begin_src go :tangle internal/tangle/tangle_test.go :comments org
func TestSkipsIdenticalWrites(t *testing.T) {
	dir := t.TempDir()
	book := filepath.Join(dir, "b.org")
	target := filepath.Join(dir, "x.go")
	write := func(body string) {
		src := "#+begin_src go :tangle x.go\n" + body + "\n#+end_src\n"
		if err := os.WriteFile(book, []byte(src), 0o644); err != nil {
			t.Fatal(err)
		}
		d, err := org.Parse(book)
		if err != nil {
			t.Fatal(err)
		}
		if err := org.ResolveAll(d); err != nil {
			t.Fatal(err)
		}
		if err := tangle.Run(d); err != nil {
			t.Fatal(err)
		}
	}
	write("package x")
	old := time.Now().Add(-time.Hour).Truncate(time.Second)
	if err := os.Chtimes(target, old, old); err != nil {
		t.Fatal(err)
	}
	write("package x")
	st, err := os.Stat(target)
	if err != nil {
		t.Fatal(err)
	}
	if !st.ModTime().Equal(old) {
		t.Errorf("rewrote a target whose bytes did not change")
	}
	write("package y")
	if st, err = os.Stat(target); err != nil {
		t.Fatal(err)
	} else if st.ModTime().Equal(old) {
		t.Errorf("did not write a target whose bytes changed")
	}
}

** The refresh tests

Two facts about the final newline cannot be pinned by a fixture,
because the txtar format the fixtures are written in ends every file
with a newline and there is no way to ask it for a file that lacks
one. They are the two halves of the same rule: saving a buffer
appends the newline, and the driver saves only a buffer it has modified.
A book with a dynamic block is always modified, even when the text
that replaces the interior is identical, because the interior is
deleted first. A book without one is never touched at all.

#+begin_src go :tangle internal/dblock/dblock_test.go
package dblock_test

import (
	"testing"

	"github.com/bilus/babble/internal/dblock"
	"github.com/bilus/babble/internal/org"
)

func refresh(t *testing.T, src string) (string, bool) {
	t.Helper()
	d, err := org.ParseBytes([]byte(src), "b.org")
	if err != nil {
		t.Fatal(err)
	}
	out, changed, err := dblock.Refresh(d, func(string) (string, error) {
		t.Fatal("no diff in these books, so no body should be asked for")
		return "", nil
	})
	if err != nil {
		t.Fatal(err)
	}
	return string(out), changed
}

func TestFinalNewlineFollowsTheSave(t *testing.T) {
	const withBlock = "#+begin: plan-toc\n#+end:\n\ntail with no newline"
	out, changed := refresh(t, withBlock)
	if !changed {
		t.Error("a book holding a dynamic block was reported unchanged")
	}
	if out[len(out)-1] != '\n' {
		t.Errorf("the refresh left the book without a final newline: %q", out)
	}

	const noBlock = "#+begin_src go :tangle no\nx\n#+end_src\n\ntail with no newline"
	out, changed = refresh(t, noBlock)
	if changed {
		t.Error("a book with no dynamic block was reported changed")
	}
	if out != noBlock {
		t.Errorf("the refresh touched a book with no dynamic block:\n got %q\nwant %q", out, noBlock)
	}
}

A fixture names the books it tangles in its own script, so the

A book the two engines cannot be compared on is named in a skip
line. The words after ~skip~ that end in ~.org~ name the excused

book excuses the whole fixture, which is how the two already

only a plain ~exec babble tangle~ names a book to compare, so the
books babble is expected to refuse are left out by the same rule

#+begin_src go :tangle internal/oracletest/oracletest.go :comments org
var (
	tangleLine = regexp.MustCompile(`(?m)^exec babble tangle (\S+)`)
	skipLine   = regexp.MustCompile(`(?m)^# oracle: skip (.*)$`)
)

// books returns the books a fixture's script tangles, and the ones
// its skip line excuses.
func books(script string) (run []string, excusedAll bool) {
	excused := map[string]bool{}
	for _, m := range skipLine.FindAllStringSubmatch(script, -1) {
		named := 0
		for _, word := range strings.Fields(m[1]) {
			if !strings.HasSuffix(word, ".org") {
				break
			}
			excused[word] = true
			named++
		}
		if named == 0 {
			excusedAll = true
		}
	}
	seen := map[string]bool{}
	for _, m := range tangleLine.FindAllStringSubmatch(script, -1) {
		if seen[m[1]] || excused[m[1]] {
			continue
		}
		seen[m[1]] = true
		run = append(run, m[1])
	}
	return run, excusedAll
}

		t.Fatal("ORACLE=1 is set and emacs is not on PATH; the cross-check cannot run")

two runs disagree: a file one wrote and the other did not, or the

#+begin_src go :tangle internal/oracletest/oracletest.go :comments org
func compareAdditions(t *testing.T, oracleDir, babbleDir string) {
	t.Helper()
	oracle := added(t, oracleDir)
	babbled := added(t, babbleDir)
	paths := map[string]bool{}
	for p := range oracle {
		paths[p] = true
	}
	for p := range babbled {
		paths[p] = true
	}
	var names []string
	for p := range paths {
		names = append(names, p)
	}
	sort.Strings(names)
	for _, p := range names {
		want, inOracle := oracle[p]
		got, inBabble := babbled[p]
		switch {
		case !inBabble:
			t.Errorf("%s: the oracle wrote it and babble did not", p)
		case !inOracle:
			t.Errorf("%s: babble wrote it and the oracle did not", p)
		case !bytes.Equal(want, got):
			t.Errorf("%s: the two engines disagree\n oracle: %q\n babble: %q", p, want, got)
		}
	}
}

// added is every file in the tree after a run, keyed by its path. It
// does not subtract the files the fixture supplied, on purpose: a
// book is one of those and a refresh rewrites it, so leaving them in
// is what puts the book's own bytes under the comparison.
func added(t *testing.T, dir string) map[string][]byte {
	t.Helper()
	out := map[string][]byte{}
	err := filepath.Walk(dir, func(path string, info os.FileInfo, err error) error {
		if err != nil || info.IsDir() {
			return err
		}
		rel, err := filepath.Rel(dir, path)
		if err != nil {
			return err
		}
		body, err := os.ReadFile(path)
		if err != nil {
			return err
		}
		out[filepath.ToSlash(rel)] = body
		return nil
	})
	if err != nil {
		t.Fatal(err)
	}
	return out
}

** [2026-08-22] Dynamic blocks

#+begin_quote
The book side closed. plan-toc and src-block-diff refresh
byte-identically to the driver, run for run, and babble now
refreshes and tangles this book into the same bytes batch Emacs
produces from it.

An interior is one newline more than the writer inserted. Org empties
a dynamic block by deleting the interior and then opening a line for
the writer to insert at, and that opened line's newline stays behind
whatever arrives, and that alone explains why plan-toc leaves a blank
line before its closer and src-block-diff does not.

A writer reads the book part-refreshed: every block above it already
rewritten, its own interior one empty line, every block below it
still stale. So one refresh is not a fixed point. plan-toc corrects
for the lines it is about to insert and for nothing else, and a
generated diff below it that grows leaves every site under that diff
short until the next run. babble is short in the same places, since
matching the driver is the point and being right where the driver is
wrong is a difference like any other.

Org finds dynamic blocks with a raw search that ignores block
structure and allows indentation, and closes them on a line the
keyword reader rejects. The closer takes org's rule, because the
disagreement decides which bytes get overwritten by a refresh, and following
the reader would have deleted text org kept. The opener disagreement
cannot be reconciled at all, so the parse asks both searches and
refuses a book where they differ. This book carried such a line
since stage 17, and every tangle since had silently tried to refresh
it.

Every pattern ported from the driver folds case, because Emacs folds
case and the driver never turns it off. A lowercase todo word in a
heading is a plan site and an uppercase opener opens a block, though
the writer's own name is matched as written: org pastes it onto a
function name, and a function name is case-sensitive.

The tangle flow moved into a package of its own that the command
line and the oracle harness both call. They had each kept a copy of
the order and the copies had drifted, so the cross-check was
measuring something ~babble tangle~ does not do.

** [2026-08-21] Noweb

#+begin_quote
A reference resolves to the block carrying its name, or to the
blocks sharing it as a ~:noweb-ref~, joined by each block's own
separator with the last one's dropped. The text before a reference
is repeated in front of every line it expands to, and that text is
what lies between the previous reference and this one on the same
line, never the whole line.

Three things the book said about org were wrong and are now measured
rather than assumed. Recursion is gated: a referenced block's own
references expand only if that block carries ~:noweb yes~, and
otherwise reach the file as text. A cycle does not hang Emacs; it
exhausts the recursion limit in about a second and writes nothing.
And a block that tangles nowhere is still a source.

Four references are refused. A miss, which org expands to nothing
and writes anyway. A cycle. A call reference, since parentheses
anywhere in a name make org evaluate. And a name differing only in
case, because org folds case when searching for a block's name and
babble does not, so the error names the near miss. Two more are
refused because org's answer is not stable: a name that matches a
heading's ~CUSTOM_ID~, which org answers with the whole subtree as
raw text, and a name that is both a block's name and a
~:noweb-ref~, where the answer depends on what org expanded before.
#+end_quote

** [2026-08-21] Org comments

#+begin_quote
A ~:comments org~ block tangles with its docstring attached the way
the driver attaches it. The extent runs from the nearest anchor
above the block, which is a headline's stars, a previous block's end
keyword, or the start of the file, and a block that tangles nowhere
is still an anchor. The docstring is everything after the last
~# doc~ marker, or the last paragraph when there is none. Wrapping
follows the shape of what it wraps rather than putting a marker on
every line: the marker sits at the shallowest indentation and each
line keeps what it had beyond that.

Two shapes are refused. A language whose prefix holds no marker
cannot carry a comment, and the driver does not refuse that, it dies
partway with the file unwritten. And a delimiter written at column
zero inside an example body is an anchor to org's backward text
search and not to a tree, so the two engines would disagree about
where an extent begins and both would write a file. That second
refusal was owed to a later stage, and doc comments are what make it
visible, so it came forward to the stage whose reason it is.
#+end_quote

** [2026-07-27 Mon] Header arguments, resolved through a closed table
