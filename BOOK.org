* Plan                                                                :plan:

The first chapter in the file, and a temporary one: it exists only
while work is in flight. One entry per stage; the LOGBOOK lines that
state changes leave behind are the in-flight ledger. When a stage
completes, its entry is deleted, ledger and all, and its Changes
draft moves, timestamped, to [[#changes][Changes]]. The plan is scaffolding;
the journal is the record.

Vocabulary, since this chapter sits before everything that
defines it. Tangling extracts a book's code blocks into source
files. The oracle is batch Emacs running the lit driver,
lit/tangle.el; babble must match it byte for byte, and the closing
whole-book comparison is the parity sweep. A hole is a typed stub
whose body only panics, tracked by name; the census is the grep
that lists every hole and every plan mark by its sigil, a marker
string steady-state prose never contains. A badge is the
fifteen-star marker headline the plan convention plants at a
change site. Fixture books are each test's miniature input book,
and goldens are their expected outputs, minted from Emacs. The
fence is the pass that rejects everything outside the subset.
Stage headings wear the todo keywords the #+todo line declares,
and the skeleton gate is where work stops for human review.

This plan builds the whole program, so the ladder is long: eleven
stages, of which the first is the skeleton gate and the last is the
parity sweep. Every stage after the skeleton lands with its tests in
the same commits and leaves the suite green. The oracle harness
arrives in stage 6, early enough that every later stage's fixtures
are cross-checked against Emacs from the day they are written; the
fixture books start from the worked examples in
[[#writing-a-book][Writing a book for babble]].

After the harness the ladder opens into a diamond: comments,
noweb (block inclusion by named reference), and dynamic blocks
(the book's generated views) are independent of one another, and
they close back together at the fence.

Claim: after this stage, ~babble tangle BOOK.org~ writes every
eligible block of a book without comments, noweb, or dynamic blocks
to its resolved target in document order, with the generated-file
banner, one blank line between blocks, parent directories on

Decided: (1) babble compares the final bytes, banner included, and
skips the write when they match, so an unchanged target keeps its
mtime. The oracle never skips: its identity check compares a
bannerless buffer against a bannered file, so it rewrites every
target on every run (checked during bootstrap: the mtimes bump). The
brief asks for the skip; bytes agree either way, so the oracle
harness, which compares bytes, is untouched. Listed under
[[#deviations][Deviations]]. (2) The body pipeline lands here in
the contract's order: drop one trailing newline, drop one comma
from each escaped line, remove the common indentation measured in
columns with tabs at eight, then trim. Noweb expansion slots into
the middle of it later, which is why the second dedent and the
final trim are written now rather than discovered then. (3) The
tangle command parses, resolves, and writes. Refreshing the
dynamic blocks belongs at the front of that sequence and arrives
with the stage that can refresh them, as a twin. (4) A block
asking for something a later stage owns, a doc comment or a noweb
reference, reaches that stage's hole and the panic names it; this
stage's fixtures stay inside what it claims.

** Census

An agent picking up the work starts from this census: two greps
that index every hole and every plan-markup line. The tangled
sources are authoritative for holes that ship. The book side works
because every kind of plan markup carries a sigil that no
steady-state text contains, so the second command below lists
every transition-layer line (markup that exists only while work is
in flight). Escaped spellings such as ~HOLE[(]~ keep the patterns
from matching themselves.

* Introduction

babble tangles lit books without Emacs. A lit book is one org
file that is the whole program: prose says why, code blocks tangle
into the sources, and two generated views (a plan index and a
diff) keep the in-book planning in step with the code. Org is
Emacs's plain-text outline format; lit is the convention and
toolchain, carried under lit/, that turns such a file into a book
like this one. Batch Emacs running org-babel (org's code-block
machinery) plus lit/tangle.el, the driver from here on, does the
tangling today. And it works. It is also four hundred megabytes of
editor waking up for over a second every time I tangle, on every
CI run and every fresh machine.

Literate programming is an idea Donald Knuth came up with in 1984,
and at a high level it goes like this: a program should be written
for humans first, computers second. You write an essay, actual
prose with a narrative flow, and embed the code inside it wherever
the explanation calls for it. A tool then extracts the code and
stitches it together into something a compiler can run
("tangling"), while another pass produces a nicely typeset
document for reading ("weaving").

The radical part is the ordering. Traditional code follows the
structure the machine needs: imports at the top, functions in
dependency order. Literate programming follows the structure your
thinking needs. You present ideas in whatever sequence makes the
argument clearest, and the tooling reorders everything behind the
scenes.

Books also plan inside themselves. Work in flight lives in a
temporary Plan chapter as stage entries; badges (marker headlines
of fifteen or more stars) stand at every site the work touches; a
planned twin (a rewrite kept beside the block it replaces) waits
for acceptance; and a generated index, plan-toc, lists every such
site. This book opens with exactly such a plan.

One constraint shapes everything here: the oracle.
~babble tangle BOOK.org~ must produce byte-identical results to
~emacs -Q --batch -l lit/tangle.el --eval '(lit-tangle "BOOK.org")'~,
the same tangled files, the same refreshed book. Why bytes?
Because a machine can check bytes. The suite carries an oracle
mode that runs every fixture through both engines and diffs the
trees, and an update mode that mints expected outputs from the
Emacs side only. So committed goldens are Emacs output by
construction.

This is a port of a narrow, documented subset, not of org-mode.
Where the books never rely on a behavior, babble prefers a loud
error to a faithful imitation; the [[#deviations][Deviations]] chapter is the
complete list. When the oracle and any description of it disagree,
this book included, the oracle wins.

babble is itself a lit book. This file is the program: the blocks
below tangle into the Go sources, tests included, and until babble
reaches parity, batch Emacs tangles it. Self-hosting is the finish
line: v1 is done when babble tangles its own book byte-identically.

* Writing a book for babble

:PROPERTIES:
:CUSTOM_ID: writing-a-book
:END:
This chapter is the tour: the org babble reads, one construct at a
time, each construct with an example. And the examples are load
bearing: every one of them is meant to reappear in the test suite
as a fixture book whose expected output batch Emacs mints, so what
this chapter promises, the oracle enforces. The precise
rules behind the tour live in [[#subset-contract][The subset contract]].

Org quoted inside the examples is comma-escaped (a comma before a
star or a ~#+~), which is org's own convention for quoting itself;
the section on escaping below explains it.

** A minimal book

A book is prose and code under headlines. Every src block that
names a target file tangles into it; everything else is yours. The
smallest useful book is one block:

#+begin_example
,#+title: a tiny book

,* Greeting

greet is the whole library.

,#+begin_src go :tangle greet.go
package greet
,#+end_src
#+end_example

Running ~babble tangle BOOK.org~ writes greet.go:

#+begin_example
// Code generated from BOOK.org by make tangle. DO NOT EDIT.

package greet
#+end_example

Every tangled file opens with that banner in the file's own comment
syntax (~//~ for .go, ~;;~ for .el, ~--~ for .lua, ~#~ for
everything else), then one blank line, then the code. A file ends
with exactly one newline. Tangling again without changing the book
rewrites nothing: the target's bytes already match, so its
timestamp survives and nothing downstream rebuilds.

** Choosing targets

~:tangle~ decides where a block lands. A path lands relative to the
book's directory, and parent directories appear on demand:

#+begin_example
,#+begin_src go :tangle internal/req/req.go
package req
,#+end_src
#+end_example

~:tangle no~ keeps a block in the book only, which is what you want
for illustrations and scratch work; a block with no ~:tangle~ at
all means the same thing. ~:tangle yes~ derives the target from
the book's name and the language, so in BOOK.org a go block lands
in BOOK.go. Tangling into the book itself is refused.

A block with no language is an error. Emacs would skip it without
a word, which is how a renamed language quietly empties a file;
babble names the line instead.

** How files assemble

Blocks reach a file in document order, whatever their targets do in
between, and consecutive blocks in the same file are separated by
exactly one blank line:

#+begin_example
,#+begin_src go :tangle greet.go
package greet
,#+end_src

,#+begin_src go :tangle other.go
package other
,#+end_src

,#+begin_src go :tangle greet.go
func greet(name string) string {
	return "Hello, " + name + "!"
}
,#+end_src
#+end_example

greet.go collects the first and third blocks with one blank line
between them; other.go gets the middle one. Trailing blank lines
inside a block body are dropped, so you cannot accidentally pad a
file's end.

** Keeping drafts out

A heading whose title starts with ~COMMENT~ takes its whole
subtree out of the tangle, children included. The ~:ARCHIVE:~ tag
does the same:

#+begin_example
,* COMMENT Scratchpad

,#+begin_src go :tangle greet.go
package wrong
,#+end_src

,* Old ideas                                                    :ARCHIVE:
#+end_example

Neither block above reaches a file. This is how a rejected draft
stays in the book without tangling: mark the heading, keep the
text.

** Doc comments

~:comments org~ turns the paragraph directly above a block into its
comment in the tangled file. Only the last paragraph is taken,
which keeps narrative and doc comment from repeating each other.

#+begin_example
,* Greeting

Callers pick the name; greet only decorates it.

greet returns its salute with the name spliced in.

,#+name: greet
,#+begin_src go :tangle greet.go :comments org
func greet(name string) string {
	return "Hello, " + name + "!"
}
,#+end_src
#+end_example

greet.go reads:

#+begin_example
// Code generated from BOOK.org by make tangle. DO NOT EDIT.

// greet returns its salute with the name spliced in.
func greet(name string) string {
	return "Hello, " + name + "!"
}
#+end_example

The first paragraph stayed in the book; the ~#+name:~ line never
leaks into the comment. When a docstring needs several paragraphs,
put an invisible ~# doc~ marker line where it starts:

#+begin_example
Greeting strings concatenate; there is no template engine here.

# doc
greet returns its salute with the name spliced in.

The exclamation point is part of the contract: tests pin it.

,#+begin_src go :tangle greet.go :comments org
func greet(name string) string {
	return "Hello, " + name + "!"
}
,#+end_src
#+end_example

Everything after the marker becomes the comment, blank lines
preserved as bare ~//~ lines.

A paragraph opening with ~Note:~ or ~Apropos:~ is an aside: the
weave styles it, and the tangle drops the sigil and keeps the
text, so the aside lands in the source as an ordinary comment.

Doc comments work for go, python, emacs-lisp, sh, and makefile
blocks; any other language under ~:comments org~ is an error,
because without a mode for the language, batch Emacs keeps the
previous block's comment syntax.

** Splitting code with noweb

With ~:noweb yes~, a block can pull named blocks into itself with
~<<name>>~ references, which is how a long function becomes a
skeleton of named regions:

#+begin_example
,#+begin_src go :tangle greet.go :comments org :noweb yes
func main() {
	<<print-greetings>>
}
,#+end_src

,#+name: print-greetings
,#+begin_src go
fmt.Println(greet("you"))
fmt.Println(greet("me"))
,#+end_src
#+end_example

The tangled main carries both lines, and the tab before
~<<print-greetings>>~ is replicated in front of every expanded
line, so indentation survives:

#+begin_example
func main() {
	fmt.Println(greet("you"))
	fmt.Println(greet("me"))
}
#+end_example

When no single block carries the name, the reference collects
every block whose ~:noweb-ref~ equals it, in document order, each
followed by its own ~:noweb-sep~ (a newline unless you say
otherwise). Expansion is recursive: a referenced block may itself
reference further blocks. A reference nothing defines is an error,
and so is a cycle; Emacs would silently expand the first to
nothing and hang on the second.

** Header arguments at large

Org defines some thirty header arguments; a tangler needs eight of
them. babble sorts every header key on every block into three
bins. Implemented: ~:tangle~, ~:mkdirp~, ~:comments~,
~:padline~ (the blank line between blocks in a target), ~:noweb~,
~:noweb-ref~, ~:noweb-sep~, and the ~-i~ switch that preserves
indentation. Inert: the evaluation-only
arguments such as ~:results~ and ~:exports~, accepted and ignored
because they cannot change a tangled byte. Everything else is an
error that names the key, which among other things catches typos:

#+begin_example
,#+begin_src go :tangel greet.go
package greet
,#+end_src
#+end_example

Emacs reads ~:tangel~ as an unknown key and ignores it, and the
block silently stops tangling. babble refuses the book until the
key is spelled right.

Headers can be set once and inherited. A property drawer under a
heading applies to every block in its subtree, nearest setting
winning:

#+begin_example
,* Engine
:PROPERTIES:
:header-args: :comments org
:END:
#+end_example

** The plan convention

lit books plan changes inside themselves, and babble has to
recognize what that leaves in the text. A change in flight lives
in a temporary Plan chapter at the front of the book, and it marks
the book three ways. A twin is a planned replacement for a live
block: a sibling block, named after the original plus a planned
marker, that sits inert until accepted. A badge is a marker
headline of fifteen or more stars before a change site, pointing a
reviewer at it. And each kind of markup carries a sigil (a
spelling ordinary text never contains), so one grep, the census,
indexes the whole in-flight layer. babble's own part is small:
badge lines parse as plain headlines, and the two dynamic blocks
below render the plan's jump list and a twin's diff.

** Dynamic blocks

Two generated views live in books, and tangling refreshes both
before any code moves, so committed generated content cannot
disagree with the blocks it describes. Hand edits inside them are
lost: the next refresh rewrites the interior wholesale. Dynamic
blocks start in column zero, and only these two names exist; an
unknown name is an error.

plan-toc renders a jump list of every plan-markup site in the
book, one line-number link per site:

#+begin_example
,#+begin: plan-toc
,#+end:
#+end_example

src-block-diff renders a unified diff of two named blocks' bodies,
which is how a twin shows its delta next to the original:

#+begin_example
,#+begin: src-block-diff :old greet :new greet-quiet
,#+end:
#+end_example

Both names must exist as ~#+name:~'d blocks.

** Quoting org inside a block

Org has one rule for putting org inside org: escape a line that
starts with a star or ~#+~ by putting a comma in front, and the
tangle strips one comma back off. Headlines are the reason the
rule exists at all: a bare star line ends every block it appears
in, no matter how deeply quoted it looks.

#+begin_example
,#+begin_src org :tangle no
,,* A quoted heading, safely inert
,,#+begin_src go
,,#+end_src
,#+end_src
#+end_example

One comma per nesting level. An unescaped block delimiter inside
an example, src, export, or comment body is refused outright: the
Emacs driver's raw text searches would anchor doc-comment extents
on it, and a parser working from the tree cannot reproduce that.

** When babble says no

Everything outside src and dynamic blocks is yours: keywords,
drawers, tables, footnotes, links, timestamps pass through
untouched, because babble rewrites the book only by splicing fresh
dynamic-block interiors into the bytes it read. The refusals all
sit on the tangling path; the complete list, with what Emacs would
have done instead, is [[#deviations][Deviations]]. A book that
tangles at all tangles to the same bytes Emacs produces; a book
that would not is refused before any file changes.

* The subset contract

:PROPERTIES:
:CUSTOM_ID: subset-contract
:END:
What ~babble tangle~ does, in order: refresh every dynamic block in
the book, rewriting the book file only when its bytes changed, then
tangle every eligible src block into its target file. The
subsections here state the contract each stage implements; the
chapters that own the code carry the mechanics.

** Recognition

A tangle candidate is a src block that has a language. Recognition
follows org's element grammar: delimiter keywords are
case-insensitive, only whitespace may follow ~#+end_src~ on its
line, affiliated ~#+name:~ lines belong to the block below them, and
blocks inside example, export, comment, and quote blocks are text,
not blocks. A src block without a language is an error
(org's scanner cannot even see one, which is worse). A src block
that never closes is an error (org reads it as a paragraph).

** Collection

Walk src-block nodes in document order. A block under a COMMENT
heading or an ARCHIVE-tagged heading is skipped, with keyword and
tag inheritance down the subtree, and a badge line is a headline
like any other, because batch Emacs never loads org-inlinetask,
which would read it as an inline task instead. A block whose
~:tangle~ resolves to ~no~ is skipped. Blocks group by resolved target file, groups ordered by
first appearance, blocks within a group in document order.

** Targets

~:tangle~ takes ~no~, ~yes~, or a path. A path resolves relative to
the book's directory; ~yes~ derives the target from the book's name
plus the language's extension. ~:mkdirp~ (default yes, set by the
driver) creates parent directories. Tangling into the book itself
is an error. A target whose final bytes, banner included, already
sit on disk is not rewritten, so its mtime survives.

** Header arguments

Effective headers merge in org's order: babel defaults (with the
driver's mkdirp), language defaults, inherited ~header-args~ and
~header-args:LANG~ properties (nearest ancestor wins, the
accumulating ~+~ forms rejected), then the block's own header line,
later entries winning. The header line splits on space-then-colon
outside balanced parentheses, brackets, and double quotes. A value
is a string; a quoted value is read with elisp string escapes; a
value org would evaluate as lisp is rejected.

The header surface is closed. Every key on every src block,
tangling or not, must sit in a fixed table with three bins:
implemented (~:tangle~, ~:mkdirp~, ~:comments~, ~:padline~,
~:noweb~, ~:noweb-ref~, ~:noweb-sep~, the ~-i~ switch), rejected
(the [[#deviations][Deviations]] list), and inert, the evaluation-only keys
(~:results~, ~:exports~, ~:session~, ~:cache~, ~:eval~ and kin)
that org parses but its tangle path never reads. A key outside the
table is an error. The bins are exhaustive against the oracle
because the union of parameter lookups on org's tangle code path
(collection, block assembly, noweb expansion, the write loop) is
exactly the implemented set plus the rejected set; a key that path
never reads cannot change a byte, so the inert bin rests on proof.
The table applies to non-tangling blocks too: a misspelled
~:tangle~ leaves the block looking like a deliberate illustration,
and only the unknown-key error can tell the difference. A
non-tangling block carrying ~:results output~ passes, because
inert keys are accepted everywhere.

** The body pipeline

The body is the raw text between the delimiter lines, minus exactly
one trailing newline. Comma-escaped lines (a comma before ~*~ or
~#+~, possibly indented) drop one comma. Common indentation,
measured in columns with tab width eight, is removed unless the
block carries the ~-i~ switch. Noweb expansion runs when enabled,
indentation is removed once more, and a final trim drops leading
and trailing blank lines, so trailing blanks never reach a target.

** Assembly

Each target file is its blocks in document order, exactly one blank
line between consecutive blocks (org's padline), a single final
newline at end of file. The first line is the generated-file
banner, ~Code generated from BOOK.org by make tangle. DO NOT
EDIT.~, in the file's own comment syntax: ~//~ for .go, ~;;~ for
.el, ~--~ for .lua, ~#~ for everything else, followed by one blank
line.

** Org comments

Under ~:comments org~, the text between a block and the structure
above it becomes its doc comment. The extent runs from whichever is
nearest above: just past the stars and single space of the closest
headline, or just past the literal end_src of the previous block,
or offset zero, down to the start of the block's begin line, so an
affiliated name line sits inside the extent. The driver's docstring
rule then applies: everything after the last ~# doc~ marker line if
one is present, else the last paragraph; ~#+~ keyword lines drop; a
leading ~Note:~ or ~Apropos:~ sigil drops. The result wraps in the
block language's line-comment syntax, blank lines becoming a bare
comment marker with no trailing space, and a docstring that is all
whitespace inserts nothing.

The anchors need an example. Two commented blocks under one
heading:

#+begin_example
,* Loading

Load reads the set.

,#+begin_src go :tangle a.go :comments org
func Load() {}
,#+end_src

,#+begin_src go :tangle a.go :comments org
func Save() {}
,#+end_src
#+end_example

Load's extent starts after the heading's stars and runs to its
begin line, so it holds the title and the paragraph; the
last-paragraph rule picks ~Load reads the set.~ and the title
stays behind. Save's extent starts after the previous block's
literal end_src and holds only blank lines, so Save tangles with
no comment at all. Delete the paragraph, though, and the title
itself becomes Load's comment: the extent still ends somewhere,
and the docstring rule takes the last paragraph it finds there.

** Noweb

Under ~:noweb yes~, a reference ~<<name>>~ on its own or with text
before it resolves to the named block's body, or, when no block
carries the name, to the document-order concatenation of every
block whose ~:noweb-ref~ equals it, each followed by its own
~:noweb-sep~ (default newline) except the last. The reference is
single-line and its name neither starts nor ends with whitespace.
Text before the reference on its line is replicated in front of
every expansion line. Expansion is recursive. Blocks under COMMENT
headings do not participate. An unresolvable reference and a
reference cycle are errors; org would expand the first to nothing
and recurse forever on the second.

** Dynamic blocks

~#+begin: NAME args~ dispatches on NAME; a refresh deletes the
interior wholesale and rewrites it, so hand edits do not survive
and a second refresh is byte-identical to the first. Dynamic
blocks are recognized at column zero, and the writer set is closed
by dispatch: two names exist, and an unknown name is an error.
src-block-diff takes ~:old~ and ~:new~ block names, runs the
system ~diff -u~ over their bodies, drops the two temp-file header
lines, and wraps the rest in a src diff block, or writes the words
~no differences~. plan-toc writes one line per plan-markup site (a
site is any line carrying plan markup: a stage heading, a badge
line of fifteen or more stars, a hole string, a CriticMarkup edit,
a twin name, or a generated diff), labels spelled without the
sigils, as line-number links, with sites below the block shifted
by the number of lines the writer is about to insert. babble never
renders org; the book file is rewritten by splicing fresh
interiors into the retained bytes, so every construct outside a
dynamic-block interior, understood or not, survives byte-for-byte
by construction.

* Deviations

:PROPERTIES:
:CUSTOM_ID: deviations
:END:
Places where babble departs from what org would do: refusals,
each a loud error instead of an imitation, plus one byte-neutral
difference in when files are written. The refusals are the fence.
No refusal may fire on the reqsync book or the lit example book,
and a test enforces that. The error message always names the
construct and the supported alternative.

- Lisp-valued header arguments (a value starting with a parenthesis,
  quote, backquote, or bracket) are rejected; org evaluates them.
- A src block without a language is an error; org's tangle scanner
  silently ignores the block.
- A src block that never closes is an error; org parses it as a
  paragraph.
- ~#+header:~ affiliated keywords are rejected; org merges them
  into the header with a precedence the books never use.
- An unresolvable noweb reference is an error; org expands it to
  the empty string for most languages. A noweb cycle is an error;
  org recurses without bound. A noweb call reference,
  ~<<name(args)>>~, is evaluation and is rejected.
- Noweb and named-block resolution is case-sensitive; a reference
  that only resolves under org's case folding is an error naming
  the near-miss.
- A duplicate ~#+name:~ across src blocks is an error, as is a name
  that some block also uses as a ~:noweb-ref~ value; org would
  resolve both by whichever its scan finds first.
- The header table is closed: a key babble does not know is an
  error, so org's option space cannot leak in unclassified. Within
  the table, the rejected keys error by name: ~:comments~ values
  other than ~no~ and ~org~, ~:var~, ~:shebang~, ~:tangle-mode~,
  ~:no-expand~, ~:noweb~ values other than ~yes~ and ~no~,
  ~:noweb-prefix~, ~:prologue~, ~:epilogue~, ~:dir~ in its attach
  form (org's attachment-directory feature), the ~-r~ and ~-l~
  coderef switches (org's code-reference labels), accumulating
  ~header-args+~ properties, inline src blocks (code blocks inside
  a prose line), and ~#+include~ (org's file-inclusion keyword).
  The inert keys (evaluation-only arguments such as ~:results~ and
  ~:exports~, and the ~-n~ and ~-k~ switches) pass through because
  the oracle's tangle path never reads them; an oracle fixture
  holds a tangled block carrying them all and proves the bytes do
  not move.
- ~:comments org~ is limited to languages whose comment syntax the
  batch-Emacs driver actually has: go, python, emacs-lisp, sh,
  makefile. In batch Emacs a missing language mode silently leaves the
  previous block's mode active, so comment syntax would leak from
  an earlier block; that order-dependence stays out of the subset.
- Block and dynamic-block delimiters quoted verbatim inside
  example, src, export, or comment block bodies are a lint error:
  org's raw backward searches would anchor comment extents on them,
  and no structural parser can agree with that.
- A dynamic block with an unknown name is an error; org empties
  its interior and logs a message it then ignores. An indented
  dynamic block is an error; org re-indents its interior, padding
  blank lines with trailing spaces. Dynamic-block arguments beyond keyword and name tokens
  are rejected; org hands them to the lisp reader.
- Unchanged targets are not rewritten, so their mtimes survive a
  tangle; the oracle rewrites every target every run because its
  identity check compares a bannerless buffer to the bannered file
  on disk. The book file likewise is written only when its bytes
  changed; the oracle saves it after every dynamic-block refresh.
  Bytes are identical in all four cases; only mtimes differ.

* Architecture

babble parses first: the whole book becomes a logical tree, and
the tangler and the dynamic-block writers decide everything
against that tree, never by re-scanning text. The oracle works the
same way. org-babel's scan loop uses its block regex only to find
candidates; every hit must be confirmed by the element parser, and
everything babel then reads (language, name, switches, headers,
body, position) comes from the element, not from the regex
captures. The element grammar is the authority for recognition and
attributes, and the tree is babble's spelling of the same
authority.

The document model is the tree plus the retained source bytes plus
a line index. Every node carries its line number, which plan-toc
links point at, and its byte span, which extents and dynamic-block
splicing slice. The census that plan-toc renders is defined by the
lit convention on raw lines, not on structure, so babble runs the
patterns ported from tangle.el over retained source lines and the
tree supplies only the splice points.

Org spellings stop at ~internal/org~. The frontend knows org
syntax, scanning, spans, the balanced header splitter, the value
reader, and nothing past it does. ~internal/book~ is the tree the
engine consumes, free of org spellings, which is the seam a future
markdown frontend would plug into. ~internal/tangle~ owns
collection, targets, the body pipeline, comments, noweb, banners,
and assembly; ~internal/dblock~ owns refresh and the two writers.
The dependency arrows all point one way, and the tree is the waist:

#+begin_src mermaid
graph LR
  book[BOOK.org] --> org["internal/org<br/>recognition, spans, headers"]
  org -->|"org spellings stop here"| tree["internal/book<br/>the logical tree"]
  tree --> tangle["internal/tangle<br/>collect, noweb, comments, assemble"]
  tree --> dblock["internal/dblock<br/>refresh, plan-toc, src-block-diff"]
  tangle --> files[tangled sources]
  dblock --> book2[BOOK.org rewritten]
#+end_src

The scan regex has exactly three observable effects of its own,
and each has a home here. First, it demands a language token, so a
languageless block never tangles: babble makes that an error.
Second, the ~:comments org~ extent is anchored on raw match
positions, so the tree records them: per headline, the offset just
past the stars and following space; per block, the offset where the
begin line starts and the offset just past the literal end_src.
Third, org's backward anchor search does not element-confirm, so a
delimiter quoted inside a verbatim body would anchor extents in
Emacs but never in a tree; the quoted-delimiter lint forbids the
shape, so the divergence never reaches an accepted book.

Two facts keep the port small. Batch Emacs loads no language packs,
so org's language-specific expansion hooks never exist and body
expansion is the generic path, which is the identity when nothing
injects variables; babble expands nothing. And the driver pins the
whole comment story to five language modes, so comment wrapping is
a table, not a port of Emacs's comment machinery.

* The command line

babble is two subcommands over one book: ~tangle~ writes the
sources, ~parse~ shows the tree. main is only the wiring, streams
in and exit code out, so the tests can drive run the way a shell
drives main. Exit codes follow convention: 2 for usage errors, 1
for failures.

babble tangles lit books without Emacs. This file is tangled from
BOOK.org.

#+begin_src go :tangle main.go :comments org
func run(args []string, stdout, stderr io.Writer) int {
	if len(args) < 1 {
		fmt.Fprint(stderr, usage)
		return 2
	}
	switch args[0] {
	case "parse":
		fs := flag.NewFlagSet("parse", flag.ContinueOnError)
		fs.SetOutput(stderr)
		dump := fs.Bool("dump", false, "print the tree as JSON")
		if err := fs.Parse(args[1:]); err != nil {
			return 2
		}
		if fs.NArg() != 1 {
			fmt.Fprint(stderr, usage)
			return 2
		}
		d, err := org.Parse(fs.Arg(0))
		if err == nil {
			err = org.ResolveAll(d)
		}
		if err != nil {
			fmt.Fprintln(stderr, "babble:", err)
			return 1
		}
		if *dump {
			out, err := book.Dump(d)
			if err != nil {
				fmt.Fprintln(stderr, "babble:", err)
				return 1
			}
			if _, err := stdout.Write(out); err != nil {
				return 1
			}
		}
		return 0
	case "tangle":
		if len(args) != 2 {
			fmt.Fprint(stderr, usage)
			return 2
		}
		return tangleCmd(args[1], stderr)
	}
	fmt.Fprint(stderr, usage)
	return 2
}

#+begin_src go :tangle internal/book/book.go
func walk(nodes []Node, fn func(Node) bool) {
	for _, n := range nodes {
		if !fn(n) {
			continue
		}
		switch n := n.(type) {
		case *Headline:
			walk(n.Children, fn)
		case *DynamicBlock:
			walk(n.Children, fn)
		case *QuoteBlock:
			walk(n.Children, fn)
		}
	}
}
#+end_src

LineAt is total: any int is a valid argument, offsets before the
source count as its start and offsets past it as its end, so no
caller can turn a bad offset into a panic.

#+begin_src go :tangle internal/book/book.go :comments org
func (d *Document) LineAt(off int) int {
	if off < 0 {
		off = 0
	}
	if off > len(d.Source) {
		off = len(d.Source)
	}
	return 1 + bytes.Count(d.Source[:off], []byte("\n"))
}

	out, err := json.MarshalIndent(v, "", " ")
	if err != nil {
		return nil, err
	}
	return append(out, '\n'), nil
}

Each node type carries its own JSON tags, so the dump never
restates a field list. One wrapper adds what tags cannot: the type
discriminator in front and the wrapped children behind. A leaf is
the same wrapper with no children, which is why there is one type
here and not two.

The wrapper marshals itself because Go cannot flatten a field into
its enclosing object: an embedded type parameter is illegal and an
embedded interface marshals under its own key, so a typed wrapper
that keeps the flat shape has to splice the node's object itself.
Marshaling the children here rather than at construction lets an
unknown node type surface as an error instead of a null.

func (d dumped) MarshalJSON() ([]byte, error) {
	body, err := json.Marshal(d.node)
	if err != nil {
		return nil, err
	}

		return nil, fmt.Errorf("dump: %s node marshaled as %s, want an object", d.kind, body)
	}
	var b bytes.Buffer
	fmt.Fprintf(&b, `{"type":%q`, d.kind)
	if inner := body[1 : len(body)-1]; len(inner) > 0 {
		b.WriteByte(',')
		b.Write(inner)

		kids, err := dumpNodes(d.children)
		if err != nil {
			return nil, err
		}
		raw, err := json.Marshal(kids)
		if err != nil {
			return nil, err
		}
		b.WriteString(`,"children":`)
		b.Write(raw)
	}
	b.WriteByte('}')
	return b.Bytes(), nil
}

#+begin_src go :tangle internal/book/book.go
func dumpNodes(nodes []Node) ([]json.Marshaler, error) {
	out := make([]json.Marshaler, 0, len(nodes))
	for _, n := range nodes {
		m, err := dumpNode(n)
		if err != nil {
			return nil, err
		}
		out = append(out, m)
	}
	return out, nil
}

func dumpNode(n Node) (json.Marshaler, error) {
	switch n := n.(type) {
	case *Headline:
		return dumped{"headline", n, n.Children}, nil
	case *Prose:
		return dumped{"prose", n, nil}, nil
	case *Keyword:
		return dumped{"keyword", n, nil}, nil
	case *SrcBlock:
		return dumped{"src", n, nil}, nil
	case *DynamicBlock:
		return dumped{"dynamic", n, n.Children}, nil
	case *QuoteBlock:
		return dumped{"quote", n, n.Children}, nil
	case *VerbatimBlock:
		return dumped{"verbatim", n, nil}, nil

* How the oracle parses

:PROPERTIES:
:CUSTOM_ID: how-the-oracle-parses
:END:
The specification for babble's frontend is not the org manual, it
is org-element.el. This chapter states the algorithm that file
implements, because babble replicates it: same shape, same
decisions, same order, in Go types. Line numbers below are org
9.7.11, the version the oracle runs, and the syntax those parsers
implement is written up separately at
https://orgmode.org/worg/dev/org-syntax.html. Everything here is
this book's own account of what that code does; none of its text
is reproduced, since org is GPL and babble is not.

The first thing to know is that org has no tokenizer. There is no
token stream between the buffer and the parser. The parser looks
at raw text at the moment it needs to decide something, which is
why a construct's meaning can depend on where it sits.

** The loop

:PROPERTIES:
:CUSTOM_ID: the-loop
:END:
~org-element--parse-elements~ (org-element.el:5192) walks a byte
range and does three things per element: ask what starts here,
jump to where that element says it ends, and, when the element can
contain other elements, recurse into its interior. The range is
the parser's bound, and it is the reason a block cannot swallow
the heading below it: a section's elements are parsed between the
section's own start and end.

#+begin_src mermaid
flowchart TD
  start([parse range beg..end]) --> ask["current-element:<br/>what starts at point?"]
  ask --> el["element with begin, end,<br/>contents-begin, contents-end"]
  el --> jump["point = element end"]
  jump --> greater{"greater<br/>element?"}
  greater -->|yes| rec["recurse into<br/>contents range"]
  greater -->|no| more{"point < end?"}
  rec --> more
  more -->|yes| ask
  more -->|no| done([return elements])
#+end_src

** The dispatch

:PROPERTIES:
:CUSTOM_ID: the-dispatch
:END:
~org-element--current-element~ (org-element.el:4637) decides an
element's type from the start of one line, in a fixed order.
Context comes first: when the caller passed a mode saying "we are
inside a list item" or "inside a property drawer", that mode wins
before any text is examined. Then a star run means a headline.
Then one bulk regexp (~org-element--current-element-re~, 4616)
matches drawers, fixed-width lines, dynamic-block openers,
~#+begin_X~, ~#+CALL:~, plain keywords, footnote definitions,
horizontal rules and diary sexps in a single pass, and the code
dispatches on which numbered group matched. What is left over is a
table or a paragraph.

The single regexp is an optimization, and the source explains it:
the parsers follow house rules about never disturbing Emacs's
global match data, grouping regexps so one call replaces several,
and precomputing patterns instead of building them per line, all
because repeated matching dominated the profile on large buffers.
babble inherits the decision but not the technique. Its dispatcher
tests line prefixes rather than matching regexps, so there is no
match state to protect and nothing to gain by fusing the tests;
the branches stay separate, which is what lets the dispatch table
read as a table.

For ~#+begin_X~ the block name picks the parser: CENTER, COMMENT,
EXAMPLE, EXPORT, QUOTE, SRC and VERSE have their own, and any
other name is a special block. That list is the whole reason
babble splits verbatim blocks from greater blocks.

The order is the specification, because the first branch that
matches wins and several of them can match the same line. Here it
is as the elisp reads it, with the branches babble's subset never
reaches marked. babble's ~currentElement~ answers these questions
in this order, which is what makes the two comparable at all.

| # | branch | condition | subset |
|---|---|---|---|
| 1 | item | mode is item | no |
| 2 | table row | mode is table-row | no |
| 3 | node property | mode is node-property | yes |
| 4 | headline | stars, then a space | yes |
| 5 | section | mode is a section mode | implicit |
| 6 | comment | an org comment line | as prose |
| 7 | planning | mode is planning | no |
| 8 | property drawer | mode admits one | yes |
| 9 | paragraph | point past a line start | no |
| 10 | clock | a clock line | no |
| 11 | inlinetask | deep stars, feature loaded | no |
| 12 | affiliated | a name line, then retry | yes |
| 13 | bulk regexp | nine shapes in one match | four |
| 14 | table | a leading pipe | no |
| 15 | paragraph | everything left | yes |

Branch 13 is the one that carries most of org's syntax. Its nine
shapes are drawers, fixed-width lines, dynamic-block openers,
~#+begin_X~, ~#+CALL:~, keywords, footnote definitions,
horizontal rules and diary sexps, and babble reaches four of them:
the dynamic-block opener, ~#+begin_X~, keywords, and the drawer
shape that branch 8 consumes.

Two other entries are worth reading twice. Branch 11 is why a
fifteen-star badge is an ordinary headline here: batch Emacs never
loads org-inlinetask, so the condition is false and control falls
to branch 4, which is what babble does unconditionally. Branch 7 is
a difference babble carries: org admits a planning line between a
headline and its property drawer, and babble does not, so a drawer
below a planning line is prose here and its properties are lost.

** Elements find their own end

Every element parser receives the bound and searches for its own
terminator inside it. ~org-element-src-block-parser~
(org-element.el:2990) looks for a line matching ~#+END_SRC~ with
nothing after it, and when the search fails it does not raise an
error: it calls the paragraph parser instead, and the opening line
becomes ordinary text. babble refuses that case instead, which is
one of the [[#deviations][Deviations]].

Paragraphs are the subtle ones (org-element.el:2854). A paragraph
ends at the next line that cannot be inside it, but each candidate
is verified before it counts: a drawer line only ends the
paragraph if a matching ~:END:~ exists ahead, and a ~#+BEGIN_X~
only ends it if a matching ~#+END_X~ exists, with X captured from
the opener and quoted into a fresh search. Deciding where prose
stops therefore requires proving that a pair matches, somewhere
below.

** Greater, lesser, and mode

Two properties of an element type steer the loop. Whether it is a
greater element decides whether the parser recurses into it:
headlines, sections, quote blocks, centre blocks, special blocks,
items, tables and footnote definitions hold elements, while src,
example, export, comment and verse blocks hold text. And the mode
an element hands to its successor decides how the next line is
read: after a headline the mode admits a planning line and then a
property drawer, inside a list the mode makes each line an item,
inside a property drawer each line is a node property.

Mode is why the same three characters parse differently in two
places. ~:END:~ closes a drawer in one position and is prose in
another, and no amount of looking at the line itself will tell you
which.

One rule about greater elements is worth stating because babble's
block parsers depend on it: apart from headlines and list items, a
greater element cannot contain another of its own type. That is
why searching forward for the first matching terminator is correct
rather than merely convenient, and why a quote block inside a
quote block closes the outer one.

** Affiliated keywords

~org-element--collect-affiliated-keywords~ (org-element.el:4843)
runs before the element parser and attaches ~#+name:~,
~#+caption:~ and their kin to the element below them. The element
then carries two positions: ~:begin~, at the first affiliated
keyword, and ~:post-affiliated~, at the element's own first line.
The tangler uses the second, which is why babble records the
begin-line offset separately from the block's full extent.

** What babble takes, and what it leaves

babble replicates the element layer: the loop, the dispatch, the
per-element terminator search, greater against lesser, mode, and
affiliated keywords. It leaves three things behind. The object
layer, ~org-element--object-lex~ (org-element.el:5261), which
tokenizes inline markup inside paragraphs, is unnecessary because
nothing in a tangle looks inside prose. The element cache exists
for interactive editing. And granularity, which lets a caller stop
the recursion early, has one setting here: parse everything.

The naming follows the oracle deliberately. Org calls its parsers
~org-element-TYPE-parser~, so babble calls its own TYPEParser, and
the two correspond function for function, which is what makes a
divergence findable rather than merely suspected. Org also
records what adding an element type costs: write its parser, teach
the dispatcher to recognize it, and list the type. babble's price
is the same three, an element parser, a branch in the table, and a
node type, which is the shape the remaining stages pay each time
they widen the subset.

them. A verbatim block leaves both empty, so the loop cannot
recurse into text that must stay text. Properties ride here too,
because a drawer is an element in org's model but a field of the
headline in ours.

parseElements is the loop from [[#the-loop][The loop]]: identify what starts
here, recurse when it holds elements, jump to its end, repeat. The
bound matters twice over. Elements are parsed within it, and a
non-headline element gets the tighter bound of the next headline,
which is org's section, and the reason a block cannot reach past
a heading to find its terminator.

#+begin_src go :tangle internal/org/org.go :comments org
func (p *parser) parseElements(beg, end int, m mode) ([]book.Node, error) {
	var out []book.Node
	for off := beg; off < end; {
		p.off = off
		text, _ := p.line(off)
		limit := end
		if starRun(text) == 0 {
			limit = p.nextHeadline(off, end, anyLevel)
		}
		el, next, err := p.currentElement(limit, m)
		if err != nil {
			return nil, err
		}
		if el.node != nil {
			if el.adopt != nil && el.contents.End > el.contents.Start {
				kids, err := p.parseElements(el.contents.Start, el.contents.End, el.childMode)
				if err != nil {
					return nil, err
				}
				el.adopt(kids)
			}
			out = append(out, el.node)
		}
		off = next
		m = modeSection
	}
	return out, nil
}
#+end_src

currentElement is the dispatcher, and its order is the table in
[[#the-dispatch][The dispatch]]: the mode branch, then a star run, then the
affiliated name line, then the block delimiters, then the keyword
shape, then a paragraph for everything left. The first branch that
matches wins, which is why the order is the contract and not a
detail.

#+begin_src go :tangle internal/org/org.go :comments org
func (p *parser) currentElement(limit int, m mode) (parsed, int, error) {
	start := p.off
	text, next := p.line(start)
	if starRun(text) > 0 {
		return p.headlineParser(text, next, limit)
	}
	if m == modePropertyDrawer {
		if props, after, ok := p.propertyDrawerParser(start, limit); ok {
			return parsed{props: props}, after, nil
		}
	}
	aff := affiliated{begin: start}
	if key, value, ok := keywordLine(text); ok && key == kwName && next < limit {
		if t2, n2 := p.line(next); opensBlock(t2) {
			aff.name = value
			p.off, text, next = next, t2, n2
		}
	}
	if name, rest, _, ok := blockDelim(text, "begin"); ok {
		switch name {
		case "src":
			return p.srcBlockParser(rest, next, limit, aff)
		case "example", "export", "comment", "verse":
			return p.verbatimBlockParser(name, next, limit, aff)
		default:
			return p.greaterBlockParser(name, next, limit, aff)
		}
	}
	if key, value, ok := keywordLine(text); ok {
		if key == kwBegin {
			return p.dynamicBlockParser(value, next, limit, aff)
		}
		return p.keywordParser(key, value, text, next)
	}
	return p.paragraphParser(limit)
}

const anyLevel = 1 << 30

func opensBlock(text string) bool {
	if _, _, _, ok := blockDelim(text, "begin"); ok {
		return true
	}
	key, _, ok := keywordLine(text)
	return ok && key == kwBegin
}

func startsElement(text string) bool {
	if starRun(text) > 0 || opensBlock(text) {
		return true
	}
	_, _, ok := keywordLine(text)
	return ok
}

func (p *parser) nextHeadline(from, limit, maxLevel int) int {
	for off := from; off < limit; {
		text, next := p.line(off)
		if lvl := starRun(text); lvl > 0 && lvl <= maxLevel {
			return off
		}
		off = next
	}
	return limit
}

func (p *parser) findEnd(from, limit int, closes func(string) bool) (int, string, bool) {
	for off := from; off < limit; {
		text, next := p.line(off)
		if closes(text) {
			return off, text, true
		}
		off = next
	}
	return 0, "", false
}

the other before handing the rest of the range to the loop.

#+begin_src go :tangle internal/org/org.go :comments org
func (p *parser) headlineParser(text string, next, limit int) (parsed, int, error) {
	off := p.off
	stars := starRun(text)
	h := &book.Headline{Level: stars, Line: p.lineNum(off),
		AfterStars: off + stars + 1,
		Head:       book.Span{Start: off, End: off + len(text)}}
	rest := strings.TrimLeft(text[stars+1:], " \t")
	if w, r, ok := firstWord(rest); ok && p.todo[w] {
		h.Todo = w
		rest = r
	}
	if len(rest) >= 4 && strings.HasPrefix(rest, "[#") && rest[3] == ']' {
		rest = strings.TrimLeft(rest[4:], " \t")
	}
	if rest == "COMMENT" || strings.HasPrefix(rest, "COMMENT ") {
		h.Commented = true
		rest = strings.TrimLeft(strings.TrimPrefix(rest, "COMMENT"), " \t")
	}
	rest, h.Tags = splitTags(rest)
	h.Title = strings.TrimSpace(rest)
	for _, tag := range h.Tags {
		if tag == "ARCHIVE" {
			h.Archived = true
		}
	}
	end := p.nextHeadline(next, limit, stars)
	contents := next
	if after, ok := p.planningLine(next, end); ok {
		contents = after
	}
	p.off = contents
	if el, after, err := p.currentElement(end, modePropertyDrawer); err == nil && el.props != nil {
		h.Properties = el.props
		contents = after
	}
	return parsed{node: h, contents: book.Span{Start: contents, End: end},
		adopt:     func(kids []book.Node) { h.Children = kids },
		childMode: modeSection}, end, nil
}

A planning line carries the timestamps a heading schedules itself
with. Nothing in a tangle reads them, but they have to be stepped
over, because org lets one stand between a heading and the drawer
whose properties the blocks below inherit.

func (p *parser) planningLine(from, limit int) (int, bool) {
	if from >= limit {
		return from, false
	}
	text, next := p.line(from)
	head := strings.TrimLeft(text, " \t")
	for _, kw := range []string{"SCHEDULED:", "DEADLINE:", "CLOSED:"} {

			return next, true
		}
	}
	return from, false
}

plus the four org extras. Anything that fails the shape stays in
the title, so the first line below has two tags and the second has

  ** Ship it                              :release:tools:
  ** Ship it: a story in two parts

#+begin_src go :tangle internal/org/org.go :comments org
func splitTags(s string) (string, []string) {
	t := strings.TrimRight(s, " \t")
	if !strings.HasSuffix(t, ":") {
		return s, nil
	}
	i := strings.LastIndexAny(t, " \t")
	cand := t[i+1:]
	if len(cand) < 2 || cand[0] != ':' {
		return s, nil
	}
	parts := strings.Split(cand[1:len(cand)-1], ":")
	for _, p := range parts {
		if p == "" || !tagWord(p) {
			return s, nil
		}
	}
	return t[:i+1], parts
}

func tagWord(s string) bool {
	for _, c := range s {
		switch {
		case c >= 'a' && c <= 'z', c >= 'A' && c <= 'Z',

The shape tests below are the only place a line's spelling is
examined, and every one of them is a pure function of the line
plus a position. They are read at the point of decision, never
ahead of time, which is what stops a lexical phase from deciding
grammar. Each answers one question about one line, in the order
below: how many stars open it, whether it is a block delimiter,
whether it is a keyword line, and whether it is a colon line.
#+begin_example
  ** Ship it
  #+begin_src go
  #+end_src
  #+title: babble
  :header-args: :comments org
#+end_example

#+begin_src go :tangle internal/org/org.go :comments org
func starRun(text string) int {
	i := 0
	for i < len(text) && text[i] == '*' {
		i++
	}
	if i > 0 && i < len(text) && text[i] == ' ' {
		return i
	}
	return 0
}

func blockDelim(text, word string) (name, rest string, after int, ok bool) {
	i := 0
	for i < len(text) && (text[i] == ' ' || text[i] == '\t') {
		i++
	}
	prefix := "#+" + word + "_"
	if len(text) < i+len(prefix) || !strings.EqualFold(text[i:i+len(prefix)], prefix) {
		return "", "", 0, false
	}
	j := i + len(prefix)
	k := j
	for k < len(text) && text[k] != ' ' && text[k] != '\t' {
		k++
	}
	if k == j {
		return "", "", 0, false
	}
	return strings.ToLower(text[j:k]), strings.TrimSpace(text[k:]), k, true
}

func keywordLine(text string) (key, value string, ok bool) {
	t := strings.TrimLeft(text, " \t")
	if !strings.HasPrefix(t, "#+") {
		return "", "", false
	}
	rest := t[2:]
	i := strings.IndexByte(rest, ':')
	if i <= 0 {
		return "", "", false
	}
	for _, c := range rest[:i] {
		switch {
		case c >= 'a' && c <= 'z', c >= 'A' && c <= 'Z',
			c >= '0' && c <= '9', c == '_', c == '-':
		default:
			return "", "", false
		}
	}
	return strings.ToLower(rest[:i]), strings.TrimSpace(rest[i+1:]), true
}

func colonLine(text string) (key, value string, ok bool) {
	t := strings.TrimSpace(text)
	if len(t) < 3 || t[0] != ':' {
		return "", "", false
	}
	j := strings.IndexByte(t[1:], ':')
	if j <= 0 || strings.ContainsAny(t[1:1+j], " \t") {
		return "", "", false
	}
	return t[1 : 1+j], strings.TrimSpace(t[2+j:]), true
}

func todoWords(src []byte) []string {

			case kwTodo, kwSeqTodo, kwTypTodo:

					}
					if f != "" {

					}
				}
			}
		}
		off = next
	}

		words = []string{"TODO", "DONE"}

The =begin_src= line splits three ways: the language, then a run of

grammar, since org accepts exactly -i, -k, -r, -n and +n with an
optional count, and -l with a quoted format. Whatever follows the
run is the header string, which stays raw until it is resolved. In
the tail below the language is go, the switch run is "-i", and the
header begins at the first colon:

  go -i :tangle greet.go :comments org

#+begin_src go :tangle internal/org/org.go :comments org
func srcHeader(s string) (lang, switches, header string) {
	rest := strings.TrimLeft(s, " \t")
	lang, rest = cutWord(rest)
	run := rest
	taken := 0
	for {
		w, after := cutWord(rest)
		switch w {
		case "":
			return lang, strings.TrimSpace(run[:taken]), ""
		case "-i", "-k", "-r":
		case "-n", "+n":
			if n, a := cutWord(after); isNumber(n) {
				after = a
			}
		case "-l":
			if q, a, ok := cutQuoted(after); ok {
				_ = q
				after = a
			} else {
				return lang, strings.TrimSpace(run[:taken]), strings.TrimSpace(rest)
			}
		default:
			return lang, strings.TrimSpace(run[:taken]), strings.TrimSpace(rest)
		}
		rest = after
		taken = len(run) - len(rest)
	}
}

#+begin_src go :tangle internal/org/org.go
func cutWord(s string) (word, rest string) {
	s = strings.TrimLeft(s, " \t")
	if i := strings.IndexAny(s, " \t"); i >= 0 {
		return s[:i], s[i:]
	}
	return s, ""
}

func cutQuoted(s string) (quoted, rest string, ok bool) {
	t := strings.TrimLeft(s, " \t")
	if !strings.HasPrefix(t, `"`) {
		return "", s, false
	}
	if i := strings.IndexByte(t[1:], '"'); i >= 0 {
		return t[1 : 1+i], t[i+2:], true
	}
	return "", s, false
}

func isNumber(s string) bool {
	if s == "" {
		return false
	}
	for _, c := range s {
		if c < '0' || c > '9' {
			return false
		}
	}
	return true
}

Inheritance is nearest-wins, and wholesale. Org reads an inherited
property with org-entry-get, which returns the closest ancestor's
value and stops, so a nearer drawer replaces a farther one
entirely rather than adding to it; a key the nearer one omits is
not inherited from further up. The scope below therefore carries
one generic value and one per language, each overwritten as the
walk descends.

#+begin_src go :tangle internal/org/org.go :comments org
type scope struct {
	generic string            // header-args
	lang    map[string]string // header-args:LANG
}

func (s scope) with(props map[string]string) (scope, error) {
	out := scope{generic: s.generic, lang: s.lang}
	for k, v := range props {
		if strings.HasSuffix(k, "+") {
			return out, fmt.Errorf("accumulating property %s is not in the subset; set the whole value", k)
		}
		if k == "header-args" {
			out.generic = v
			continue
		}
		if l, ok := strings.CutPrefix(k, "header-args:"); ok {
			next := map[string]string{}
			for key, val := range out.lang {
				next[key] = val
			}
			next[l] = v
			out.lang = next
		}
	}
	return out, nil
}

#+begin_src go :tangle internal/org/org.go :comments org
func balancedSplit(s string) []string {
	var out []string
	start, depth, quoted := 0, 0, false
	for i := 0; i < len(s); i++ {
		switch c := s[i]; {
		case quoted:
			if c == '\\' {
				i++
			} else if c == '"' {
				quoted = false
			}
		case c == '"':
			quoted = true
		case c == '(' || c == '[':
			depth++
		case c == ')' || c == ']':
			if depth > 0 {
				depth--
			}
		case c == ':' && depth == 0 && i > 0 && (s[i-1] == ' ' || s[i-1] == '\t'):
			out = append(out, strings.TrimSpace(s[start:i]))
			start = i
		}
	}
	if last := strings.TrimSpace(s[start:]); last != "" {
		out = append(out, last)
	}
	if len(out) > 0 && out[0] == "" {
		out = out[1:]
	}
	return out
}

#+begin_src go :tangle internal/org/org.go
func unquote(v string) (string, error) {
	if len(v) < 2 || v[len(v)-1] != '"' {
		return "", fmt.Errorf("unterminated string in header argument %s", v)
	}
	var b strings.Builder
	for i := 1; i < len(v)-1; i++ {
		if v[i] != '\\' {
			b.WriteByte(v[i])
			continue
		}
		i++
		if i >= len(v)-1 {
			return "", fmt.Errorf("trailing escape in header argument %s", v)
		}
		switch v[i] {
		case 'n':
			b.WriteByte('\n')
		case 't':
			b.WriteByte('\t')
		default:

* Testing

Two layers hold babble to the oracle: a pure fixture suite that
runs anywhere, and an oracle mode that replays every fixture
through batch Emacs and diffs the bytes. The suite is testscript,
the script-driven test runner from go-internal, running txtar
fixtures (one text file bundling a book plus its expected outputs)
in testdata/script; the script runs ~babble tangle~ or
~babble parse --dump~ and compares every expected file, the book
itself included when dynamic blocks are in play. The fixtures are
data files outside this book, hand-started and machine-reminted,
like the dependency manifests. Their books start from the worked
examples in [[#writing-a-book][Writing a book for babble]], so what the guide shows
is what the suite pins.

The oracle harness ties every fixture to Emacs's own output.
Under ORACLE=1, each fixture's inputs are extracted twice; batch Emacs
with lit/tangle.el runs in one tree and babble in the other, and
any byte difference between the trees fails the test. Under
UPDATE=1, the harness rewrites each fixture's expected outputs from
the Emacs tree, never from babble's, so a committed golden cannot
encode babble's own misunderstanding. Fixtures that pin babble's
deliberate deviations (error paths, the mtime-preserving skip) are
marked to run without the oracle, since the oracle disagrees with
them by design.

#+begin_src go :tangle internal/org/org_test.go
func countSrcBlocks(src string) int {
	n, inside := 0, ""
	for _, l := range strings.Split(src, "\n") {
		t := strings.ToLower(strings.TrimLeft(l, " \t"))
		if inside != "" {
			if strings.HasPrefix(t, "#+end_"+inside) {
				inside = ""
			}
			continue
		}
		if !strings.HasPrefix(t, "#+begin_") {
			continue
		}
		kind := strings.TrimPrefix(t, "#+begin_")
		if i := strings.IndexAny(kind, " \t"); i >= 0 {
			kind = kind[:i]
		}
		switch kind {
		case "src":
			n++
			inside = kind
		case "example", "export", "comment", "verse":
			inside = kind
		}
	}
	return n
}

* Changes

:PROPERTIES:
:CUSTOM_ID: changes
:END:
A journal, newest first: one entry per completed plan stage,
covering the problem it addressed or the capability it changed, the
decisions that shaped it, and the delta at the level a reader of
this document cares about. Entries are written once, at acceptance,
and never reworded; history that needs correcting gets a new entry.
An entry speaks from its date; the rest of the document speaks from
no date at all.

** [2026-07-27 Mon] Header arguments, resolved through a closed table

Header arguments resolve the way the oracle merges them: the
driver's defaults, then the nearest inherited property, then the
block's own line. Inheritance is wholesale, since org reads an
inherited property by taking the closest ancestor's value and
stopping, so a nearer drawer replaces a farther one entirely
rather than adding to it. Every key is looked up in a closed
table: the ones babble acts on land in the block's parameters, the
evaluation-only ones are accepted and dropped because the tangle
path never reads them, the excluded ones refuse by name, and a key
the table does not know stops the tangle rather than being
guessed at. A planning line no longer hides the drawer beneath it,
which had cost a heading its inherited headers.

** [2026-07-27 Mon] Blocks, parsed the way the oracle parses

Blocks joined the tree with the byte anchors the comment extents
later hang from, and parsing both real corpora became a test. An
unterminated block, which org silently reads as a paragraph, is an
error here. The frontend that finds them is a port of the oracle's
own algorithm: a bounded loop, a dispatcher that reads a line
where it stands, element parsers that find their own ends, and a
mode passed from parent to child. An earlier attempt put a line
tokenizer in front of the parser, which moved grammar into the
lexical phase and computed one stage's anchor on behalf of
another; reading the source at the point of decision removes both
problems and matches the oracle's own shape, which is what makes
byte parity arguable rather than lucky.

** [2026-07-27 Mon] The document tree

babble parse --dump arrived: headlines, keywords, and prose runs
parse into a spanned tree, pinned by testscript fixtures. Badge
lines parse as the deep headlines batch Emacs sees, not as inline
tasks.

** [2026-07-27 Mon] The skeleton

The whole shape of babble landed as a typed skeleton tangled from
