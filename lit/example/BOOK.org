* From title to address

slug turns post titles into URL addresses. Most of the work is
throwing things away: punctuation, case, everything past the cap,
without shipping half a word. And two titles can reduce to the
same slug, while an address is only an address if it is unique.

This file is the program: the blocks below tangle into slug.py,
the paragraph above a block is its doc comment, and ~python3 -m
doctest slug.py~ is the suite. ~make tangle~ regenerates slug.py;
~make check~ tangles into a scratch directory and diffs. The
Makefile is one hand-written line, ~include lit/lit.mk~; ~lit~ here
is a symlink to the parent toolchain, standing in for the copy of
lit/ a real project carries, and .gitignore is hand-managed too.

slugify keeps the alphanumeric runs and hyphenates the gaps; a run
of junk is one gap, not several, and the ends come out clean.

#+begin_src python :tangle slug.py :comments org
def slugify(title):
    kept = "".join(c if c.isalnum() else " " for c in title.lower())
    return "-".join(kept.split())
#+end_src

truncate cuts at the last hyphen inside the limit, never mid-word;
a single run longer than the limit takes the hard cut.

#+begin_src python :tangle slug.py :comments org
def truncate(slug, limit):
    if len(slug) <= limit:
        return slug
    cut = slug.rfind("-", 0, limit + 1)
    return slug[:cut] if cut > 0 else slug[:limit]
#+end_src

** [2026-07-22 Wed] Truncation stops splitting words

truncate cut at the raw limit, so a cap landing mid-word shipped
fragments: "quiet-brown-fox" at nine came out "quiet-bro". The cut
moved back to the last hyphen inside the limit, the hard cut
surviving only for a single run longer than the cap.

** [2026-07-18 Sat] Separator runs collapse

slugify gave every rejected character its own hyphen, and titles
like "C++ & Go" slugged to rows of dashes reading like redactions.
Rejected characters became spaces and the join collapsed the runs:
one hyphen per gap, none at the ends.
