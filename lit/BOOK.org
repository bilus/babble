* Introduction

A program and its explanation drift apart because they live in
different files. The code moves with every commit; the document
moves when someone remembers it exists. Every project accepts some
version of this drift, and every project pays for it.

lit removes the second file. A project using lit keeps its source
code and its narrative in one org document called the book, named
BOOK.org by convention. The book reads as a paper: chapters, prose,
diagrams, and code listings in an order chosen for the reader.
Two operations connect it to the working program. Tangling extracts
every code listing into ordinary source files, and weaving renders
the whole book as a PDF. The prose cannot drift from the code
because deleting the prose would delete the program.

This document is the lit toolchain's own book. The scripts that
tangle and weave every other book are tangled from this one, so the
toolchain is proof of its own method. The chapters go from the
outside in: first what the system promises, then the programs it
stands on, then the flows, then each script in full.

* The contract

These are the requirements. Everything after this chapter is
implementation.

** One source of truth

The book is the program. Every generated file opens with a banner
comment, "Code generated from BOOK.org by make tangle. DO NOT
EDIT.", in the comment syntax of its own language. A hand edit to a
generated file is always a mistake; the next tangle silently
reverses it. Files the book does not generate, dependency
manifests, the one-line Makefile, .gitignore, README files, are
hand-managed and never touched by the toolchain.

** Tangling

A code block in the book names a target, the file it lands in.
Tangling writes every target from its blocks, in the order the
blocks appear in the book, separated by exactly one blank line,
with a final newline at the end of the file. Parent directories are
created as needed. A target whose new content is byte-identical to
what is on disk is not rewritten, so timestamps survive and build
tools stay calm.

The paragraph directly above a code block is that block's
docstring. It tangles into the source file as a comment above the
code, so the explanation a reader sees in the book is the comment a
maintainer sees in the file. A paragraph that begins with "Note: "
or "Apropos: " is an aside; the sigil is presentation and is
stripped on the way into the source. When a docstring needs several
paragraphs, an invisible marker line in the book separates
narrative from docstring; the rules live in AGENTS.md next to this
file.

Comment syntax follows the language a block is written in, not the
extension of the file it lands in, so one table answers both the
banner and the doc comment. A project adds a language the toolchain
does not know, or overrides one it does, through
~.lit/comments.json~ beside its book: an object of language to
line-comment prefix, whose entries win over the built-in table. A
file fed by blocks of two languages is an error, since one file
takes one comment syntax.

A book that has outgrown one file is split into chapter files, and a
master file includes them in reading order. Two spellings are
understood and no others. ~#+INCLUDE: "path"~ brings a chapter into
the book, and ~#+INCLUDE: "path" example~ shows a file's text in the
PDF without making it part of the book. Two programs read a book,
org and pandoc, and each understands a different set of extensions
to that keyword; the forms both read the same way are the only ones
that can mean one thing. The quotes are part of the rule rather than
a convention: org accepts an unquoted path and pandoc ignores it
without a word, so an unquoted include would tangle correctly and
weave a book with a chapter missing.

The two forms differ in what reads them. A chapter is expanded by
both halves, because it can hold blocks and prose that the rest of
the book depends on. A file shown as an example holds neither, being
verbatim text wherever it lands, so only the weave has any use for
it and the tangler leaves the line alone. This is what lets a book
show a test fixture, or any other file it does not own, on the page
without that file becoming part of the program.

Both halves of the toolchain expand the includes before they do
anything else, so a split book and a whole one produce the same
bytes. This is a requirement rather than an optimisation. Blocks
reach a file in the order they appear across the whole book, and a
doc comment's extent runs back to the nearest structure above the
block, which may be in the chapter before it. An engine that read
chapters one at a time would not see either, and would write
different files from the same book.

Books may also hold generated views: blocks whose content is
derived from the rest of the book, such as a diff between a block
and its planned replacement, or a jump list of every planned
change. Tangling refreshes all of them before extracting code, so a
committed view can never disagree with the book that contains it.

** Weaving

Weaving produces book.pdf, a paper-like rendering of the book. The
PDF must carry a table of contents, syntax-highlighted code, and
three affordances that make the code navigable:

- Every block that tangles gets a numbered caption, "Listing N:",
  naming its target file, the way figures are captioned in a paper.
- A named block shows its name in the caption, spelled ~<<name>>~,
  the same spelling a reference uses.
- A named region block, one that reaches a file only by being
  referenced from another block, is captioned with the file it
  lands in, resolved through the references. A named block that
  neither tangles nor is referenced, a planned twin for instance,
  stays uncaptioned.
- A reference to a named block inside another listing is a
  hyperlink; clicking it jumps to the named block's caption.

A block can ask for the other rendering. Written
~:noweb yes inline~, its references are replaced in the listing by
the code they name, so a reader sees the assembled block rather
than a link to follow. The reference is still the right default,
since it tells the reader the code is composed and where each part
lives, and this is for the short helper where following a link
costs more than reading the lines would.

The extra word rides on org's own header, and org ignores it. That
header is read by splitting its value on whitespace and looking for
a word org knows, so ~yes~ decides what tangling does and ~inline~
is carried past every reader but this one. A book marked this way
tangles the same under Emacs, under babble, and under an org that
has never heard of the word. The word means nothing on its own:
~:noweb inline~ is a value org does not recognise, which it treats
as ~no~, leaving the references in the tangled file with nothing to
say why.

Only a reference to a named block is inlined. One answered by a
group of blocks sharing a ~:noweb-ref~ stays a link, since inlining
it would mean reproducing the rules that join a group, and a reader
who follows the link to a group is not badly served. What is inlined
is what tangling produces, the repeated prefix included, so the
listing shows the bytes the file gets.

A custom id identifies a heading across the whole book, so two
headings may not claim the same one. After the includes are expanded
the chapters are a single document with a single set of anchors, and
a repeated id makes every link to it ambiguous, with no way for
either engine to tell which heading was meant. The check runs while
the chapter files are being read, because that is the last moment
the file and line of the second definition are known. Once the text
is merged, a position refers to a line in text that exists in no
file, which is of no use to the person who has to fix it.

A link to a heading in another chapter names both a file and a
custom id, which is the form Emacs stores. Weaving resolves it to
the id alone. The merged document has no separate files left to
point at, and a link naming an org file would sit in the PDF
pointing at something that is not beside it.

Diagrams written in mermaid, a plain-text diagram language, render
as pictures. Note and Apropos asides render as indented quotations.
Prose links to named blocks become internal PDF links.

** Plans render in place

A book can carry its own change plan: a temporary Plan chapter,
marked paragraphs at every site a change touches, and proposed
replacements beside the code they replace. The authoring rules are
AGENTS.md's business, not this book's. The toolchain's obligation
is rendering: the weave must show badges as colored ruled boxes
with margin marks, insertions in green and deletions in red, a
"Plan sites" branch in the PDF outline, a sticky-note annotation
per badge, and a jump list whose entries link to their badges. A
book with no plan in flight weaves as a plain book, and make review
is the same weave under the name the review gate uses.

** Checking

make check proves the book and the tree agree: it tangles the book
into a scratch directory and compares the result against the
working tree, byte for byte, recursively. Hand-managed files are
excluded from the comparison; everything else must match. A
consumer can extend the exclusion list through the ~CHECK_EXTRA~
variable without editing the toolchain.

** Starting a project

make setup bootstraps a fresh project: it copies a starter book
from the templates directory, go or python by autodetection
(TARGET= forces the choice), writes the one-line Makefile when none
exists, refuses to overwrite an existing book, and runs the first
tangle. The example directory holds a complete toy book that
doubles as the toolchain's smoke test.

** Self-hosting

This book tangles the toolchain: the make targets and the six
scripts below. Running make inside lit/ regenerates them; running
make check inside lit/ proves this book and the scripts agree. The
committed driver runs the tangle that regenerates the driver, which
is circular only at first glance: the running copy is already in
memory when its file is rewritten.

* The programs

lit writes none of its own parsers or typesetters. It stands on six
programs, each doing the one thing it is best at.

Emacs with org-babel does the tangling. org-babel is the reference
implementation of org's literate features, and batch Emacs, started
with a blank configuration, runs it headless and reproducibly. The
driver script tangle.el configures it and adds what lit needs.

Pandoc converts the book to LaTeX. Pandoc reads org natively and
accepts filters, small Lua programs that rewrite the document tree
between reading and writing. lit's three filters run inside pandoc,
so they need no separate Lua installation.

Tectonic compiles the LaTeX to PDF. It is a self-contained XeTeX
engine that downloads the packages a document needs on first use,
so there is no TeX distribution to install or maintain.

Python 3 runs the two rewriters that bracket pandoc: one prepares
the org before pandoc sees it, one repairs the LaTeX after pandoc
writes it.

mmdc, the mermaid command-line compiler, turns mermaid diagram
source into PDF images at weave time. Without it, diagrams degrade
to source listings and the weave still completes.

make and diff are the glue: make sequences the steps, diff powers
both the byte-identity check and the generated diff views.

* The flows

** Tangling

#+begin_src mermaid
flowchart LR
  B[BOOK.org] --> E[batch Emacs + tangle.el]
  E --> R[refresh generated views]
  R --> B
  E --> S[source files, banner stamped]
#+end_src

make tangle starts batch Emacs, loads tangle.el, and calls its
entry point on the book. The driver first refreshes every generated
view and saves the book if any changed, then extracts all code
blocks. Two hooks run on every written file: one normalizes blank
comment lines, one stamps the banner.

** Weaving

#+begin_src mermaid
flowchart LR
  B[BOOK.org] --> P[preprocess.py]
  P --> W[book-weave.org]
  W --> PD[pandoc + three filters]
  PD --> T[book-weave.tex]
  T --> X[texlinks.py]
  X --> TC[tectonic]
  TC --> PDF[book.pdf]
#+end_src

make weave is a pipeline of five steps. preprocess.py rewrites plan
markup into org pandoc understands and injects the LaTeX preamble.
Pandoc converts that org to LaTeX, running the four filters in
order: mermaid.lua renders diagrams, svg.lua converts hand-drawn
figures, notes.lua handles captions, references, and asides,
plan.lua styles the plan. texlinks.py then
rewrites reference placeholders in the LaTeX into hyperlinks, and
tectonic compiles the result. The intermediate files are removed
whether the weave succeeds or fails.

** Checking

make check needs no diagram: copy the book and the toolchain into a
scratch directory, tangle there, and diff the scratch tree against
the working tree with the hand-managed files excluded. The output
is either "ok" or the first disagreement.

* The make targets

Everything a consumer touches is a make target, and all the targets
live in one file, lit.mk. A consuming project's Makefile is a
single line, "include lit/lit.mk". The LIT variable names the
directory the toolchain lives in; it defaults to lit, and this
directory's own Makefile points it at "." so the same targets work
here.

Four hook targets sit around tangling and weaving: before_tangle,
after_tangle, before_weave and after_weave. They are empty here, and
a project fills the ones it needs by writing a rule for the same
name in its own Makefile. The work a hook does is the work that
belongs to the project rather than to the toolchain. Tangling a Go
book writes go files and cannot write go.sum, since only the Go
tools know what the imports resolve to, so an after_tangle hook that
runs go mod tidy leaves the project buildable in one step:

#+begin_example
include lit/lit.mk

after_tangle::
	go mod tidy
#+end_example

The double colon is what makes that work. A rule written with one
colon replaces any earlier rule for the same target, so a project
Makefile would silently take the place of the empty definition and
make would warn about it. Rules written with two colons add to each
other and run in the order they were read, so a project can add a
hook without knowing whether the toolchain or another include
already did.

Tangling is a target of its own, tangle_el, with tangle standing for
the three steps in order. Weaving is arranged the same way around
book.pdf. A hook that fails stops the run, since make stops at the
first failing prerequisite, which is what you want from a check
placed in before_tangle.

#+name: lit-mk-targets
#+begin_src makefile :tangle lit.mk
LIT ?= lit

# Every file the book is made of, so editing a chapter rebuilds the
# PDF. The preprocessor answers, rather than a pattern here, because
# it is what decides which lines are includes.
BOOK_PARTS := $(shell python3 $(LIT)/preprocess.py --deps BOOK.org)

.PHONY: tangle weave review check setup \
  before_tangle after_tangle before_weave after_weave tangle_el

# Hooks a project can define in its own Makefile to run something
# before or after a tangle or a weave. Each is declared with a double
# colon, so a project adds its own rule for the same name instead of
# overriding this empty one.
before_tangle::
after_tangle::
before_weave::
after_weave::

tangle_el:
	emacs -Q --batch -l $(LIT)/tangle.el --eval '(lit-tangle "BOOK.org")'

tangle: before_tangle tangle_el after_tangle

weave: before_weave book.pdf after_weave

book.pdf: $(BOOK_PARTS) $(LIT)/preprocess.py $(LIT)/plan.lua $(LIT)/notes.lua $(LIT)/mermaid.lua $(LIT)/svg.lua $(LIT)/texlinks.py
	python3 $(LIT)/preprocess.py BOOK.org book-weave.org
	t=$$(mktemp -d) && MERMAID_TMP=$$t pandoc book-weave.org -s --toc \
	  --lua-filter=$(LIT)/mermaid.lua --lua-filter=$(LIT)/svg.lua \
	  --lua-filter=$(LIT)/notes.lua \
	  --lua-filter=$(LIT)/plan.lua -V colorlinks -V linkcolor=NavyBlue \
	  -o book-weave.tex && \
	  python3 $(LIT)/texlinks.py book-weave.tex && \
	  tectonic book-weave.tex && \
	  mv book-weave.pdf book.pdf; rc=$$?; \
	  rm -rf "$$t" book-weave.org book-weave.tex book-weave.pdf; exit $$rc

review: weave
#+end_src

The PDF depends on every file the book is made of, not on the master
alone, so editing a chapter rebuilds it. The list is asked for
rather than matched for: the preprocessor decides which lines are
includes and which of the two forms they are, and a second reader
written as a pattern here would eventually disagree with it. The
question is asked while make is reading this file, before any target
has been chosen, which is why the answer never fails; a book that
cannot be read is refused later, by the tangler and by the weave.

setup bootstraps a new project, as the contract describes. It never
overwrites an existing book, and it writes the one-line Makefile
only when the project has none.

#+name: lit-mk-setup
#+begin_src makefile :tangle lit.mk
setup:
	@test ! -f BOOK.org || { echo "BOOK.org already exists"; exit 1; }
	@t="$(TARGET)"; \
	if [ -z "$$t" ]; then \
	  if [ -f go.mod ]; then t=go; \
	  elif [ -f requirements.txt ]; then t=python; fi; \
	fi; \
	test -n "$$t" || { echo "no go.mod or requirements.txt here; use TARGET=go or TARGET=python"; exit 1; }; \
	test -f "$(LIT)/templates/$$t/BOOK.org" || { echo "unknown TARGET '$$t'"; exit 1; }; \
	cp "$(LIT)/templates/$$t/BOOK.org" BOOK.org && \
	echo "BOOK.org created from the $$t template" && \
	{ test -f Makefile || printf 'include lit/lit.mk\n' > Makefile; } && \
	$(MAKE) -f $(LIT)/lit.mk tangle
#+end_src

check tangles into a scratch directory and diffs. The exclusion
list is the hand-managed set plus the toolchain directory itself
(the scratch copy exists to run the tangle, not to be compared),
and ~CHECK_EXTRA~ appends a consumer's own exclusions, spelled as
diff flags: ~CHECK_EXTRA = -x PROMPT.md -x testdata~.

#+name: lit-mk-check
#+begin_src makefile :tangle lit.mk
check:
	@d=$$(mktemp -d) && mkdir $$d/lit && \
	  for f in $(BOOK_PARTS); do \
	    mkdir -p $$d/$$(dirname $$f) && cp $$f $$d/$$f; \
	  done && \
	  cp -R $(LIT)/* $$d/lit/ && ( \
	  cd $$d && emacs -Q --batch -l lit/tangle.el \
	    --eval '(lit-tangle "BOOK.org")' >/dev/null 2>&1 \
	) && diff -r -x BOOK.org -x lit -x example -x templates \
	  -x Makefile -x .gitignore -x go.mod -x go.sum \
	  -x requirements.txt -x README.md -x AGENTS.md -x book.pdf \
	  -x book-review.pdf -x docs -x .git -x .DS_Store \
	  $(CHECK_EXTRA) $$d . \
	  && echo ok
#+end_src

check copies the chapters into its scratch directory before tangling
there, since a book it cannot read is a book it cannot check. It
copies the chapters and nothing else around them. A book that keeps
other files beside them, diagrams for instance, excludes those
through ~CHECK_EXTRA~, which is how a book already tells check about
everything it does not generate.

* The tangling driver

tangle.el is everything batch Emacs needs to tangle a lit book. It
loads org-babel, then patches the gaps a blank batch session has.
Comment syntax comes from a table keyed
by language, which a project extends beside its book, and the mode
lookup org would use is answered from that table. Backup files are suppressed because the
post-tangle hooks save every written file, and each save would
otherwise strew a backup through the tree. Directory creation is on
by default so a block can target a path that does not exist yet.

#+name: tangle-setup
#+begin_src emacs-lisp :tangle tangle.el
;; Batch tangler for the org literate experiment. Supplies line-comment
;; syntax per language and turns the last prose paragraph before a
;; :comments org block into its comment.

(require 'org)
(require 'ob-tangle)
(require 'json)
(require 'ox)

;; Line-comment syntax, keyed by the language a block is written in. A
;; language absent here takes the hash, which comments shells, Python,
;; Ruby and make.
(defconst lit-comment-syntax
  '(("go" . "//") ("js" . "//")
    ("emacs-lisp" . ";;") ("elisp" . ";;")
    ("lua" . "--")))

(defvar lit-comment-table lit-comment-syntax)

;; A project extends the table through .lit/comments.json beside its
;; book, an object of language to prefix, whose entries win. The format
;; is JSON because both engines parse it with a reader neither of them
;; wrote, and a hand-written reader is where two implementations drift.
(defun lit-load-comment-table (book)
  (let ((file (expand-file-name
               ".lit/comments.json"
               (file-name-directory (expand-file-name book))))
        (table (copy-alist lit-comment-syntax)))
    (when (file-readable-p file)
      (dolist (pair (with-temp-buffer
                      (insert-file-contents file)
                      (json-parse-buffer :object-type 'alist)))
        (let ((lang (symbol-name (car pair)))
              (prefix (cdr pair)))
          (unless (stringp prefix)
            (error "%s: comment prefix for %s is not a string" file lang))
          (setf (alist-get lang table nil nil #'equal) prefix))))
    (setq lit-comment-table table)))

(defun lit-comment-prefix (lang)
  (or (cdr (assoc lang lit-comment-table)) "#"))

;; org takes comment syntax from a major mode, so a language whose mode
;; batch Emacs never loaded silently reuses the previous block's
;; syntax. Answering from the table instead makes comment syntax a
;; property of the language rather than of what Emacs happens to have
;; loaded.
(defun lit-lang-mode (lang)
  (let ((mode (intern (format "lit-comment-%s-mode" lang)))
        (prefix (lit-comment-prefix lang)))
    (unless (fboundp mode)
      (eval `(define-derived-mode ,mode prog-mode "lit"
               (setq-local comment-start ,prefix)
               (setq-local comment-end "")
               (setq-local comment-padding 1))))
    mode))

(advice-add 'org-src-get-lang-mode :override #'lit-lang-mode)

(setq comment-empty-lines t)

;; the post-tangle hooks modify and save every tangled file; without
;; this, batch Emacs strews foo~ backups through the tree
(when noninteractive
  (setq make-backup-files nil))

(setq org-babel-default-header-args
      (cons '(:mkdirp . "yes") org-babel-default-header-args))
#+end_src

The docstring rule from the contract lives in one function. Org
hands it the raw text between the previous block or heading and the
block being tangled; it picks the docstring out of that text: the
part after the last marker line when one is present, else the last
paragraph, with org keyword lines removed and the aside sigil
stripped.

#+name: tangle-docstring
#+begin_src emacs-lisp :tangle tangle.el
;; The docstring for a :comments org block is the text after the last
;; "# doc" marker line when one is present, else the last paragraph.
;; Earlier text is narrative. A leading "Note: " or "Apropos: " sigil is
;; presentation, not part of the source comment.
(defun lit-docstring (text)
  (let* ((doc-end (let ((start 0) (end nil))
                    (while (string-match "^# doc\n" text start)
                      (setq end (match-end 0) start (match-end 0)))
                    end))
         (sliced (if doc-end (substring text doc-end) text))
         ;; #+name: and other org keyword/comment lines sit between the
         ;; docstring and the block; they are not comment material
         (clean (replace-regexp-in-string "^#\\+[^\n]*\n?" "" sliced))
         (chosen (if doc-end
                     clean
                   (car (last (split-string clean "\n\n+" t)))))
         (trimmed (string-trim (or chosen ""))))
    (replace-regexp-in-string "\\`\\(Note\\|Apropos\\): " "" trimmed)))

(setq org-babel-process-comment-text #'lit-docstring)
#+end_src

Two hooks run after every file is written. The first exists because
Emacs pads an empty comment line,
and a file wants the bare marker.
The second stamps the banner, choosing the comment prefix from the
language that wrote the file and skipping past a shebang when one is present. The
Go spelling of the banner is canonical so Go tooling recognizes
generated files.

#+name: tangle-banner
#+begin_src emacs-lisp :tangle tangle.el
;; Which language wrote each target. org stamps the banner in a hook
;; that sees a filename and not a language, so the map is built while
;; the book is still open and read back by name. One file takes one
;; comment syntax, so two languages in a file is an error rather than
;; a guess.
(defvar lit-file-languages nil)

(defun lit-collect-file-languages ()
  (setq lit-file-languages nil)
  (dolist (group (org-babel-tangle-collect-blocks))
    (let ((file (expand-file-name (car group)))
          (langs (delete-dups (mapcar (lambda (b) (nth 0 b)) (cdr group)))))
      (when (cdr langs)
        (error "%s: blocks in %s; one file takes one comment syntax"
               file (mapconcat #'identity langs " and ")))
      (push (cons file (car langs)) lit-file-languages))))

(defun lit-file-comment-prefix ()
  (lit-comment-prefix
   (cdr (assoc (expand-file-name (buffer-file-name)) lit-file-languages))))

;; comment-region pads an empty comment line; the file wants the bare
;; marker.
(defun lit-trim-empty-comment-lines ()
  (let ((marker (lit-file-comment-prefix)))
    (goto-char (point-min))
    (while (re-search-forward (concat "^" (regexp-quote marker) " $") nil t)
      (replace-match marker))
    (save-buffer)))

(add-hook 'org-babel-post-tangle-hook #'lit-trim-empty-comment-lines)

;; Every tangled file opens with a generated-file banner in the comment
;; syntax of the language that wrote it, after a shebang when one is
;; present. The Go spelling is canonical ("Code generated ... DO NOT
;; EDIT.") so Go tooling recognizes it too.
(defconst lit-banner
  "Code generated from BOOK.org by make tangle. DO NOT EDIT.")

(defun lit-insert-banner ()
  (goto-char (point-min))
  (let ((banner (concat (lit-file-comment-prefix) " " lit-banner "\n")))
    (when (looking-at "#!.*\n")
      (goto-char (match-end 0)))
    (unless (looking-at-p (regexp-quote banner))
      (insert banner "\n"))
    (save-buffer)))

(add-hook 'org-babel-post-tangle-hook #'lit-insert-banner t)
#+end_src


The first generated view: a diff between two named blocks, used to
show a planned replacement beside the live code. The writer
resolves both blocks, runs diff, drops the two header lines that
only name temporary files, and wraps the rest so both Emacs and the
weave fontify it.

#+name: tangle-diff-view
#+begin_src emacs-lisp :tangle tangle.el
;; A "#+begin: src-block-diff :old A :new B" dynamic block renders as
;; a unified diff of the two named blocks' bodies. The content is
;; derived: refresh one with C-c C-c on its begin line, and tangling
;; refreshes them all first, so a committed diff cannot disagree with
;; the blocks under it.
(defun lit-named-block-body (name)
  (save-excursion
    (goto-char (or (org-babel-find-named-block name)
                   (error "no block named %s" name)))
    (nth 1 (org-babel-get-src-block-info t))))

(defun org-dblock-write:src-block-diff (params)
  ;; fetch both bodies before with-temp-file switches buffers
  (let ((old-body (lit-named-block-body
                   (format "%s" (plist-get params :old))))
        (new-body (lit-named-block-body
                   (format "%s" (plist-get params :new))))
        (old (make-temp-file "src-block-diff"))
        (new (make-temp-file "src-block-diff")))
    (unwind-protect
        (progn
          (with-temp-file old (insert old-body "\n"))
          (with-temp-file new (insert new-body "\n"))
          (let ((diff (with-temp-buffer

The entry point expands the book's includes before org collects any
block, and where that expansion happens is forced from two
directions.

It happens in the buffer visiting the master, not in a scratch
buffer, because org asks the buffer for its own file name while it
writes blocks out. That also settles how a target named inside a
chapter is resolved: against the master's directory, not the
chapter's. The paths in a book are the project's paths, and a
chapter that moves into a subdirectory does not drag its targets
with it.

It happens with the tangle hook that saves the source buffer unbound
for the call, and the buffer is marked unmodified afterwards. By
that point the buffer holds the merged book. Saving it would write
that merge over the master, replacing the file that names the
chapters with a copy of their contents. The failure destroys the
book rather than the output, which is why the hook is unbound rather
than worked around.

* The weave preprocessor

preprocess.py runs before pandoc and exists because pandoc alone
ignores three things books rely on: custom heading keywords, the
badge markup that flags plan sites, and CriticMarkup, the
bracket-based notation for insertions, deletions, and comments in
prose. The preprocessor rewrites all three into org and raw LaTeX
that pandoc passes through, and it injects the LaTeX preamble the
rest of the weave depends on.

It reads the master and every chapter it includes as one text. Plan
markup sits where the change it describes sits, which is in the
chapters, so a preprocessor that read only the master would rewrite
nothing and the badges would reach the PDF as literal rows of stars.
Reading the chapter files here also puts the duplicate custom id
check in the one place that can report a useful position, since
after this point every line number refers to merged text.

CriticMarkup spans become LaTeX color macros, but only the shells
are raw: the content between the braces stays org, so links and
verbatim inside an insertion keep rendering as org.

#+name: preprocess-criticmarkup
#+begin_src python :tangle preprocess.py
# The content between the delimiters stays org: pandoc renders its
# markup (verbatim, links, braces) and only the \cm..{ } shells are
# raw. Flattening the content into the raw span instead breaks on
# inner braces and turns org markup into literal TeX.
def cm(macro, s):
    return "@@latex:\\%s{@@%s@@latex:}@@" % (macro, s)

def criticmarkup(text):
    text = re.sub(r"\{~~(.+?)~>(.+?)~~\}",
                  lambda m: cm("cmdel", m.group(1)) + " " + cm("cmins", m.group(2)),
                  text, flags=re.S)
    text = re.sub(r"\{\+\+(.+?)\+\+\}",
                  lambda m: cm("cmins", m.group(1)),
                  text, flags=re.S)
    text = re.sub(r"\{--(.+?)--\}",
                  lambda m: cm("cmdel", m.group(1)),
                  text, flags=re.S)
    text = re.sub(r"\{>>(.+?)<<\}",
                  lambda m: cm("cmnote", m.group(1)),
                  text, flags=re.S)
    return text

def strip_org(s):
    s = re.sub(r"\[\[[^]]*\]\[([^]]*)\]\]", r"\1", s)
    s = re.sub(r"\[\[([^]]*)\]\]", r"\1", s)
    return s.strip()

Badges are the plan's road signs, and the weave gives each one a
box, a margin mark, an anchor for the jump list, and a sticky-note
annotation. The note text must survive two hostile containers, a
PDF literal string and a TeX macro argument, so it is reduced to
safe ASCII; parens stay only when they balance, which the PDF
string grammar requires.

#+name: preprocess-badges
#+begin_src python :tangle preprocess.py
def badge_titles(text):
    """Badge display titles, in the same order badges() counts them."""
    star = re.compile(r"^\*{15,}\s+(.*\S)\s*$")
    out = []
    for l in text.split("\n"):
        m = star.match(l)
        if not m or m.group(1).strip() == "END":
            continue
        t = m.group(1)
        tm = re.match(r"^(.*?)\s+(:[A-Za-z0-9_@:]+:)$", t)
        if tm:
            t = tm.group(1)
        out.append(strip_org(t))
    return out

def pdf_note(title, body):
    """Sticky-note contents: PDF-string- and macro-arg-safe ASCII.

    Balanced parens are legal unescaped in a PDF literal string, and
    backslash escapes would be undefined control sequences inside the
    special, so parens stay only when balanced in order."""
    s = title
    if body:
        s += ": " + " ".join(l.strip() for l in body if l.strip())
    s = strip_org(s)
    s = re.sub(r"[{}~%$&^_\\#]", " ", s)
    s = " ".join(s.split())
    depth = 0
    for c in s:
        if c == "(":
            depth += 1
        elif c == ")":
            depth -= 1
            if depth < 0:
                break
    if depth != 0:
        s = " ".join(s.replace("(", " ").replace(")", " ").split())
    return s[:237] + "..." if len(s) > 240 else s

def badges(lines):
    star = re.compile(r"^\*{15,}\s+(.*\S)\s*$")
    head = re.compile(r"^\*+\s")
    out, i, k = [], 0, 0
    while i < len(lines):
        m = star.match(lines[i])
        if not m:
            out.append(lines[i])
            i += 1
            continue
        title = m.group(1)
        body = None
        j = i + 1
        while j < len(lines):
            if head.match(lines[j]):
                mm = star.match(lines[j])
                if mm and mm.group(1).strip() == "END":
                    body = lines[i + 1:j]
                    i = j
                break
            j += 1
        tags = ""
        tm = re.match(r"^(.*?)\s+(:[A-Za-z0-9_@:]+:)$", title)
        if tm:
            title, tags = tm.group(1), tm.group(2)
        kw = None
        parts = title.split(None, 1)
        if parts and parts[0] in KEYWORDS:
            kw = parts[0]
            title = parts[1] if len(parts) > 1 else ""
        block = KEYWORDS.get(kw, "planned")
        label = ("*%s* \u2014 " % kw if kw else "") + title
        if tags:
            label += "  (" + tags.strip(":").replace(":", ", ") + ")"
        stage = re.search(r"stage(\d+)", tags)
        # inline in the label line: the margin mark aligns with the
        # box's first line, the hypertarget (ordinal k, matching the
        # badge order the plan-toc rewrite counts) receives the index
        # links, and the sticky note carries the badge's why
        k += 1
        mark = ("@@latex:\\hypertarget{planbadge-%d}{}"
                "\\planbadgemark{badgeplan}{%s}{%s}@@ ") % (
            k, "s" + stage.group(1) if stage else "",
            pdf_note(strip_org(title), body))
        out.append("#+begin_" + block)
        out.append(mark + label)
        if body:
            out.append("")
            out.extend(body)
        out.append("#+end_" + block)
        i += 1
    return out

The main pass stitches it together: CriticMarkup first, then the
preamble injection (after the options line when the book has one,
else before the first content line, so headerless books weave too),
the "Plan sites" outline branch, and the jump-list rewrite that
turns file links, which are dead in a PDF, into internal links to
each site's governing badge.

#+name: preprocess-main
#+begin_src python :tangle preprocess.py
INCLUDE = re.compile(r'^[ \t]*#\+INCLUDE:(.*)$', re.IGNORECASE)
BARE = re.compile(r'^"([^"]+)"$')
WRAPPED = re.compile(r'^"([^"]+)"\s+example$')
CUSTOM_ID = re.compile(r'^[ \t]*:CUSTOM_ID:[ \t]*(\S+)', re.IGNORECASE)


def read_book(src, seen=None, ids=None, base=None):
    """The master and every chapter it includes, as one text.

    Only the bare quoted form is understood, the same one the tangler
    accepts, so both halves of the toolchain read the same book. A
    custom id defined twice is refused here rather than left to pandoc:
    this function still knows which file and line the second definition
    sits on, and after expansion nobody does.
    """
    seen = seen if seen is not None else set()
    ids = ids if ids is not None else {}
    path = os.path.abspath(src)
    base = base if base is not None else os.path.dirname(path)
    # positions are reported the way the includes are written, relative
    # to the master, since that is how the reader will go looking
    here = os.path.relpath(path, base)
    if path in seen:
        raise SystemExit("%s: includes itself" % here)
    seen.add(path)
    out = []
    for n, line in enumerate(open(path, encoding="utf-8").read().split("\n"), 1):
        m = INCLUDE.match(line)
        if m:
            rest = m.group(1).strip()
            if WRAPPED.match(rest):
                out.append(line)      # verbatim display; pandoc expands it
                continue
            arg = BARE.match(rest)
            if not arg:
                raise SystemExit(
                    '%s:%d: only #+INCLUDE: "path" and #+INCLUDE: "path" '
                    "example are understood" % (here, n))
            out.append(read_book(
                os.path.join(os.path.dirname(path), arg.group(1)),
                seen, ids, base))
            continue
        cid = CUSTOM_ID.match(line)
        if cid:
            key = cid.group(1)
            if key in ids:
                raise SystemExit(
                    "%s:%d: custom id %s is already defined at %s"
                    % (here, n, key, ids[key]))
            ids[key] = "%s:%d" % (here, n)
        out.append(line)
    return "\n".join(out)


def main(src, dst):
    text = read_book(src)
    text = criticmarkup(text)
    text = text.replace("\u2192", "$\\rightarrow$")
    has_geometry = re.search(r"^#\+latex_header:.*geometry", text,
                             re.IGNORECASE | re.MULTILINE)
    preamble = [p for p in PREAMBLE
                if "geometry" not in p or not has_geometry]
    # badge ordinals by original line number: the jump list's targets
    badge_lines = [i + 1 for i, l in enumerate(text.split("\n"))
                   if re.match(r"^\*{15,}\s+(?!END\b)", l)]
    # a "Plan sites" branch in the PDF outline, one entry per badge;
    # level 1 keeps the book's chapters as siblings, not children
    marks = []
    titles = badge_titles(text)
    if titles:
        marks.append("#+latex: \\bookmark[level=1,dest=planbadge-1]"
                     "{Plan sites}")
        for j, t in enumerate(titles, 1):
            marks.append("#+latex: \\bookmark[level=2,dest=planbadge-%d]"
                         "{%s}" % (j, re.sub(r"[{}\\%$&#^_~]", " ", t)))
    lines = []
    in_toc = False
    injected = False
    for line in text.split("\n"):
        if re.match(r"^#\+begin: plan-toc", line):
            in_toc = True
            continue
        if re.match(r"^#\+(begin|end):", line):
            if line.startswith("#+end:"):
                in_toc = False
            continue
        if in_toc:
            # file links are external in a PDF; link each item to its
            # governing badge instead, the nearest one above the site
            m = re.match(r"^- \[\[file:[^]]*::(\d+)\]\[(\d+)\]\] (.*)$", line)
            if m and bisect.bisect_right(badge_lines, int(m.group(1))):
                k = bisect.bisect_right(badge_lines, int(m.group(1)))
                line = "- @@latex:\\hyperlink{planbadge-%d}{%s}@@ %s" % (
                    k, m.group(2), m.group(3))
            else:
                line = re.sub(r"\[\[file:[^]]*\]\[([^]]*)\]\]", r"\1", line)
        # inject after #+options: when the book has one, else before
        # the first content line, so headerless books weave too
        if (not injected and line.strip()
                and not line.startswith("#+")):
            lines.extend(preamble)
            lines.extend(marks)
            injected = True
        lines.append(line)
        if not injected and line.startswith("#+options:"):
            lines.extend(preamble)
            lines.extend(marks)
            injected = True
    open(dst, "w", encoding="utf-8", newline="\n").write(
        "\n".join(badges(lines)) + "\n")

def deps(src, seen=None, base=None):
    """Every file the book is made of, the master included.

    Reported for make, which needs to know when the PDF is stale.
    Both include forms count: a chapter changes the book, and a file
    shown as an example changes the page it appears on.
    """
    seen = seen if seen is not None else []
    path = os.path.abspath(src)
    base = base if base is not None else os.path.dirname(path)
    rel = os.path.relpath(path, base)
    if rel in seen:
        return seen
    seen.append(rel)
    try:
        text = open(path, encoding="utf-8").read()
    except OSError:
        return seen
    for line in text.split("\n"):
        m = INCLUDE.match(line)
        if not m:
            continue
        arg = BARE.match(m.group(1).strip()) or WRAPPED.match(m.group(1).strip())
        if arg:
            deps(os.path.join(os.path.dirname(path), arg.group(1)), seen, base)
    return seen


if __name__ == "__main__":
    # --deps runs while make is still reading the Makefile, before a
    # target exists, so it reports what it can and never fails. A bad
    # include is refused later, by the tangler and by the weave, where
    # there is somewhere sensible to report it.
    if sys.argv[1] == "--deps":
        print("\n".join(deps(sys.argv[2])))
    else:
        main(sys.argv[1], sys.argv[2])
#+end_src

* The pandoc filters

Four Lua filters run inside pandoc, in the order the weave recipe
lists them.

** Diagrams

mermaid.lua renders each mermaid block to a PDF image through mmdc
and swaps the block for the image. When mmdc is missing or a
diagram fails to render, the block stays as source and the weave
completes anyway; a broken diagram should cost a picture, not the
whole book.

mmdc drives a headless browser, and a browser inside a container
usually refuses to start: it wants a sandbox helper owned by root,
which a package store cannot provide. ~MERMAID_PUPPETEER_CONFIG~
names a config file the filter passes on, so the book that runs in a
container can say so without every other book paying for it. Left
unset, mmdc runs exactly as before.

Both converters are called directly rather than through a shell, so a
scratch directory or a figure path containing a space converts like any
other, and nothing in a path is read as shell syntax.

#+name: mermaid-filter
#+begin_src lua :tangle mermaid.lua
-- Render mermaid src blocks to PDF images at weave time via mmdc.
-- MERMAID_TMP names the scratch directory for generated files; the
-- weave recipe creates and removes it. MERMAID_PUPPETEER_CONFIG, when
-- set, names a puppeteer config file passed on to the browser mmdc
-- drives; a container needs one to turn the sandbox off. When mmdc is
-- missing or a render fails, the block stays as fontified source and
-- the weave still completes.
local dir = os.getenv("MERMAID_TMP") or "."
local puppeteer = os.getenv("MERMAID_PUPPETEER_CONFIG")
local n = 0

function CodeBlock(el)
  if not el.classes:includes("mermaid") then return nil end
  n = n + 1
  local base = string.format("%s/mermaid-%d", dir, n)
  local f = assert(io.open(base .. ".mmd", "w"))
  f:write(el.text)
  f:close()
  local args = { "-q", "-i", base .. ".mmd", "-o", base .. ".pdf",
                 "-f", "-b", "transparent" }
  if puppeteer and puppeteer ~= "" then
    table.insert(args, "-p")
    table.insert(args, puppeteer)
  end
  local ok = pcall(pandoc.pipe, "mmdc", args, "")
  if not ok then
    io.stderr:write("mermaid.lua: mmdc failed; keeping source block\n")
    return nil
  end
  return pandoc.Para({ pandoc.Image({}, base .. ".pdf", "",
                                    pandoc.Attr(el.identifier)) })
end
#+end_src

A mermaid block carrying a ~#+name:~ and a ~#+caption:~ becomes a
numbered figure, so the identifier rides along on the image the
filter returns and notes.lua promotes the pair.

** Hand-drawn figures

A diagram too particular for mermaid is drawn by hand and kept as
SVG, which is the format worth editing. LaTeX cannot include SVG:
the svg package shells out to inkscape, tectonic refuses piped
input, and one such figure fails the whole build. So svg.lua
converts each one to PDF at weave time with rsvg-convert, leaving
the drawing vector and the repository free of a generated binary
beside every source.

A figure that cannot be converted becomes a visible note rather
than a missing picture, because a diagram that silently vanishes
from a PDF is worse than one that says why it is not there.

#+name: svg-filter
#+begin_src lua :tangle svg.lua
-- Convert SVG figures to PDF at weave time, since LaTeX cannot
-- include SVG. MERMAID_TMP names the scratch directory the weave
-- recipe creates and removes.
local dir = os.getenv("MERMAID_TMP") or "."
local n = 0

function Image(el)
  if not el.src:match("%.svg$") then return nil end
  n = n + 1
  local out = string.format("%s/svg-%d.pdf", dir, n)
  local ok = pcall(pandoc.pipe, "rsvg-convert",
    { "-f", "pdf", "-o", out, el.src }, "")
  if not ok then
    io.stderr:write("svg.lua: rsvg-convert failed on " .. el.src .. "\n")
    return pandoc.Emph({ pandoc.Str("[figure " .. el.src .. " could not be converted]") })
  end
  el.src = out
  return el
end

** Captions, references, asides

notes.lua carries the weave's general-purpose repairs and the
listing machinery. The strikeout guard exists for pandoc run by
hand without the preprocessor: org parses a short CriticMarkup span
as strikethrough and hands it to a LaTeX command that cannot
typeset it, so the guard restores the plus signs. The span repair
turns pandoc's dead links to named blocks into working internal
links.

#+name: notes-guards
#+begin_src lua :tangle notes.lua
-- CriticMarkup pluses in a plain weave parse as org strikeout, and
-- soul's \st cannot typeset what lands inside ("Reconstruction
-- failed"); render the span raw instead, pluses restored. The review
-- weave never gets here: preprocess.py rewrites the marks first.
function Strikeout(el)
  local out = pandoc.List({ pandoc.Str('+') })
  out:extend(el.content)
  out:insert(pandoc.Str('+'))
  return out
end

-- Org links to #+name:'d blocks work in the buffer, but pandoc's org
-- reader leaves them as "spurious-link" spans; the named block itself
-- does get a \label. Repair the spans into real internal links.
function Span(el)
  if el.classes:includes('spurious-link') and el.attributes['target'] then
    local name = pandoc.utils.stringify(el.content)
    return pandoc.Link({ pandoc.Code(name) }, '#' .. el.attributes['target'])
  end
end
#+end_src

A figure carries a ~#+name:~ starting ~fig:~ and a ~#+caption:~, which
pandoc turns into a float with a numbered caption and a label. Prose
refers to it with an ordinary org link to that name, and the filter
below turns the link into a LaTeX cross-reference, so the number in
the sentence is the number under the figure. The point of the float
is that the figure need not sit where the sentence does: a full-page
drawing lands on its own page and the prose around it stays
continuous.

#+name: notes-figrefs
#+begin_src lua :tangle notes.lua
-- A link whose target names a figure (#+name: fig:...) becomes a
-- numbered cross-reference. Pandoc's org reader turns [[fig:x]] into
-- an autolink, which the LaTeX writer would set as a \url; the label
-- comes from the #+name: on the figure itself.
function Link(el)
  if el.target:match('^fig:') then
    return pandoc.RawInline('latex', 'Figure~\\ref{' .. el.target .. '}')
  end
  -- A stored link to a heading in another chapter names the file and
  -- the custom id. Includes make the chapters one document, so by the
  -- time this runs the file names nothing; the id resolves.
  local id = el.target:match('::#(.+)$')
  if id then
    el.target = '#' .. id
    return el
  end
end
#+end_src

The filter also resolves a link that names a file and a custom id,
the form Emacs stores when a link is made to a heading in another
chapter. Both halves are true while the book is being edited, and
only one of them survives the weave: the includes make the chapters
a single document, so the file names nothing that the PDF contains,
while the id names a heading in it. Keeping the id and dropping the
file is what the link meant. The alternative, leaving it alone,
produces a link to an org file that is not beside the PDF, which
fails silently for the reader.

An image written as a link is a figure already, because pandoc's org
reader promotes a captioned paragraph on its own. A captioned block
is not: the reader wraps it in a division and leaves the caption as
a paragraph above, which typesets as a stranded picture that cannot
float. The filter below promotes such a division into a figure when
what it wraps is a single image, which is the shape mermaid.lua and
svg.lua leave behind.

#+name: notes-figures
#+begin_src lua :tangle notes.lua
-- Pandoc's org reader wraps a captioned block in a captioned-content
-- division rather than a figure, so a mermaid diagram with a
-- #+caption: would typeset as a bare image with its caption above.
-- Promote the division to a figure, which floats and takes a number.
-- The label comes from the #+name:, which mermaid.lua leaves on the
-- image it returns.
function Div(el)
  if not el.classes:includes('captioned-content') then
    return nil
  end
  local caption, content = nil, pandoc.List({})
  for _, b in ipairs(el.content) do
    if b.t == 'Div' and b.classes:includes('caption') then
      caption = b.content
    else
      content:insert(b)
    end
  end
  if not caption or #content ~= 1 then
    return nil
  end
  local body = content[1]
  if body.t ~= 'Para' and body.t ~= 'Plain' then
    return nil
  end
  if #body.content ~= 1 or body.content[1].t ~= 'Image' then
    return nil
  end
  local img = body.content[1]
  local id = img.identifier ~= '' and img.identifier or el.identifier
  img.identifier = ''
  return pandoc.Figure({ pandoc.Plain({ img }) },
                       pandoc.Caption(caption), pandoc.Attr(id))
end
#+end_src

The caption and reference machinery implements the weave contract.
Pandoc keeps the block's target and name as attributes, so a
tangling block's caption is direct. A region block needs a second
look: its file is whatever its includer tangles to, so the filter
first walks the whole document, recording every block's own target
and every reference each expanding block makes, then resolves
region names to files through those references until nothing
changes. A named block nothing references and nothing tangles, a
planned twin for instance, resolves to no file and gets no caption.
References are the hard half: syntax highlighting shreds a
reference into operator and identifier tokens, so no literal
reference survives into the LaTeX for anything to linkify. The
filter therefore swaps each reference in an expanding block for an
alphanumeric placeholder, the one spelling every language's lexer
keeps whole, and texlinks.py decodes the placeholders after pandoc
has written the LaTeX.

#+name: notes-captions
#+begin_src lua :tangle notes.lua
-- Pandoc's org reader keeps :tangle and :noweb as block attributes;
-- every source block gets a paper-style numbered caption, so any
-- listing in the book can be pointed at by number. What the caption
-- says after the number is whatever identifies the block: the file
-- it lands in, or its <<name>> when it reaches no file of its own,
-- or nothing at all. A named region block (no target of its own,
-- included through a reference) is captioned with the file its
-- includer tangles to, resolved transitively over the whole
-- document.
--
-- The test is what the block is, not whether it reaches a file. A
-- listing number belongs to a listing of the program, and pandoc
-- hands this filter two things that are not one. An example block
-- is an illustration of markup, and it arrives carrying the literal
-- class example. The text of an included file arrives carrying no
-- class at all, because by then it is a file's contents rather than
-- a block anybody wrote. Only a source block carries a language, so
-- the language is the test. Every other org block that could be
-- confused for one arrives as something else entirely, a quote as a
-- block quote and an export as raw output.
--
-- Syntax highlighting shreds a <<ref>> into operator and identifier
-- tokens, so no literal <<ref>> survives into the .tex for a filter
-- to linkify. Instead, in :noweb yes blocks each ref is swapped for
-- an alphanumeric placeholder (hex-encoded name), which every
-- lexer keeps whole; texlinks.py decodes it back into a \NowebRef
-- hyperlink after pandoc writes the .tex.
local function hex(s)
  return (s:gsub('.', function(c) return string.format('%02x', c:byte()) end))
end

local REF = '<<([%w_][%w_.%-]*)>>'

-- A caption written by hand is prose, so it reaches the page as
-- prose rather than through the detokenized monospace a filename
-- gets. Pandoc renders it, rather than this filter flattening it to
-- text and escaping the result: a caption is the one place in a
-- listing's furniture where an author writes org, and ~code~ and
-- /emphasis/ in one should survive to the page. Handing the inlines
-- back to pandoc also puts the escaping where it belongs, since the
-- writer already knows which characters TeX reads as instructions.
local function latexInlines(inlines)
  local s = pandoc.write(pandoc.Pandoc({ pandoc.Plain(inlines) }), 'latex')
  return (s:gsub('%s+$', ''))
end

-- Whether a code block is a listing of the program at all. Only a
-- source block is, and only a source block carries a language.
local function isListing(el)
  return el.classes[1] ~= nil and el.classes[1] ~= 'example'
end

-- A listing with no file, no name and no caption renders as a bare
-- number, which tells a reader nothing about what they are looking
-- at. The weave says so rather than printing it quietly, because
-- nothing else in the pipeline can tell a listing that needs a
-- caption from one that does not.
--
-- It stays quiet about a diff, and the reason is that the advice
-- would not work there. The only diff listings in a lit book are the
-- ones a src-block-diff dynamic block generates, and a caption
-- written above that block attaches to the dynamic block rather
-- than to the src block inside it. A warning a reader cannot act on
-- is worse than no warning, because it teaches them to ignore the
-- ones they can act on.
local function warnBareListing(el)
  local first = (el.text:match('^[^\n]*') or ''):gsub('^%s+', '')
  io.stderr:write(string.format(
    'lit: a listing has no file, no name and no caption, so it renders as a bare number. Add a "#+caption:" line above it. First line: %s\n',
    first:sub(1, 60)))
end

function Pandoc(doc)
  -- A #+caption: line above a block is org's own way of naming a
  -- listing, and pandoc reads it as a wrapper div holding a caption
  -- div and the block. Unwrapping it here, with the text moved onto
  -- the block as an attribute, means the rest of this filter never
  -- has to know the shape: it keeps walking code blocks, and a
  -- captioned one differs only by carrying one more attribute.
  doc = doc:walk({ Div = function(el)
    if el.classes[1] ~= 'captioned-content' then return nil end
    local text, code
    for _, b in ipairs(el.content) do
      if b.t == 'Div' and b.classes[1] == 'caption' then
        for _, inner in ipairs(b.content) do
          if inner.content then text = latexInlines(inner.content) end
        end
      elseif b.t == 'CodeBlock' then
        code = b
      end
    end
    if not code then return nil end
    if text and text ~= '' then
      code.attributes['lit-caption'] = text
    end
    return code
  end })
  local bodies = {}
  -- first pass: each block's own target, and who references whom
  local blocks = {}
  doc:walk({ CodeBlock = function(el)
    local t = el.attributes['tangle']
    local entry = { id = el.identifier, names = {} }
    if t and t ~= 'no' then
      entry.target = t
    end
    if expandsNoweb(el) then
      for name in el.text:gmatch(REF) do
        table.insert(entry.names, name)
      end
    end
    if el.identifier ~= '' then
      bodies[el.identifier] = el
    end
    table.insert(blocks, entry)
  end })
  -- resolve region names to their includer's file, transitively
  local resolved = {}
  for _, e in ipairs(blocks) do
    if e.target and e.id ~= '' then
      resolved[e.id] = e.target
    end
  end
  for _ = 1, #blocks do
    local changed = false
    for _, e in ipairs(blocks) do
      local t = e.target or (e.id ~= '' and resolved[e.id])
      if t then
        for _, name in ipairs(e.names) do
          if not resolved[name] then
            resolved[name] = t
            changed = true
          end
        end
      end
    end
    if not changed then
      break
    end
  end
  -- second pass: captions, anchors, and reference placeholders
  return doc:walk({ CodeBlock = function(el)
    local out = el
    if nowebWord(el, 'inline') then
      local text = inlineRefs(el.text, bodies, {})
      if text ~= el.text then
        out = el:clone()
        out.text = text
      end
    elseif expandsNoweb(el) then
      local text = el.text:gsub(REF, function(name)
        return 'NOWEBREF' .. hex(name) .. 'FERBEWON'
      end)
      if text ~= el.text then
        out = el:clone()
        out.text = text
      end
    end
    local anchor = ''
    if el.identifier ~= '' then
      anchor = '\\hypertarget{noweb:' .. el.identifier .. '}{}'
    end
    local t = el.attributes['tangle']
    local file = (t and t ~= 'no') and t or nil
    if not file and el.identifier ~= '' then
      file = resolved[el.identifier]
    end
    if isListing(el) then
      local written = el.attributes['lit-caption']
      local caption = anchor .. '\\codecaption'
      if el.identifier ~= '' then
        caption = caption .. '[' .. el.identifier .. ']'
      end
      if written then
        caption = anchor .. '\\codecaptiontext'
        if el.identifier ~= '' then
          caption = caption .. '[' .. el.identifier .. ']'
        end
        caption = caption .. '{' .. written .. '}'
      else
        caption = caption .. '{' .. (file or '') .. '}'
        if not file and el.identifier == '' and el.classes[1] ~= 'diff' then
          warnBareListing(el)
        end
      end
      return { pandoc.RawBlock('latex', caption), out }
    end
    if anchor ~= '' then
      return { pandoc.RawBlock('latex', anchor), out }
    end
    if out ~= el then
      return out
    end
  end })
end

The noweb header is a list of words, not one value. Org reads it by
splitting on whitespace and looking for a word it knows, which is
what lets a book carry a word org has never heard of without
changing what tangling does.

Inlining reproduces what tangling produces. A reference is replaced
by the named block's body, the text before it on the line is
repeated in front of every line after the first, and a body that
asks for expansion itself is expanded further. A name no block
carries is left alone, which is what a group reference is, and it
stays a link.

#+name: notes-inline
#+begin_src lua :tangle notes.lua
-- The noweb header is a word list. Org splits it and looks for a
-- word it knows, so "yes inline" tangles as "yes" and carries the
-- extra word past every reader but this one.
function nowebWord(el, word)
  for w in (el.attributes['noweb'] or ''):gmatch('%S+') do
    if w == word then return true end
  end
  return false
end

function expandsNoweb(el)
  return nowebWord(el, 'yes')
end

-- What tangling would produce: the named body in place of the
-- reference, with the text before it repeated in front of every line
-- after the first. The body's own trailing newline goes first, the
-- way tangling drops it, or the prefix would be repeated once more
-- onto a line with nothing after it. A name nothing carries is left
-- as it stands, which is how a group reference keeps its link.
function inlineRefs(text, bodies, open)
  return (text:gsub('([^\n]-)(<<([%w_][%w_.%-]*)>>)', function(prefix, whole, name)
    local block = bodies[name]
    if not block or open[name] then return prefix .. whole end
    open[name] = true
    local body = block.text:gsub('\n$', '')
    if expandsNoweb(block) then
      body = inlineRefs(body, bodies, open)
    end
    open[name] = nil
    return prefix .. body:gsub('\n', '\n' .. prefix)
  end))
end

* The LaTeX postprocessor

texlinks.py is the second half of the reference machinery: it scans
the LaTeX pandoc wrote and decodes every placeholder notes.lua
planted. Inside highlighted code the placeholder becomes a
hyperlink call; anywhere else, in a verbatim fallback that takes no
commands, it decodes back to the literal reference text.

#+name: texlinks
#+begin_src python :tangle texlinks.py
#!/usr/bin/env python3
"""Rewrite noweb placeholders in the woven .tex into hyperlinks.

notes.lua swaps each <<ref>> in a :noweb yes block for an
alphanumeric placeholder, the only spelling that survives syntax
highlighting in one piece. Here the placeholder turns back into
\\NowebRef{name} where LaTeX commands work (pandoc's Highlighting
environment) and into the literal <<name>> everywhere else, since
verbatim fallbacks take no commands.
"""
import re
import sys

PLACEHOLDER = re.compile(r"NOWEBREF([0-9a-f]+)FERBEWON")


def decode(match):
    return bytes.fromhex(match.group(1)).decode("utf-8")


def rewrite(lines):
    out = []
    highlighted = False
    for line in lines:
        if "\\begin{Highlighting}" in line:
            highlighted = True
        if "\\end{Highlighting}" in line:
            highlighted = False
        if highlighted:
            line = PLACEHOLDER.sub(lambda m: "\\NowebRef{%s}" % decode(m), line)
        else:
            line = PLACEHOLDER.sub(lambda m: "<<%s>>" % decode(m), line)
        out.append(line)
    return out


def main():
    path = sys.argv[1]
    with open(path, encoding="utf-8") as f:
        lines = f.readlines()
    with open(path, "w", encoding="utf-8", newline="\n") as f:

* Reproducing this document

This directory is a lit project like any other. Its Makefile sets
LIT to "." and includes lit.mk, so the usual targets work here:
make tangle regenerates the seven files above from this book, make
check proves book and files agree, make weave renders this PDF. The
Makefile, .gitignore, README.md, AGENTS.md, the templates
directory, and the example directory are the hand-managed remainder
outside the book, exactly as the contract prescribes for every
project.

* Changes

- [2026-08-21] A block written ~:noweb yes inline~ shows its
  references expanded in the woven listing instead of as links. The
  reference stays the default, since it tells a reader the code is
  composed and where each part lives; this is for the short helper
  where following a link costs more than reading the lines. The
  switch rides on org's own header as an extra word: org reads that
  header by splitting on whitespace and looking for a word it knows,
  so ~yes~ decides what tangling does and ~inline~ is carried past
  every reader but this filter. Alone the word does nothing, since
  ~:noweb inline~ is a value org reads as ~no~.

- [2026-08-20] Block quotes render as sidebars: a gray rule down the
  left edge, through the same framed machinery the plan boxes use.
  It keeps a clear space above and below itself, so it reads as an
  aside rather than as the next line of whatever came before.
  The Note and Apropos asides reach LaTeX as block quotes, so they
  pick the style up too; before this they were only indented, which
  read as ordinary paragraphs.

- [2026-08-20] make learned what a book is made of. The PDF depends
  on every chapter the master includes, so editing one rebuilds it,
  and check copies those chapters into its scratch directory before
  tangling there; before this a split book left the PDF stale and
  could not be checked at all. The list comes from the preprocessor
  rather than from a pattern in the Makefile, because the program
  that decides what an include is should also answer what the book
  contains. It reports what it can and always succeeds, since it runs
  while make is reading the Makefile and a bad include there would
  stop every target.

- [2026-08-20] A book may be split into chapter files that a master
  includes. Both halves of the toolchain expand the includes before
  they do anything else, because blocks reach a file in the order
  they appear across the whole book and a doc comment's extent can
  run back into the chapter before it; reading chapters one at a
  time would write different files from the same book. Only the bare
  quoted form is understood, since org and pandoc understand
  different extensions of the keyword and pandoc ignores an unquoted
  path without a word. A custom id must be unique across the book,
  and the check runs while the chapter files are read, which is the
  last moment the file and line of the second definition are known.
  A stored link to a heading in another chapter resolves to that
  heading in the PDF.

- [2026-08-11] Comment syntax became a property of the language a
  block is written in, rather than of the file's extension and of
  whatever major mode Emacs had loaded. One table answers both the
  banner and the doc comment, so a ~go~ block writing a ~.templ~ file
  opens with ~//~ without the toolchain knowing the extension. A
  project extends the table through ~.lit/comments.json~ beside its
  book. Two failures went with the old arrangement: a language whose
  mode batch Emacs never loaded took the previous block's comment
  syntax, and where there was no previous block Emacs prompted for a
  syntax and hung the tangle. A file fed by blocks of two languages
  is now an error rather than a guess.

- [2026-08-11] The banner prefix table gained the JavaScript
  extensions, so a tangled ~.js~, ~.mjs~ or ~.cjs~ file opens with a
  comment its parser accepts instead of a hash, which is a syntax
  error there rather than a comment. Doc comments already worked:
  Emacs carries ~js-mode~ in core and autoloads it in batch, so
  ~:comments org~ on a JavaScript block has always come out in
  ~//~. A book that kept a JavaScript file by hand for the banner
  can tangle it.

- [2026-07-27] The toolchain became its own book. lit.mk, formerly
  tangled from a consuming project's book, moved here along with
  tangle.el, preprocess.py, notes.lua, plan.lua, mermaid.lua, and
  the new texlinks.py; consumers now include lit/lit.mk unchanged
  and pass project-specific check exclusions through ~CHECK_EXTRA~.
  The weave gained listing captions (numbered, naming the target
  file and the block's ~<<name>>~; a region block resolves its file
  through the references that include it) and clickable noweb
  references,
  which forced the weave recipe apart into pandoc, a LaTeX
  postprocessing step, and tectonic: highlighting shreds references
  into tokens, so notes.lua plants placeholders and texlinks.py
  decodes them into hyperlinks after pandoc has written the LaTeX.
